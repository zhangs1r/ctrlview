# CtrlView 精读契约（L0）

> 这一层对所有栏目通用，改它就等于改全站标准。栏目相关的部分在 `L1-<栏目>.md`。
> 版本：v1（2026-10-01 定稿）。改动请往上加版本号并在正文里说明改了什么。

## 一、这份稿子是给谁看的

读者画像：**控制工程 / 机器人方向的研究生，AI 与具身智能是入门水平**。他可能已经会用 OpenVINS、卡尔曼滤波、MPC，但没读过这批新论文。

所以成功标准只有一条：

> **一个没读过原文的人，读完这篇稿子，能不能复述出论文的核心方法与思路。**

自测口径是「能不能复述」，不是「能不能复现」。**不要为了可复现去堆参数清单**——真想复现的人自然会回去啃原文，导读不该抢这件事。反过来说，凡是**核心洞察**（为什么难、为什么这样设计、关键结论怎么来的）必须讲透到能复述。

`通俗易懂` 是最高优先级。为了讲清楚一个难概念，允许用比喻、日常场景、伪代码、示意图，甚至允许比原文啰嗦。

## 二、输入与输出

### 硬前提（不满足就不许动笔）

1. **必须先下载论文原文。** 只用摘要、搜索片段或自己的记忆写精读是不允许的。摘要里没有方法细节，记忆会编出不存在的公式、数字和结论。
2. **下载的如果是 PDF，必须先用 MinerU 解析成 Markdown 再读。** 不要拿普通 PDF 阅读器或 pdf-parse 硬读——公式、表格、图片引用都会丢，而精读恰恰靠这三样。
3. 下载走 `paper-download` 技能的 `fetch_paper.py`，它内置 `%PDF-` 魔数校验，能防止把风控挑战页当成 PDF 存下来。**先检索后下载**，不许凭记忆列论文（记忆里的编号可能对应完全无关的论文）。
4. 解析出来的 `document.md` 才是写作依据。引用公式编号和指标数字时对着它核，不要凭印象写。

MinerU 的 token 要先从注册表回填到进程变量（它只存在于用户变量里，dsh 进程读不到）：

```powershell
foreach ($s in @('User','Machine','Process')) {
  $t = [Environment]::GetEnvironmentVariable('MINERU_API_TOKEN', $s)
  if ($t) { $env:MINERU_API_TOKEN = $t; break }
}
python "$env:USERPROFILE\.agents\skills\mineru-pdf-reader\scripts\convert_pdf.py" "<PDF>" "<输出目录>"
```

解析脚本**不要放在 `%TEMP%` 里跑**：那里有一个 `struct.py`，会把脚本目录插到 `sys.path` 最前面，`zipfile` 导入到假的 `struct`，`latex2mathml` 直接崩，公式会静默降级成源码。

### 输入与产出

- 输入：上一步得到的原文全文（`document.md`）+ 该栏目的 `L1-<栏目>.md` + `document.md` 里引用的图表。
- 输出：**只输出一份 Markdown**，写入 `posts/<arXiv编号>.md`。不要在正文里写"以下是精读"这类交代语。
- 文件名必须是 arXiv 编号（例如 `2609.27702.md`），因为站点的论文原文链接是用文件名拼出来的。

## 三、硬性格式契约（写错就渲染不出来）

### front-matter

```
---
title: "标题"
arxiv: "2609.27702"
date: "2026-10-05"
column: "slam"
tags: 状态估计, 视觉惯性里程计, 初始化
authors: "作者一, 作者二 等"
read_time: "26 分钟"
---
```

- `column` 必须是 `pipeline/columns.json` 里的 id（slam / embodied / control / robotics / cps / security / automation），否则栏目页挂不上。
- `tags` 写成**逗号分隔、不带方括号和引号**。写成 `["A", "B"]` 会在页面上显示出引号（解析器按逗号裸切）。

### 允许的块语法

| 写法 | 渲染成 |
|---|---|
| `$$ ... \tag{N} $$` | 带编号的独立公式（编号沿用论文原编号） |
| `$...$` | 行内公式（段落、列表项、引用块里都能用） |
| `**文字**` | 加粗 |
| `==文字==` | 高亮 |
| `__文字__` | 下划线 |
| `` `文字` `` | 行内代码（**只给代码、文件名、命令用，不要拿它当公式用**） |
| `<figure src="xxx.svg" caption="...">` + `<figcaption>` + `</figure>` | 配图块 |
| `> 📌 **控制视角**　...` | 带色条的引用块 |
| `※ ...` | 细体小字块（声明、脚注用） |
| `⚠ ...` | 警示块 |
| ```` ``` ```` 围栏 | 伪代码 / 流程块 |
| `---` | 分隔线 |

**注意**：`<figcaption>` 里的内容是原样 HTML，**不解析 `$...$` 和高亮语法**。图注里表示符号请用 Unicode（如 w₀、λⱼ），不要写 LaTeX。

### 图片

- 从原文提取的图表放进 `figs/`，命名 `figNN.png` 会与别的文章冲突，**必须带 arXiv 前缀**：`<编号>-fig2.jpg`。
- 自己画的示意图命名 `<编号>-svg-<名字>.svg`，图注里标 `（编者绘制）`。
- 论文原图沿用论文的图号（图 2、图 3…），自己画的用 **示意图 A / B / C…**，两套不混。

## 四、内容的骨架

固定七节 + 一张表。栏目不同只在细节，骨架不动。

1. **它想干什么** — 三到五段，先把问题讲成人话，再说这篇怎么解。开头尽快碰到事情，不要预告全文结构。
2. **一、问题背景** — 为什么难（物理或数学根源）、前人两条路的短板、这篇的做法。
3. **二、总体结构** — 放架构原图，配一张"阶段 ↔ 章节 ↔ 输入输出"的对照表。
4. **三、方法拆解** — 主体。每个小节一件事，公式给出来并逐个符号解释。
5. **四、结果** — 表格给数字，正文只解读"哪一列值得看、哪个结论反直觉"。
6. **五、局限** — 逐条列论文自己承认的局限。**编者补充的必须单独成段并写明"论文未将其列为局限"**，不许混进论文的清单。
7. **六、我的评价** — 做得对的、存疑的、它想走去哪。这一节明确是作者观点。
8. **七、可以接着做什么** — 选题线索。**末尾必须用 `※` 小字声明：这是即时联想，没有实验、没有查证、只当线索。**

最后是 **名词速查** 表，本文字段里出现过的术语都要能查到。

## 五、文风硬禁令（有机器校验，见第八节）

- **不写破折号**（`—`、`——`、`–`）。
- **不写提示性冒号**。冒号只允许用来引出人物的直接引语。
- 不写翻案腔：「不是 A 而是 B」「并非…而是」「与其…不如」「看似…本质」以及一切"先立一个读者没有的误解再推翻"的写法。判断直接正面下。
- 单项排比最多两项，第三项换说法或删掉。
- **单句不超过 90 字**（不含空白；公式和代码块不计入）。
- 不写这些词：值得注意、值得一提、显而易见、说实话、打个比方、简单来说、说白了、本质上、实际上、真正…是、这说明、这意味着、体现了、揭示了、提醒我们、由此可见、从而得出、进一步。
- 不给抽象名词配具体动词写抒情。
- 不把动词名词化（写"把流程改顺了"，不写"完成了对流程的优化"）。

## 六、十二条内容规则

**R1 五问必答**：每篇都要能定位到这五处——①问题为什么难；②相对哪条替代路线的取舍；③核心机制一句话（≤40 字、不含符号）；④机制的可检验推论（靠哪个可观测量、哪条判据）；⑤什么情形下会失效。

**R2 自由度账本**：凡出现"方程 / 约束 / 未知数 / 秩 / 退化 / 最少需要几个"，同段必须给出未知数个数、每个观测源最多贡献几个独立方程、最少需要几个观测，并写成算式。

**R3 外部方法必须「它怎么做 + 差在哪」**：文中出现的每一个其他系统名（OpenVINS、ScaRF-SLAM、ORB-SLAM3、MASt3R-Fusion、VGGT-SLAM2…），首次出现处必须有机制一句 + 差异一句，**差距必须落在机制上**（谁给尺度、谁优化位姿、在线还是离线、用不用同一个模型）。

**R4 编者判断进容器**：凡不由原文陈述句或公式直接推出的因果、类比、数量级判断，只能出现在「控制视角 / 我的评价 / 局限（编者补充）/ 可以接着做什么」四类容器里，正文陈述句禁用。原文没有的解释，不许写成"论文认为"。

**R5 被优化的量要有三件套**：凡出现"优化 / 估计 / 求解某量"，写清①初值从哪来；②由哪个残差驱动；③由哪个先验或约束兜底。缺一项就是机制断链。

**R6 伪代码的准入**：只有三种情况配伪代码——a) 循环次数不定的搜索 + 多重判据；b) 接受/拒绝的级联检查；c) 跨模块的时序交接。一行一个动作，行内不推导，每行都能指回原文的某句或某式。**单个公式或单步变换不许写成伪代码。**

**R7 示意图的准入**：只在"文字已经说了、读者仍会画错"的空间或结构关系上画图（列的块结构、相机间距、门的开合区域、时序）。一张图只讲一个关系。坐标轴必须写清物理量及其来源。**禁止用"时间"偷换"距离/漂移"。** 颜色语义要与好坏一致，别让"好"的颜色落在危险区域。

**R8 每节一句话**：每节末尾给一句 ≤40 字、不含符号的"这节要你记住的是…"。

**R9 优势必须双向**：凡声称比某方法快或准，同段必须给出对方的优势场景与本文的劣势场景，并附数字。

**R10 局限逐条对齐**：每条局限都要能映射到原文显式承认的句子；引用时不得改强度（"可能"不能写成"确实"）。原文把两个误差源并列的，不许只留一个。

**R11 数字溯源**：每个数字要写明取得条件（哪张表、哪套位姿、causal 还是 final、是否同权重、是否离线）。跨表引用不得混条件。

**R12 术语首现解释**：每个术语第一次出现，用一句**只用已解释过的词**来定义它。

## 七、重点标记怎么用

标记是给读者导航的，不是装饰。

- `==高亮==` 全篇 8~12 处，只给**信息点**不给情绪句。分布要摊开，别全挤在前 15% 的篇幅里。
- `__下划线__` 全篇 2~4 处，给**定义句或可直接引用的判据**。
- `**加粗**` 给关键数字和短语，表格里只加粗最优值和本文那一行。
- 同一句话不要既高亮又加粗。

## 八、交稿前的机器自检

```powershell
$env:PYTHONIOENCODING = "utf-8"
python pipeline\check_quality.py posts\<编号>.md          # 文风门禁，必须 exit 0
python "%USERPROFILE%\.agents\skills\human-writing\scripts\check_prose.py" posts\<编号>.md
python pipeline\build_site.py . docs                      # 构建，检查公式有没有降级
```

构建输出里出现 `⚠ 有 N 处公式转换失败` 就是 LaTeX 写错了，必须修到 0。
产物里 `tex-err` 必须为 0、裸 `$` 必须为 0。

## 九、写作流程

### 当前生效：单轮（盲读评审已关闭）

**writer 出稿 → 过第八节的机器门禁 → 交稿。**

没有评审环节，所以写作时要自己按第六节的十二条规则逐条自查一遍再交。最容易漏的是 R3（外部方法必须写清机制差异）和 R4（编者判断不许写成论文的话）。

### 评审开启时的流程（现在关闭，需要时再开）

1. **writer**：拿原文 + 本契约 + `L1-<栏目>.md`，产出初稿。writer 不许看任何评审意见。
2. **blind reader**：**只读精读文章，不许看原文**，先答下面那份固定考卷（每题标【有把握】/【半猜】/【答不出】），答完再打开原文自评。
3. **一轮定向修订**：按缺口清单改一次就停。不要多轮循环，第二轮的边际收益低，而且容易把文章改肿。

> **开关在这三处，要一起改**：本文件这一段、`README.md` 运行手册的第 3 步、任务看板上那条定时任务的 prompt。

### 盲读考卷（评审开启时用，固定不变）

1. 这篇论文要解决什么问题？为什么原来的方法不行？
2. 输入是什么？一次解出哪几个量？一共几个未知数？
3. 每个观测源最多贡献几个独立方程？为什么观测再多也不增加？最少需要几个？
4. 哪种情形会退化？论文怎么处理？
5. 核心机制里最容易做错的一步是什么？为什么不能那样做？
6. 关键判据是什么？为什么这么设计？
7. 和最强的基线相比：好在哪、差在哪、有没有反例场景？
8. 它和**最接近的那个工作**在机制上的区别是什么？
9. 论文自己承认的局限有哪些？
10. 如果要用在自己的课题里，最需要先确认什么？

### 评分口径（评审开启时用）

- 只按 **R1~R12 + 考卷答对率** 打分，**不按"缺多少可复现参数"打分**。导读不承担参数清单的职责。
- 覆盖率目标：核心思路可复述比例 ≥ 80%。
- 考卷第 8 题（与最接近工作的机制区别）**必须答得出**，答不出就是必补项。
