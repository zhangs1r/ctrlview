路由日志也能认出微调数据，MoE 推理遥测泄了谁的密

Yixin Tan, Jiayang Liu, Lu Sun, Yuke Hu, Zheng Li, Rui Wen
arXiv:2610.10616 · 2026-10-19 · 精读约 34 分钟
成员推断混合专家路由遥测隐私泄露威胁模型

它想干什么

一个 MoE 语言模型被下游任务微调过之后摆到线上，服务端通常会把推理过程中的路由信息记一笔。这一笔记录的用途是运维，看专家负载是不是歪了，看哪个请求把某个专家打爆了，出了故障拿它排查，做安全审计也靠它。写日志的人多半把路由当成内部结构信息，而不是用户数据。

论文指出这类日志能回答一个别的问题。给定一段文本，它有没有出现在这个模型的微调数据里。

这个问题叫成员推断，英文 membership inference。判断的对象是单个例子 x，答案只有两个，在这份微调数据里或者不在。攻击算法输出一个分数 s(x)，分数越大越倾向于认为它是成员，拿阈值 τ 一比就出结论。

m^(x)=𝕀[s(x)≥τ]

在这个式子里 m^(x) 是攻击给出的判断，取值 0 或 1，𝕀[·] 是示性函数，条件成立取 1。s(x) 是攻击分数，τ 是判定阈值。

论文用三个 MoE 模型乘三个数据领域，做出九套组合来量这件事。结论很干净。把输出侧信号和路由遥测拼在一起，九套里的低误报识别率全都涨了，涨幅从 2.7 个百分点到 9.4 个百分点。这里的低误报识别率指的是 TPR@1% FPR，即把误报率压在 1% 的工作点上能抓到多少成员，后面会展开讲这个指标为什么比 AUROC 更能说明部署风险。

涨幅的方向和模型强弱正好相反。LLaMA-MoE-v2 在 GitHub 上的基线最弱，识别率只有 0.6725，加上路由之后跳到 0.7662，涨了 9.37 个百分点，是九套里最大的。OLMoE-1B-7B 在 Wikipedia 上基线本来就有 0.9388，路由只补上 2.67 个百分点，是九套里最小的。哪一套留的余地大，哪一套的涨幅就大。

有人会先猜，这是不是因为微调动了路由器的参数，路由器把训练数据记下来了。论文拿两组实验把这条猜测挡掉。把路由器参数冻住不让它更新，泄露的涨幅还有 9.04 个百分点，比全参数微调的 8.41 个百分点还略高一点。两轮微调之后的机制分析给出一致的证据，路由器权重矩阵张成的那片子空间里保留的成员信息更多，AUROC 到 0.661，同样大小的随机子空间只有 0.594。泄露的源头在微调写进隐藏表示里的成员信息，路由器只是一个读得比较准的低维投影口。

想过堵它，思路是在遥测暴露出去之前做后处理扰动。论文试了高斯噪声、特征丢弃和量化三种，每种都是同一条曲线。要压住泄露就得牺牲遥测保真度，最能压的那几档，保真度已经掉到接近零。论文在受测范围内没有找到既能压住路由泄露又能保住高保真遥测的配置。

这节要你记住的是，路由日志是运维信号，也是一条额外的隐私暴露面。

一、问题背景

1.1 一层路由就是一次降维观测

MoE 语言模型把一部分密集前馈块换成了一组专家网络，路由负责给每个 token 挑几个专家来算。第 ℓ 个 MoE 层里的路由由两步组成，先线性映射再取前几名。

zℓ,t=Wℓhℓ,t,pℓ,t=softmax(zℓ,t),Sℓ,t=TopK(pℓ,t,k)

这里 hℓ,t 是第 ℓ 层第 t 个 token 的隐藏表示，维度是 d。Wℓ 是这一层的路由权重矩阵，形状是 E 行 d 列，E 是专家个数。zℓ,t 是路由打分，长度 E。pℓ,t 是 softmax 之后的专家概率分布，Sℓ,t 是概率最大的 k 个专家组成的集合。

关键在 Wℓ 的形状。论文在附录 E.1 里给出 OLMoE-1B-7B 的两个量，隐蔽维度 d=2048，专家个数 E=64。也就是说这一层的路由把两千零四十八维的隐藏向量压成六十四个数，Wℓ 的每一行都是对隐藏向量的一个线性测量，一层给出六十四个独立观测。观测数没有超过被观测空间的维度，这个投影远不是单射。

微调在隐藏表示里造成的成员相关信息，当然不会只落在这六十四个方向上。论文的机制分析就在量这件事，路由子空间里到底捞回来多少，同样大小的随机子空间里又能捞回来多少。两个数一对比，才知道路由这个投影口是不是选得比随机好。

1.2 输出侧信号在低误报点会不够用

成员推断在这条线上已经有很长一串工作，它们都从模型的输出里取信号。Min-K% 取一段文本里概率最低的那批 token，看它们的平均对数似然有多低。Min-K%++ 把真实 token 的 logit 先减去同一位置上词表 logit 的均值再除以标准差，做一次标准化。ReCaLL 在同一段文本前面拼一节固定的前缀，比较有无前缀时平均对数似然的变化。LTsig 从微调模型和参考模型的逐 token 对数似然差里学一个签名。

带参考模型的那一类换成用公开的预训练检查点做对照，比较微调前后同一段文本的对数似然变化。WBC 在多个窗口尺度上数票，看微调模型在多少个窗口上压过参考模型。EZ 只盯预测出错的位置，比较这些位置上两个模型的对数似然差。

这些都是同一个来源里的信号，模型最终吐出来的概率。论文引用了 Das 等人的评估结论，说这类信号在严格的低误报工作点上会变弱。想压住 1% 的误报率，输出侧能提供的区分度就不够了，明确需要一个额外信息源。

1.3 内部表示那条路要不到

另一条路去挖模型内部的表示。Makhija 等人拿隐状态和注意力模式做特征，Zaree 等人专门看注意力信号，Ranjan 等人看梯度引起的特征漂移。这条路能拿到的成员信号比输出侧强，代价是必须有内部状态的访问权。

放在部署场景里，这个前提基本落不了地。外部查询者拿到的是一个接口，接口返回文本或者概率，不返回第几层的隐藏状态，也不返回注意力矩阵。论文把这个位置讲得很清楚。隐状态那条路的信号更强但拿不到，输出那条路拿得到但信号不够，中间空出来一档。

路由遥测正好落在这个空档里。它从中间表示派生出来，又常常以运维信号的名义出现在服务接口或日志里。它比输出多一些内部视角，又不需要像隐状态那样直接开内部访问。

1.4 已有的 MoE 路由隐私工作不碰这个面

关于 MoE 路由会泄什么，现有的工作分几路。GateBleed 走硬件功耗门控留下的时序侧信道，用它做成员推断，同一路信号还能把专家选择反推出来，前提是攻击者能贴到硬件上做观测。Yona 等人盯着专家选择路由里处理平票的方式，借此把受害者的提示词恢复出来。Nuriyev 与 Kulp 证明专家选择的轨迹足以泄露出输入 token 的大量信息。

Avinash 训练模型从路由签名预测输入属于哪个任务类别，回答的是任务归属。Ding 等人利用专家执行在硬件上留下的侧信道去推断提示词和回复的内容。

这几路共同的落点是推理时那一次输入，问的是输入本身泄不泄。本文问的是另一个量，路由信息能不能反过来指认输入有没有进过微调集。两个问题对外形的依赖不同，前者往往要贴硬件或者拿到逐 token 的专家轨迹，后者只需要服务端把聚合后的负载露出来。GateBleed 和本文最接近，它的成员推断靠硬件时序通道，本文靠直接暴露的路由值。论文自己把这条差别写在相关工作里。

1.5 这篇的做法

做法本身不复杂。把微调模型推理时露出来的路由信息聚合成一个定长表示，和输出侧那批信号拼成一个特征向量，再用影子模型上的成员标签训一个分类器，最后把分类器原样用到目标模型上。

影子模型这一环是攻击训练的支点。攻击者拿不到受害者的微调数据，也就没有标签。它自己在同领域的公开数据上微调若干份模型副本，每个副本标注两拨样本，参与微调的那份是成员，留出的那份是非成员。标签就这么造出来了。

论文强调输出侧和路由侧两条攻击的对照要干净。两者用的是同一批影子模型和同一批成员标签，分类器族与留出目标也完全一致，差别只在于特征里有没有路由那一块。这样算出来的性能差就只归因于路由遥测带来的额外信息。

这节要你记住的是，内部信号拿不到、输出信号不够用，路由卡在中间那一档。

二、总体结构

2.1 威胁模型

论文在 3.1 节把威胁模型拆成三条来写，攻击者知道什么、能改什么、要拿到什么。三条要一起看，缺一条后面的数字就没有参照。

攻击者知道什么。 攻击者知道预训练检查点 Mpre，目标模型就是从它微调出来的，这个检查点公开可得。攻击者还知道下游微调数据属于哪个领域，比如 arXiv 或者 GitHub。它不知道私有的微调数据集 Dft 里到底有哪几篇，也拿不到目标模型 Mft 的参数、中间隐状态和梯度。

攻击者能改什么。 它只能查。 查微调模型，拿到逐 token 的输出概率或 logits，同时拿到对应的路由遥测。它还能查公开的预训练检查点，用来构造参考类的攻击信号。另外它可以在同领域的辅助数据上自己微调一份或多份模型副本，这些副本叫影子模型，用来训成员分类器。模型参数、推理流程、部署配置都在射程外，一样都不能动。

攻击者要拿到什么。 给定候选例子 x，判断它有没有进过 Dft，也就是 x∈Dft 成立不成立。判断是逐个例子做的，不是问整份微调集的规模或者内容。

三条并起来读，这个攻击是黑盒的。不需要事先知道目标模型有几层、每层几个专家，也不需要目标的梯度。它需要的是服务端把路由信息露出来。

2.2 假设的边界

白盒还是黑盒。黑盒，只需要能正常查询。第 5.5 节那组机制分析要看隐状态和路由器权重矩阵，那是作者在开权模型上另做的解释性实验，不属于攻击本身的假设。论文在 5.5 节开头就写明用的是 OLMoE-1B-7B 加 arXiv 这一套，其他组合没有重复这组分析。

需要多少次查询。论文没有给查询上限，也没有拿查询次数当预算来扫。攻击对每个候选例子查一次目标模型，特征就取完了。第一层额外成本在影子模型，那是攻击者自己的算力，不占目标模型的调用次数。

要不要预先知道模型结构。不要。路由表示的维度是从暴露出来的遥测里读的，层数和专家数都由遥测的形状决定。

需要几份影子模型。主线实验里每个留出目标配三份影子模型。附录 D.2 把影子模型数从一到三都扫过一遍，只用一份影子模型的时候，TPR@1% FPR 相对输出侧基线还是提升了 0.0493。

攻击者侧还要背一份微调算力。附录 A.2 给的配置是 Adafactor 优化器、学习率 8×10−6、批量 16、最大序列长度 256 个 token，只跑一个 epoch。同一套配置在三个模型上通用。论文没有把这部分算力折成攻击成本来讨论。

2.3 辅助数据这一条前提

攻击者造的影子模型必须和目标的微调数据同领域。论文用的来源池是 arXiv、GitHub、Wikipedia 三个公开语料，各造四份互不相交的成员实例，每份里成员集和留出集分开。

互不相交这一条是硬约束。同一篇文档不许同时出现在两个实例里，否则攻击分类器会从重复文档里捡便宜。论文把这条写成了一个集合条件，任意两个实例的并集交集为空。

(D~jin∪D~jout)∩(D~j′in∪D~j′out)=∅,j≠j′

D~jin 是第 j 个实例的成员集，也就是拿去微调的那份，D~jout 是同一实例的留出集，当非成员用。j 与 j&#x27; 遍历四个实例。这个式子保证四个实例互不共享文档。

论文还做了一次盲分类器的验证。纯文本特征的分类器如果就能把成员和非成员分开，后面的攻击数字就解释不清了。作者在十二对领域与实例上各训了四个只用文本表面的分类器，词级 TF-IDF 的一到二元组、字符级 TF-IDF 的三到五元组、词袋，以及手工的文本统计量，用五折折外预测评估。四十八次检查的 AUROC 落在 0.4817 到 0.5329 之间，整体贴着随机线，没有系统性偏离。

三、方法拆解

3.1 输出侧信号集合怎么搭

论文把十一种输出侧信号拼成一个集合，记作 Aout。拆开看分四块。

参照无关的那一块有十三维，只用到微调模型自己的 token 级统计。NLL 取全序列的平均负对数似然，一维。Min-K% 把 token 对数似然升序排列，在最低的 10%、20%、30% 上各取均值，三维。Min-K%++ 先把真实 token 的 logit 标准化再取低端均值，二维。

zt=ut−μtσt

ut 是位置 t 上真实 token 的 logit，μt 和 σt 是同一位置上整个词表 logit 的均值和标准差，zt 是标准化后的值。zlib 归一化似然占两维，其中一维是 UTF-8 文本的压缩比 ρzlib，另一维是平均负对数似然除以压缩比。logit 间隔占一维，取每个位置上最大 logit 与第二大 logit 之差，再对整段求平均。对数似然分位数占四维，取 10%、50%、90% 三个分位点加一个标准差。

带参考的那一块来自 Mft 与 Mpre 的对比。参考损失下降是一维，把两个模型在同一段文本上的逐 token 对数似然差求平均。WBC 用十个窗口尺度，滑窗统计微调模型在多少比例的窗口上压过参考模型，再把这些投票比例取平均。EZ 只看微调模型预测错的位置，把这些位置上的对数似然差分成正负两堆，正堆求和记作 P，负堆求和记作 N，主指标是比值 P/(N+ϵ)，ϵ 是防止除零的小量。

LTsig 是三维的签名块。它取逐 token 对数似然差的十六个等距分位点，还取微调模型对数似然的八个等距分位点。剩下八个是汇总统计量，包括均值、标准差、差值为正的比例、差值总和、两个模型各自的平均 token 排名、排名差的均值，以及序列长度 T。ReCaLL 是一维，用八篇留出的非成员文档拼一段最长 128 token 的前缀，比较有前缀和没前缀时的平均 token 对数似然。

论文在这里交代了两处改写，值得单独记一笔。ReCaLL 原始版本用的是条件对数似然与无条件对数似然的比值，论文换成了两者之差，理由是这样更简单且能捕捉同一个前缀带来的变化。LTsig 原始版本是序列级分类器，论文没有复现它，改用固定维度的汇总特征喂给同一个梯度提升分类器。这两处改动意味着论文里 WBC、EZ、LTsig 的单个基线数字，不能直接和各自原论文里的数字对比。

Aout 就是把这些块拼起来。

ϕout(x)=concatb∈ℬϕb(x)

ℬ 是特征块的名字集合，ϕb(x) 是第 b 块在候选 x 上的取值，concat 把它们首尾相接。分类器在这上面训练。

3.2 聚合这件事怎么做

#### 3.2.1 连续专家负载

每个 MoE 层、每个专家，论文都对整个序列上的路由概率求平均，候选文档里的 token 一个不落。

(16)rℓ,e(x)=1T∑t=1Tpℓ,t,e

T 是候选序列的 token 数，pℓ,t,e 是第 ℓ 层第 t 个 token 分给专家 e 的路由概率，rℓ,e(x) 是专家 e 在这份文档上的平均负载。把所有层和所有专家铺平，得到定长表示。

(17)ϕR(x)=[rℓ,e(x)]ℓ,e

这个表示有很强的结构。既然每层的概率分布过 softmax，∑erℓ,e(x)=1 对每一层都成立。长度为「层数乘以 E」的向量，每一段的元素之和都等于 1，所以独立维度比表面维度少掉层数那么多个，一层贡献 E−1 个自由度。这是论文没有展开的一层结构，读的时候用得上。

#### 3.2.2 自由度账本

论文没有把攻击拆成一组方程来解，它训的是分类器，不是解线性系统。路由这一环的几何关系是清楚的，值得把账算一遍再看后面的数字。

记 L 是 MoE 层数。一层里待观测的隐藏状态是 d 维，路由给出 E 个线性测量，也就是 Wℓ 的 E 行。按秩与零度的关系，一层路由能唯一确定的自由度最多是 E 个，剩下 d−E 维落在零空间里，方向怎么变都看不出来。OLMoE-1B-7B 的参数是 d=2048、E=64，单层留下 2048−64=1984 维零空间。喂进攻击特征的独立观测数是每层 E−1=63 个，而不是 64 个。论文把 L 层的路由全部露出来，独立观测总量是 L×63；这也说明为什么用 L 层做测量才能让 L×64≥d，即 L≥32 时，路由测量的总量才在计数上够覆盖隐状态维度。论文没有报 OLMoE-1B-7B 的 L，这一条只能当量级参照。

这里要盯住的是零空间不空这件事。1984 个方向上的隐藏状态变化，路由一点反应都没有。微调若把成员信息写进这些方向，路由就看不见。论文 5.5 节的机制分析正是在量这个剩余量。

#### 3.2.3 离散专家选择

第二种形态只保留选中的专家，丢掉概率。

(1)rℓ,ecount(x)=1T∑t=1T𝕀[e∈ℰℓ,t(k)]

ℰℓ,t(k) 是第 ℓ 层第 t 个 token 被选中的 k 个专家的集合，𝕀[·] 是示性函数，选中取 1，否则取 0。把所有层和专家铺平就是 ϕRcount(x)。这个表示里没有连续概率，只有频次。ϕRcount 和 top-K 表示是两件不同的事，前者从离散选择直接构造，后者从连续负载里挑负载最大的 K 个专家维度，其余遮掉。论文在附录 D.1 专门写了这句区分。

3.3 被估计的量与它的三件套

分类器 g 是攻击里唯一被学出来的东西，要看清它的初值、驱动和边界。

初值来自影子模型。攻击者先在辅助数据上微调出 K 份副本，每份切出成员集与留出集。第 j 份影子模型的成员标签这样定义。

驱动它的是成员与非成员之间的特征分布差。阴影模型上的特征被标准化之后，没再叠加显式的残差项或正则项，分类器族是直方图梯度提升，一个现成的提升树实现。

3.4 两个分类器与一条干净对照

输出侧攻击和路由增强攻击用同一个协议，只在特征上分岔。

(19)ϕaug(x)=[ϕout(x);ϕR(x)]

两份分数分别写成 sout(x)=gout(ϕout(x)) 和 saug(x)=gaug(ϕaug(x))。因为两者的影子模型、成员标签、分类器族和留出目标都一样，性能差就只来自路由那一块特征。论文 5.2 节到 5.4 节的所有 Δ 都是这个差。

3.5 机制分析怎么做

要看泄露到底来自何处，作者在三个条件下做同一件事。把每个 MoE 层的隐状态投影到路由权重矩阵 Wℓ 的行空间上，把这些投影在序列上聚合，用五折分层折外预测训一个成员分类器，四份独立微调模型的 AUROC 取平均。

第一个条件是路由子空间。Wℓ 的行空间是那片被路由直接读到的低维子空间。第二个条件是同秩随机子空间，每一层造一个秩相同的随机子空间，投影同样的隐状态，层和维度都对齐。这组对照控制住维度效应，把「保留信息多是因为孔开得大」这条解释挡掉。第三个条件是冻结路由器，把路由门参数冻住再跑一遍全流程，看泄露是否依赖路由参数的更新。

3.6 扰动怎么做

三种后处理都在模型推理之后、遥测暴露之前生效，模型本身和输出侧信号都不动。

高斯噪声按每个维度的经验标准差缩放后加进去，再截断到非负。

(23)r~j=max(0,rj+ϵj),ϵj~𝒩(0,σ2sj2)

rj 是原始负载的第 j 维，sj 是这一维的经验标准差，σ 是噪声强度，r~j 是扰动后的值。

特征丢弃对每一维独立地做一次伯努利抽样，抽到就保留，抽不到就置零。

(24)r~j=mjrj,mj~Bernoulli(1−p)

p 是丢弃概率，mj 是掩码，每个候选输入独立采样一次。

量化把连续负载压到 B 个等级。

(25)r~j=1Bround(Brj)

B 是量化级数，越小越粗。

遥测保真度用两个量衡量。主分析用扰动后负载与原始负载的 Pearson 相关系数，附录 F 补了另一个量，叫 top-1 专家一致率，看扰动之后负载最重的那个专家还是不是原来那个。

(26)Agreetop1=1NL∑i=1N∑ℓ=1L𝕀[\argmaxeri,ℓ,e=\argmaxer~i,ℓ,e]

N 是候选输入个数，L 是 MoE 层数，r 和 r~ 分别是扰动前后的负载。逐层比较最大负载落在哪个专家上，取一致的比例。

这里要说清一个边界。论文的策略是后处理扰动，没有往路由器参数里加噪声，也没有用差分隐私那类带理论保证的机制。所以全文没有隐私预算这类量，也没有泄露概率的上界，所有数字都是实验观测。

4.5 机制分析，泄露是不是路由器自己记的

这一组实验用的是 OLMoE-1B-7B 加 arXiv，比的是三种投影。同秩随机投影和路由投影都在全参数微调下跑，冻结路由器投影单独跑一条。AUROC 在微调前、一个 epoch、两个 epoch 三个点上采。

微调前三条都贴着 0.5 的随机线，往上一两个千分点。一个 epoch 之后，路由投影到 0.522，随机投影到 0.515。两个 epoch 之后，路由投影到 0.661，随机投影到 0.594。冻结路由器那一列的走势与全参数微调基本重合，两个 epoch 后也到 0.661。

论文由此得到结论，泄露需要的是微调往隐藏表示里写进成员信息，路由器负责把这份信息投影出来，即便它的参数一个都没动。这个结论有多硬，取决于同秩随机投影这一组对照做得干不干净，而对照组只覆盖了 OLMoE-1B-7B 与 arXiv 一套组合，其他两套模型没有重复。

五、局限

论文自己承认的局限

模型和领域都只有三个。 论文在 5.1 节把范围写死，三个开权 MoE 模型乘三个数据领域，九套组合。它没有声称这套结论能外推到别的架构尺寸或别的语种。

受测的扰动配置里没有可用的折中点。 5.6 节末句写明，在受测范围内没有观察到既能压住路由引起的泄露、又能保住高保真遥测的配置。

ReCaLL 和 LTsig 用的是改写版。 附录 A.3 交代两处改动。ReCaLL 原始定义是条件对数似然与无条件对数似然的比值，论文换成两者之差，理由是这样更简单，捕捉的是同一个前缀引起的变化。LTsig 原始版本是序列级分类器，论文改成固定维度的汇总表示，喂给和其他信号相同的直方图梯度提升分类器。这两个基线的数字与各自原论文不可直接对比。

盲分类器的验证只在辅助数据上做。 附录 A.1 的做法是在建好的成员实例上训四个纯文本分类器，四十八次检查的 AUROC 落在 0.4817 到 0.5329 之间。这一步证明构造出来的成员标签不会被文本表面特征预测，论文没有把它推到真实部署数据上。

冻结路由器的结论只覆盖一套组合。 5.3 节和附录 E.2 的冻结路由器实验都在 OLMoE-1B-7B 加 arXiv 上做，其他八套组合没有做冻结对照。

编者补充的局限

下面几条论文未将其列为局限，是读的时候自己觉得要留一手的部分。

训练机制的替代品没有正面比过。 论文在 5.5 节让路由投影和同秩随机投影对打，也跟冻结路由器对照，唯独没有和隐状态上的监督式探测做正面比较。上文提到的 LTsig 出自 Ilic 等人在 ACL 2026 的那篇，它直接拿微调模型与参考模型的逐 token 分布差学签名，是这条线上最强的一类做法。隐状态做拟合的上限没有测，所以「路由遥测比隐状态弱多少」这个问题论文答不了。缺了这个参照，读者很难判断路由遥测的增量到底是它独有的，还是所有中间表示都有的。

辅助数据的采集成本没进威胁模型。 攻击者需要同领域的公开语料，还要自己微调影子模型若干份。附录 A.2 给了 Adafactor、学习率 8×10−6、批量 16、序列长度 256、一个 epoch 这套配置，但这部分算力没有折算成攻击代价，也没有和训练免梯度的攻击做成本对照。

遥测是按查询返回这一条假设偏乐观。 论文默认每个候选例子都能拿到自己那次推理的路由信息。真实系统更常见的做法是把负载按批次或者按时间窗聚合，一露就是一堆请求的均值。这种情形下单个候选的路由被抹平，攻击的可行性论文没有测。

张量形状之外的结构条件没有被讨论。 每层负载之和为 1 这件事让表示的独立维度比表面维度少掉层数那么多个。论文把整个向量铺平就直接喂给分类器，没有讨论这个线性约束。

代码与数据处理脚本没有提到。 论文正文和附录都没有给出代码、数据构造脚本或复现包的说明，只给了来源池规模与随机划分的描述。

跨模型迁移没有测。 论文的分类器是在同一个模型的影子副本上训练并应用到同一模型的目标，没有把「在 A 模型上训的分类器拿到 B 模型上用」这条更省事的路线放进实验。

这节要你记住的是，结论的适用范围被三个模型和三个领域限住了。

六、我的评价

下面这节是读完之后自己的判断，不是论文的陈述。

做得对的地方

问题选得准。 把运维遥测当成隐私暴露面，这个角度在 MoE 的文献里是空着的。前面那些路由隐私工作问的是输入本身泄不泄，这篇换了一个量，问输入有没有进过微调集。换完这个问题，攻击者不再需要贴硬件，服务端把负载露出来就够了。问题一换，威胁模型的门槛跟着降了一大截。

对照做得干净。 输出侧和路由侧共用影子模型与成员标签，分类器族和留出目标也相同，唯一的差别是特征里多没多那一块。这个设计让所有 Δ 都有明确的归因，比那种每改一处就换个模型重训一遍的写法可靠得多。

把「路由器记住了数据」这条解释堵死。 冻结路由器的对照、同秩随机子空间的对照，两刀都砍在这个直觉上。冻结路由器那一格尤其省事，参数一个都没动，泄露反而略微变多。

存疑的地方

同秩随机投影这个对照的强度不够。 随机子空间是一个什么都不挑的投影，路由子空间可能只是碰巧比随机好。更该做的是拿另一个有意义的低维读出做对照，比如用隐状态训一个线性探测器，或者用同层的密集前馈激活做主成分投影。跟随机比只能说明路由比瞎猜好，说明不了路由是不是最优的那一档。

机制分析的样本面太窄。 5.5 节和附录 E 全部压在一套模型与领域上。结论写成「微调把成员信息写进隐藏表示，路由器把它投出来」，这个说法是全模型的，证据只有一处。另外 Figure 3 横轴用的是微调 epoch 数，横轴的量是训练时间而不是任何几何量。随着训练推进，隐藏表示里成员信息的增长、路由子空间的稳定性、以及分类器的可分性同时在变，三个量挤在一张图上，分不清哪个在起作用。想分清得固定 epoch 再换学习率或者换训练步数，论文没做。

扰动防御这一节把话说到了结论，却没给出可用的方向。 实测结论是压不干净，这没有问题。问题在于论文没有往下推一步，去讨论别的路子能不能用。跨请求聚合、只露分位数、把负载差分后再露、在训练时对路由分布加正则，这些都留在纸面之外。读者读完这一节知道此路不通，不知道该走哪条。

没有报告聚合粒度的敏感性。 攻击用的是文档级平均。如果把平均换成最大或者方差这类统计量，增量会怎么变，论文没有扫。这个消融比很多别的消融更值钱，因为它直接关系到真实遥测接口该怎么设计。

它想走去哪

从论文的措辞能看出作者把这份工作定位成风险刻画，而不是攻击工程。它在结论里写的是希望模型提供方在设计日志、监控、遥测接口的时候把路由信息当成隐私敏感项。这个定位是合理的，因为论文的威胁模型里攻击者要付的代价不低，三份同领域影子模型的微调算力不是随手能凑的。

按这个定位往前一步，最有价值的下一步是给出一个遥测接口的设计准则。比如哪些聚合量可以露、露到什么粒度、跨请求怎么聚合。这篇把风险量清楚了，准则那一半还没写。

这节要你记住的是，问题换得准，对照做得干净，但机制证据只覆盖了一套组合。

七、可以接着做什么

1. 给隐状态探测一个正面对照

拿同一批留出目标，在隐状态上训一个同样容量的探测分类器，看它的 TPR@1% FPR 是多少。再把路由遥测、隐状态探测、以及两者拼接三种做法摆在同一条轴上。这个实验能直接回答路由遥测的增量是不是它独有的。

2. 把聚合粒度当成自变量扫一遍

现在的路由表示是文档级平均。换成最大负载、负载的方差、负载的熵、或者逐层单独拼接，各跑一遍，看增量怎么变。如果某个粗糙统计量就能保住大部分泄露，那遥测接口的设计空间会立刻变窄。

3. 在真实日志形态下重测

按批次聚合、按时间窗平均、混入其他请求的负载、只露分位数，这些都是线上日志的常见形态。把攻击放在这些形态下跑，比现在这个「每个候选拿到自己那次推理的完整负载」的假设更接近部署。

4. 把防御从后处理搬到训练里

现在的三种扰动都在推理之后生效，注定要拿保真度换。如果在微调时给路由分布加一项正则，让路由输出对训练样本与留出样本尽量不可分，代价可能落在效用那一侧而不是遥测那一侧。这条路线论文只提了后处理，没有试训练期干预。

5. 测跨模型的分类器迁移

攻击者能不能在 A 模型的影子副本上训一个分类器，直接用到 B 模型的目标上。如果能，攻击成本会从「每个目标三份微调」降到「一次训练反复用」，威胁等级会明显上升。论文没有测这条。

6. 把差分隐私的口径接进来

论文全文没有隐私预算这个概念，所有数字都是实验观测。如果给路由负载加一层带差分隐私保证的机制，ε 和泄露降幅之间会有一条曲线。这条曲线比现在的相关系数曲线更有说服力，因为它给出的是上界而不是观测值。

上面六条是读完之后即时想到的线索，没有做实验，没有查证过可行性，也没有核算算力，只当选题的切入点。
