StreamRig 冻住前端，把相机组几何用进流式里程计

Yufei Wei, Shuhao Ye, Qi Wang, Xin Zheng, Qing Huang, Rong Xiong, Yue Wang
arXiv:2609.40244 · 2026-10-05 · 精读约 50 分钟
多相机里程计流式推理三维基础模型冻结前端相对位姿回归

它想干什么

一台人形机器人往前走，身上一圈相机同时按下快门。它要回答一个很朴素的问题，我现在在哪儿。这里的在哪儿指相对出发那一刻的位置和朝向。机器人在线把这个量报出来，这套做法叫里程计。

一圈相机同时看，天然比一只眼睛强。有的方向被挡住，别的方向还看得见。更关键的是，相机之间的相对位置和朝向在出厂前就标定好了，这是一份不需要在线估计的几何信息。

麻烦出在后面那半句。最近这批从海量数据里学出来的三维基础模型很能看，但它们大多按单目视频设计。一次只吃一张图，或者一小段图，跨步没有记忆。能带记忆的流式模型，又基本只处理一个相机，把相机组里那份已知几何白白放着不用。

StreamRig 的办法是先把多视图基础模型冻住，当一眼前端用。前端把同一时刻的几张图连同内参、外参一起吃进去，输出一组带几何感的特征。后面接三块轻量模块。第一块把每个相机的特征压成 16 个 latent，latent 是模型内部的摘要向量，一个相机原本有几百个 patch 向量，这里只留 16 个。第二块让这些压缩后的观测按时间因果地互相看。第三块回归出当前相机组相对锚点相机组的位姿。

要训的只有这三块，一共 74.6 M 参数，占整个 638 M 系统的 11.7%。监督信号只有一样，就是相对位姿。训练分两段。第一段做组重定位，从同一条相机轨迹上取两小段图，让模块先学会把两组图之间的刚体变换估出来。第二段把这份能力搬到因果的相机组序列上。

四套不同的相机组上，它都是参与比较的非 oracle 方法里漂移最低的那个。oracle 在这里指把真值位姿直接喂给模型的变体，论文把它排除在排名之外。五相机的一次推理花 26.2 ms、占 2.6 GiB 显存，同期最快的单目流式模型 CUT3R 处理一帧要 31.3 ms 和 3.9 GiB。

这个效率对比有个前提要摆明。StreamRig 吃的是一个相机组的 5 张 224² 图，CUT3R 只吃 1 张。两边的适用场景也不同。CUT3R 一台相机就能跑，StreamRig 需要一套标定好的相机组。真要比同配置，KITTI-360 上只用前相机时我们的平移漂移是 4.84%，CUT3R 是 3.59%，这一档我们是落后的。KITTI-360 那一列最低的 ATE 也属于 STream3R 的 53.6 m，我们是 63.7 m。

数据这块有个细节要单说。训练只用了仿真，真机上是零样本。人形机器人那套数据是作者自己采的，没有进过训练集。

小结　冻结前端，把力气花在相机组的位姿后端上

一、问题背景

1.1 一个相机组里有什么

先把对象说清楚。论文管一台设备上同一时刻同步拍到的整组图叫一个 rig，中文里叫相机组。它包含 C 个相机各自的一张图 𝐈tc 和各自的内参 𝐊c。内参管一张图怎么把三维方向投到像素上。组里还要挑一个参考相机，其余相机相对它的变换记作 𝐄={T0c}。外参管的就是相机之间怎么摆的那个刚体变换。这两个量靠离线标定拿到，论文明确写了它们已知，但并不是无噪声的。

相机组按时间一帧一帧地来。StreamRig 在任何时刻留一个锚点相机组 at。这个锚点不晚于当前时刻 t。整条流水线在线学的是这样一个映射，把锚点到当前的这一串观测连同标定一起，映到当前组相对锚点组的位姿。

(1)(ℛat,…,ℛt,𝐄)⟼Tat←t∈SE(3)

这个位姿落在 SE(3) 里，也就是三维空间中的旋转加平移。锚点随着流往前推，推进的规则放在 §3.6。

1.2 三条老路，各缺一块

第一条路把相机组当成一台广义相机。多个相机合起来视野更宽，某个方向看不清时别的方向还能补上，于是可以按显式几何残差去迭代优化。ORB-SLAM3 是这条路的代表，它把特征点的重投影误差写成残差，用非线性优化同时解位姿和地图点。这条路线成熟稳当，代价是特征要手工设计，换平台要重新调工程，而且它在线优化的是一堆显式几何量，从大数据里学来的几何先验进不到这套方程里。

第二条路是前馈三维基础模型。DUSt3R 从一对没标定的图里一次前向预测出稠密点图，VGGT 把一整组图放进去联合处理。这两个模型的共性是端到端出几何，不必迭代。它们的差别不在算法，而在调用方式，每次送进去一组固定图像，调用之间不留状态，所以拿它们直接当里程计用会缺一块。Reloc3R 把任务收窄成回归两相机之间的相对位姿，精度不错，同样是一次性的。MapAnything 接受已知的相机几何作为输入，输出带米制尺度的重建。它和前面几个的差别在于相机几何从待估量变成了输入条件，输出也带米制尺度，这一点让它适合当 StreamRig 的前端。代价照旧，它处理的是固定图像集合，跨调用没有持久状态。

第三条路是流式单目三维模型，它把视频按因果顺序处理，带着时序状态。CUT3R 维护一个大小固定的递归状态，状态里存压缩过的场景表示，每来一帧更新一次。STream3R 换个做法，把历史帧的键值缓存起来，用因果注意力去读。LingBot-Map 保留完整的锚帧，把更早的帧压成摘要 token。HorizonStream 用衰减的递归状态加一个局部窗口。这四家的共同短板是每步只处理一张图，一边估位姿一边估相机参数，标定给的那份几何没被当成已知量用上。

还有一条折中路线。G2G 把骨干也冻住，只训轻量模块去估计两组图像之间的刚体变换，组内几何是已知的。它用上了组内几何，处理的是固定的一对组，跨调用同样没有状态。

把这些摆开就能看清缺口。带相机组感知的方法都处理固定图像集合，跨调用没有状态；带时序状态的方法都只吃单目。Rig3R 显式地把相机组元数据当作条件，包括相机编号、时间戳和组内射线方向。它证明了相机组先验有用，同时指出训练数据里相机组配置的多样性有限，这个判断后面还会用到。它的处理方式与前馈模型一致，一次吃一组固定图像，跨调用没有状态。

1.3 难处被拆成两条

论文把难处拆成两条。

第一条是把相机组内部已知的几何用起来，同时让时序推理算得起。把同一时刻的同步视图当成若干独立帧塞进单目流式器，每一步要处理的 token 数直接翻几倍，带缓存的方法连持久状态也跟着涨。这样做并没有把相机之间的几何关系显式编码进去，多花的算力买不到对应的信息。

第二条是从有限的相机组数据里学出可靠的运动估计。从零训一个专用模型，既要学几何感知又要学时序推理，而真实的相机组数据集通常只给稀疏的激光深度，稠密几何监督基本只存在于仿真里。每个数据集内部的相机布局变化又很小，Rig3R 也指出过这一点。

StreamRig 采取的路线是冻结一个有几何先验的前端，把力气全花在它后面的一个紧凑后端上。论文给出的判断很直接。里程计只需要能约束运动的几何线索，不必把每个观测的稠密几何都重建出来。既然只需要线索，紧凑的表示就够做时序推理。

📌 控制视角　这是把离线标定和在线估计的分工重新划了一遍。相机之间的相对位姿是离线给死的量，运行期一个字都不改。在线要估的，只剩整组相对锚点的那一个位姿。分工划得越干净，需要学的那个映射就越窄，样本效率也越好。判断一类学习式状态估计方案能不能落地，可以先问它把哪些量寄存在离线标定里，又把哪些量留给网络现学。

1.4 这篇的做法

用一句话概括，冻住多视图前端，只训一个紧凑后端，再给它一个能把这份能力搬过去的两段训练方案。论文列了三条贡献。一是相机组级的因果流式里程计，把标定多视图感知、压缩时序推理和再锚定拼在一起，流式状态有界。二是一套省数据的迁移配方，用组重定位做预训练，让紧凑后端只靠位姿监督就能适配到因果序列。三是四套相机组上的精度与效率结果。

小结　相机组之间的几何来自离线标定，在线只估整组位姿

三、方法拆解

3.1 冻结的相机组感知，标定只从这里进

每个到达的相机组被 MapAnything 编码一次。它接收 C 张图、由内参算出的逐像素射线方向，以及把参考相机放在单位位姿上的外参 𝐄。内部先用 DINOv2 编码器把每张图切成 token，DINOv2 是一个自监督训出来的通用视觉编码器，靠对比学习得到对纹理和形状都稳的局部特征。它在本系统里原样冻住，只当编码器用，不参与训练。射线编码和位姿编码随后融进这些 token，再由一个交替注意力的 transformer 在相机之间交换信息。输出是一组有几何依据的 patch 特征。

𝐅t∈ℝC×P×D,P=256, D=768

每个相机组就这样以一个整体观测进入流。标定是作为前端的输入条件进去的，可训练模块永远拿不到外参 𝐄，也不假设相机怎么摆。所以换一套相机布局，要改的是前端收到的那个条件，不是后端的参数。

前端是冻结的，特征可以离线算好缓存起来供训练用。论文提到任何接受图像、内参和相对位姿的多视图前端都能替换，§IV-D 里实测了另外两个。

3.2 Rig-Resampler，每个相机压成 16 个 latent

时序推理之前先压缩。Rig-Resampler 用 L=16 个可学习的查询向量和两层交叉注意力，把每个相机那 P 个 patch token 压成 L 个 latent。

𝐙t∈ℝC×L×D

这些查询向量是所有相机共用的，所以加一个相机只是多挂 L 个 token，参数量一点不涨。账可以这样算，五相机时每个相机 256 个 patch，合计 1280 个 token，压完剩 5×16=80 个。80 比一张 2242 图像的 256 个 patch 还少。时序注意力的开销和缓存大小都跟着这个数走。

压缩瞄准的是估计运动与尺度所需的线索，不瞄准稠密重建。§IV-D 里比较了每相机 8、16、32 个 latent 的精度与成本。

3.3 CausalBridge，因果注意力与锚点快照

CausalBridge 装的是 StreamRig 的因果状态，也就是从锚点 a 到当前步 t 这些相机组的压缩 token。进入桥之前，第 s 组第 c 个相机的 token 会被打上三个标签。

(2)𝐙^sc=𝐙sc+𝐞camc+𝐞group1[s=a]+1[s=a,c=0]𝐞anchor

相机标签 𝐞camc 告诉模型这是第几个相机，所有相机组共用。组标签 𝐞group 只在 s=a 时加上，用来区分锚点和查询。锚点标签 𝐞anchor 更细，只有锚点的第 0 号相机拿得到，因为里程计输出的参考系就定在这个相机上。

打完标签，一个窗口里所有相机组的 token 排成一条序列，过八层自注意力。相机组内部的注意力不设限，跨相机组则严格因果，第 s 组只能看到第 s 组及更早的。

这里出现一个真实的矛盾。相对位姿这种东西，锚点和查询互相能看到才好读出来。因果掩码却让锚点永远看不到后面的相机组。StreamRig 的解法是给每个查询相机组 t 配一份锚点 token 的拷贝，论文叫锚点快照 𝐀t。快照只和当前这一组互相看，当前组则能看到自己的快照、以及锚点之后到自己的所有组。

(3)𝒱(𝐀t)={𝐀t, 𝐙^t},𝒱(𝐙^t)={𝐀t}∪{𝐙^s∣a<s≤t}

𝒱(·) 表示一组 token 允许看到的集合。这个构造的好处是双份的。第 t 步的输出只依赖 ℛa,…,ℛt，因果性没有被破坏，所以训练可以整窗一次前向算完，流式推理则可以一次只加一个相机组。式 (3) 这两行定下了桥里谁能看谁的规则，后面所有设计都建在它上面。

桥里没有时间位置编码，式 (2) 那三项里看不出先后。顺序靠两样东西承载，一个是因果掩码，一个是 token 自身的内容。好处是桥能接受比训练时更长的窗口，代价是可达的锚点距离仍然被训练时的位移覆盖范围卡住。§IV-D 试过加旋转时间编码，也就是 RoPE，一种把顺序信息编码成旋转角度的常见做法，四套相机组上都没有收益。

论文还专门解释了为什么单目流式器必须知道时间顺序，而这里可以不要。单目模型要从一帧帧单张图里跨时间恢复几何，必须知道哪些帧在时间上挨得近。StreamRig 的组内几何已经由冻结前端解决了，锚点快照又显式点名了参考相机组，桥只需要关联相机组级的观测。

3.4 Pose head 与只用相对位姿的监督

位姿头读的是两段拼接起来的桥输出，一端是锚点快照里参考相机的 token，另一端是查询组里第 c 个相机的 token。每个相机配两个可学习查询，一个管旋转一个管平移，交叉注意力读出之后再各过一个三层 MLP。旋转解码成 6D 旋转表示，再用 Gram-Schmidt 正交化还原成旋转矩阵，平移直接出三维向量。

里程计输出的是参考相机的位姿，一共 6 个数，三个旋转加三个平移。其他相机的位姿由这个位姿和已知标定推出来，所以它们作为辅助目标不花额外标签，还能让整个相机组的 token 保持几何一致。

监督只有相对位姿。真实偏移 d 上的目标位姿是 (R,𝐭)，预测是 (𝐑^,𝐭^)，损失写成

(4)ℒd=λR19𝔼‖𝐑^⊤𝐑−𝐈‖F2+λt𝔼[13‖𝐭^−𝐭‖1max(‖𝐭‖,ϵ)]

第一项是旋转的均方根弦误差，残差小的时候它近似一个按比例缩放的均方根角度误差。第二项是平移误差，分母除掉真值位移的长度，所以近处目标和远处目标在损失里的分量被拉到同一量级，同时米制尺度的监督还留着。训练时先在固定的 d 上取期望，再对 d 取平均。超参是 λR=5、λt=1、ϵ=0.1 m。

按 R5 的清账口径把估计流程补全。初值来自两个可学习的位姿查询向量，相当于一个从数据里学出来的位姿先验，没有几何迭代起点。驱动它的是式 (4) 的相对位姿残差。给它兜底的是冻结前端带进来的几何先验，以及第一段组重定位热身出来的那份能力。

3.5 两段训练，先学配准再转因果

从零开始训收敛很差，所以拆成两段。

第一段做组重定位，注意力是双向的。一个组是沿某一条相机轨迹取的一小段窗口，两组只要共享视图就配成一对，配对可以跨会话、跨轨迹。这样模块能见到单靠一套固定相机布局得不到的几何和位移范围。

第一段里有个反直觉的处理。输入外参全程被加噪，旋转方向加 1.5∘、平移方向加 0.1 m 的 SE(3) 噪声，而所有监督目标保持干净。这么做的用意是让模块学会从带噪的标定里把真实的相机组几何找回来。第二段反过来，用干净外参训练。

第二段从第一段的权重接着走，模块和参数都不动，换的只有输入和监督。一对图像被换成相机组窗口加锚点快照，双向注意力被换成因果掩码，窗口里每个查询相机组都成了监督目标。

采样上还有两处配平。窗口长度 N 从 [6,48] 里按与 N 成正比的方式抽，长窗口覆盖率不掉，短距离目标拿到的相对权重更高。帧步幅从 [1,smax] 里均匀抽，smax 按各平台的帧率和运动速度设定。这两处和式 (4) 的位移归一化一起，解决的都是同一个失衡问题，远距离目标天生误差大，不配平就会把梯度全占走。

预算方面，可训练模块 74.6 M 参数，占 638 M 全系统的 11.7%。第二段一共跑 576 k 个窗口，总 batch 16，优化器用 AdamW，一种带自适应步长和权重衰减的一阶方法，学习率 10−4 配余弦衰减。冻结特征缓存之后，NCLT 那个模型在 24 GB 显存的 RTX 4090 上大约花 48 GPU 小时。

3.6 流式推理与再锚定

每来一个相机组，骨干感知一次，Rig-Resampler 压一次，打好标签的 token 加入当前窗口。八层桥里所有更早相机组的键和值都缓存在那里，所以让桥对新的相机组和它的锚点快照走一遍，再过位姿头，Tat←t 就出来了。一次前向，不回头看。

锚点如果一直不动，状态会随着序列一直涨。为了把它顶住，StreamRig 按 N 个相机组一块做再锚定。一个块的最后一个相机组成为下一个块的锚点，窗口从那里重起，整条轨迹由一段段锚点到锚点的位姿拼起来。

state≤N·C·L 个 token

式 (1) 每给一次输出就是一个跳，把这些跳串起来就是轨迹。这样缓存里最多留 N 个压缩相机组，序列再长也不变。桥接受任意窗口长度，所以块长 N 是个部署参数，不必等于训练窗口长度。

代价也有两面。块太短，轨迹变成一串短跳，每一跳都带着单次估计的噪声底，跳多了误差累积就明显。块太长，锚点和查询可能不再共享视野，它们的关系要靠中间的相机组接力传过来，一次回归到位就更难。§IV-C 量的就是这个取舍。

还有一个可选的长历史模式。锚点可以长时间不动，整个历史都可寻址，每步延迟和再锚定模式一样。做法是离当前超过 8 步的相机组只保留每个相机的前 4 个 latent，缓存里把其余键值丢掉，训练时用匹配的带状掩码。状态仍然随序列增长，剪枝又损伤短程精度，所以再锚定仍是默认设置，这个模式只当预算参照。

📌 控制视角　再锚定把一条长序列切成一串有界的小估计问题，误差在块之间累积，不在块内部无限累积。这和滑动窗口优化里窗口长度决定精度与成本的取舍是同一个结构。工程上常被忽略的一点是，同时也可以把块长当在线可调的自由度，而论文把它当成一个需要离线扫出来的常数，后面第七节我会顺着这一点往下想。

小结　锚点快照让锚点与当前组互相可见，同时不破坏因果

四、结果

4.1 四套相机组上的主结果

四套相机组的差别很大。NCLT 是校园里的赛格威，五个共心环绕相机，两段 6 km 左右的真实序列，有室内外切换、光照变化、运动模糊和行人。TartanGround 是仿真地面机器人，四个共位的外向相机，测十个留出场景里各自最长的三条轨迹。KITTI-360 是城市驾驶，0.59 m 的双目加两个校正成 90∘ 的侧向鱼眼。ZJH 是人形机器人的自采数据，7 cm 前向双目加两个斜向相机，方位覆盖大约 180∘。

NCLT 是最难的一套。G2G-chain 完全不保留时序状态，却在那一列排第二，漂得比所有单目流式模型都少。StreamRig 和它看到的是同一批图、同一份标定、同样的冻结特征。区别在于 StreamRig 拿每个相机组去对一个好几步之前的锚点，中间那些组也在因果历史里参与推理。每次估计用到的证据因此更多，锚点换得也远没那么勤。链式做法每一跳都重新估一次再复合，复合就把误差累起来。

TartanGround 通过运动而不是外观来考同样的两件事。仿真的机器人爬坡、穿越植被和杂物，遮挡来来去去。G2G-chain 在这里明显好过在目标划分上重训过的 Reloc3R 和 Rig3R，说明把相机组感知搬到新场景靠的是那个冻结的预训练前端。微调过的 CUT3R 和 STream3R 追到差不多的水平，这正是历史状态相对单对图像多出来的那部分。

KITTI-360 是四套里运动最稳的，前向驾驶，旋转尤其稳，单目方法在这里表现很好。CUT3R 和 STream3R 拿到第二好的平移与旋转漂移。

ZJH 考的是零样本的仿真到真机迁移。走路的人形比轮式平台难，每一步都在晃相机组，单位行程的转弯量也是四套里最大的。真机上 StreamRig 的平移漂移、旋转漂移和 ATE 都是那一列最低的。收益在旋转上最大，StreamRig 把第二名 CUT3R 的旋转漂移压低了 63%。这个平台上时序状态确实起作用。CUT3R 排在 G2G-chain 前面，零样本的 LingBot-Map 和 HorizonStream 也排在除 G2G-chain 之外所有非流式方法前面。跨很多相机组的历史能把步态带来的扰动吸收掉。

4.3 再锚定放多远，训练视野放多长

三套模型都画出 U 形的平移误差曲线，最低点落在中间的块长上。锚点挨得太近，轨迹就是一串短跳，每一跳都带着单次估计的噪声底。间隔拉大以后，锚点和查询可能不再共享视野，它们的关系得靠中间那些相机组接力，一次回归到位的难度随位移增长。

标准配置训在 [6,48] 上，平移漂移的最低点在 N=24 附近，到 N=48 只是温和上升，N=64 超出训练视野之后陡升。位移诊断支持一个关于学到范围的解释，测试目标越过训练位移之后，模型输出的位移饱和在最大训练位移附近。训练视野管的是 U 形曲线右边那一段的上升速度。

把训练窗口扩到 [6,256] 和 [6,512]，大幅度上升的位置往右挪，成本从 48 GPU 小时涨到 270 和 710。这里有两条负面结论要一并记下。[6,256] 那个模型在训练范围内平移漂移就已经开始上升，从 N=256 到 320 升得很快。[6,512] 那个模型测到 N=768，上升更缓，可它在 N=512 附近的平移漂移本来就高。更长训练能延展可用的块范围，既没有改善最小的漂移，也不保证训练视野内全程低误差。

还有一个几何上的细节。在这些距离上，转弯会让锚点到查询的位移远小于走过的路程，桥可以把查询通过中间的相机组接到锚点上，位移覆盖仍然在卡位姿头。

📌 控制视角　U 形曲线是经典的偏置与方差权衡。小间隔那一侧，每一次估计的噪声底被跳数放大，是方差主导。大间隔那一侧，模型的位移覆盖不够，一次回归要外推到训练之外，是偏差主导。曲线最低点就是两者的平衡点。这一节值得学的地方在于论文拿一个可观测量（输出位移的饱和）去解释偏差那一侧的成因，而不是只贴一条调参曲线。工程上如果要把块长做成在线自适应，这个饱和量本身就可以当判据。

窗口与平移监督这一组解释的是一件事。远处查询要靠中间那些相机组接到锚点上，所以一个准确的长程估计，前提是缓存状态里那些短程关系本身够准。固定窗口 48 让 1 到 47 跳的目标等权，远目标的误差天生更大，就把损失占走了。平移损失不归一化通过位移造成同样的失衡。两条路都让近程欠训练，远目标再从不准的状态里读数，两端一起变差。混合窗口配位移归一化抵掉的就是这个。固定窗口的代价是 15% 到 30%，用平方根归一化差不多，完全不归一到两倍。按尺度归一的那种监督在三套相机组上平移漂移都更高。MapAnything 输出的是米制几何，所以 StreamRig 能在米制尺度上监督，这份监督除了把尺度定住，也让整条轨迹变好。

锚点快照那一行是 §3.3 那个构造的直接验证。换成静态锚点，三套相机组上代价是 9% 到 38%。静态锚点会被查询读到，但它整个桥里跟查询无关。快照让两组从头到尾互相可见，相对位姿是在那里被解出来的。

latent 数量这一组给出成本曲线。从 16 减半到 8，平移最多掉 18%。翻倍到 32，平移只差几个百分点，NCLT 与 TartanGround 的旋转漂移降了大约四分之一，训练算力大约是原来的三倍，所以作者保留 16。

时间编码那一行是零结果。旋转时间编码在任何一套相机组上都没有收益，平移漂移反而比无编码的桥最多高 8%。论文给的解释是单目流式器要从单帧跨时间恢复几何，必须知道哪些帧时间上挨得近，LingBot-Map 去掉旋转编码后它的轨迹记忆明显变差。StreamRig 的组内几何由冻结前端解决，锚点快照又点名了参考组，桥只关联相机组级观测，因果掩码之外不需要别的顺序信息。

热身那一行是幅度最大的消融。去掉第一段，同样的训练配置下平移漂移涨到大约 4.6 到 14.9 倍。光有冻结的几何特征，从零训不出可用的位姿读出。跨布局跨位移的组重定位先教会后端怎么把几何特征对齐起来，这一步不能省。

感知占了绝大部分。冻结骨干加 Rig-Resampler 花掉 26.2 ms 里的 24.9 ms，桥和位姿头合起来大约 1.3 ms。时序模块几乎不要钱，多挂一个相机的边际成本就是感知它的成本。

论文在这里说明了成本口径。每条链如果都把一对相机组重新编码，就要贵 1.9 倍。缓存上一组特征的链在 N=2 时做的事情和 StreamRig 完全一样。所以表 I 比的是同等成本下的精度，没有比速度。这也解释了为什么 G2G-chain 需要当主要对手。

长历史模式每步延迟和默认一样，状态却随序列增长，512 个相机组之后峰值到 3.0 GiB。有界内存来自再锚定，压缩本身独自做不到这件事。

📌 控制视角　从控制实现的眼光看，26.2 ms 里 24.9 ms 花在感知上，说明这套系统的节拍被感知模块锁死，时序那部分可以忽略。想提频率只有两条路，压感知的输入分辨率，或者换更小的前端。表 IV 已经说明换前端会掉精度。这类账在选题阶段就该算，因为它决定了这套方法能不能配高频控制器，还是只能作为低频位姿源。

小结　四套相机组上漂移最低，同等成本下买到的是精度

五、局限

论文自己承认的局限分散在消融、再锚定研究和未来工作里，归拢起来有这些。

重访没有定量评估。 论文在 NCLT 上做过探索性试验，压缩后的相机组 token 可能对同会话的重访检索有用，但这个能力没有被定量评估，接受门限还需要逐会话调。可迁移的重访触发器和把重访接进流式状态，都写进了未来工作。

位姿与稠密几何没有联合精修。 论文把它列为未来工作，希望能让累积的地图反过来约束后续估计。

从零训练时冻结特征给不出可用的位姿读出。 去掉第一段热身，同样的训练配置下平移漂移涨到 4.6 到 14.9 倍。这一条一方面说明架构对初始化配方的依赖很重，另一方面也暴露了冻结的几何特征需要被教过才用得上。

学到的位移范围限制。 测试目标越过训练时见过的最大位移之后，模型输出的位移饱和在那个范围附近。U 形曲线右边那一侧的上升，论文把它归到这个限制上。

再锚定长度的两难。 块太短会累积更多跳数误差，块太长会超出学到的平移范围。论文明确写成两边的代价，不是只讲一边。

长历史模式的状态会增长。 这个模式保持整个历史可寻址，每步延迟不变，但状态随序列增长，剪枝还损伤短程精度，所以它只能当预算参照。

训练数据里相机组配置的多样性有限。 论文引 Rig3R 的这个判断，指出每个数据集内部相机布局变化很小，这也是第一段为什么要跨会话跨轨迹地做组配对。

更长训练窗口的收益有限。 把窗口扩到 [6,256] 和 [6,512] 能把可用块范围往右延展，代价是训练成本从 48 GPU 小时涨到 270 和 710，而最小漂移并没有改善，训练视野内也不保证全程低误差。

编者补充的局限

下面这条论文未将其列为局限，是我读完之后自己记下的。

没有惯性传感器，也没有回环。 StreamRig 是纯视觉系统，整篇论文没有出现 IMU。快速旋转、强运动模糊或者长时间低纹理的片段里，没有任何惯性量可以兜底，而这类退化恰恰是视觉惯性方案最常被拿出来的理由。第二件事是全局一致性，四套实验都是开环因果拼接，每条轨迹由自己的预测复合而成，地面真值只用于评估，论文没有报告重访或全局优化之后的数字，也没有给长距离下的漂移增长率。第三件事是外参的处理，第一段只按 1.5∘ 和 0.1 m 的扰动量级训练，明显更大的标定误差、或者运行中因为碰撞与温度变化引起的外参漂移，都没有测。第四件事是 ZJH 的米制承诺有限，真机那一列所有方法都按每序列一个全局尺度评估，所以真机上的米制结论只在给定尺度之后成立，而这一列一共只有 3 段、0.36 km。第五件事是单目对照的输入口径不对称，表 V 里 CUT3R 吃一帧 224² 的图，StreamRig 吃 5×224²，输入数量不同。论文把精度和成本分成两套配置测量并明说了这一点，但没有把它列为局限。

小结　纯视觉、无回环，长距离漂移没有兜底手段

六、我的评价

边界划得干净，这是我最欣赏的一点。可训练模块从设计上收不到外参，标定只从前端一个口子进系统，前端又是冻结的。这样一来换一套相机布局要改的是接口而不是重训，论文用换前端那张表把这条路走通了一半。做系统的人都知道，模块边界划在哪，决定了后面出问题时能不能定位。

锚点快照是全文最漂亮的一处设计。它解决的是一个真矛盾，因果掩码不允许锚点看到未来，可相对位姿这种量偏偏要两个端点互相看见才好读。给每个查询配一份锚点 token 的拷贝，既保住了因果性，又让训练能整窗一次前向、推理能一次加一个组。这类做法在注意力结构里不多见，它的价值在于没有为了精度牺牲流式的性质。

不要时间位置编码那一段推理也站得住。单目流式器必须知道帧的先后，因为几何要从单帧跨时间恢复。这里组内几何交给冻结前端，锚点快照又点名了参考组，桥只剩下关联观测这一件事，因果掩码以外的顺序信息确实是多余的。加旋转编码没有收益甚至是负的，这个零结果和推理对得上。

诚实度这块也要记一笔。论文明确写出表 I 的收益是同等成本下的精度而不是速度，还把 26.2 毫秒里有 24.9 毫秒花在感知上这个分布摆出来，自己拆掉了速度这个卖点。再锚定长度的 U 形曲线拿输出位移的饱和去解释偏差那一侧的成因。给出的是一条可检验的机制，而调参记录通常只报曲线。

存疑的地方有三处。

第一，训练窗口扩到 512 之后最小漂移没有改善，论文把它归到位移覆盖上。我认为这个解释只讲了一半，因为位移覆盖够不够是一回事，一次回归能不能表达那么远的相对位姿是另一回事。可检验的推论是，如果瓶颈真的在位移覆盖，那么给更长的训练窗口应当至少把最低点往右挪并保持高度，而实测是紫色的最低点并没有比青绿更低。另一种可能是位姿头的表达能力和监督密度在长位移上不够，论文没有做能区分这两者的实验。这是我的判断，不是论文的结论。

第二，每个数据集内部相机布局变化很小这件事，Rig3R 提过，本文的第一段用跨会话跨轨迹的组配对来补。可那些组仍然是单条相机轨迹上的一小段窗口，它补的是位移和场景的多样性，补不了布局的多样性。想验证，需要一组跨布局的留出实验，比如在共心环绕那套上训、在 0.59 m 双目加侧向鱼眼那套上试。论文的四套相机组确实各不相同，但每一套都有自己的训练划分，所以这个实验没被做掉。

第三，换前端那张表给出了 4.20 到 6.78 的差距，说明前端的选择对结果影响很大。这恰好留下一个我最想问的问题。冻结前端加小后端带来的收益里，有多少属于前端本身，有多少属于这个冻结策略。要回答它需要一组端到端微调前端的对照，成本很高，论文没做。就现有证据看，这套配方最强的部分是它对数据的要求低，只用位姿监督、训练数据只来自仿真，而不是它比端到端方案更准。

它想走去哪是清楚的，重访与回环，再让位姿和稠密几何互相约束。这两条都是从开环里程计走向带全局一致的系统的常规路径。

小结　边界划得干净，机制解释与消融对得齐

七、可以接着做什么

下面四条是读完之后的即时联想，给正在找题的人当线索。

1. 把惯性量接进桥里

论文是纯视觉的。相机组的刚体结构给 IMU 提供了一个好接口。相机之间的杠杆臂是已知量，多相机的相对运动能帮陀螺零偏和尺度解耦。做法可以是在锚点快照之外再加一路惯性预积分，让式 (4) 的位姿残差和惯性残差一起驱动那个位姿头。要回答的问题有三个，惯性量用哪种方式进注意力，是当额外 token 还是当损失项；旋转快的时候惯性权重该多大；以及这种混合能不能把表 III 里那个 4.6 到 14.9 倍的热身依赖降下来。

2. 让再锚定块长在线自适应

论文把块长当离线扫出来的常数，图 4 显示最优值依训练视野和场景而变。既然位移饱和量本身是可观测的，就可以拿它当判据，输出位移一旦接近训练覆盖的边界就把窗口重置，离得远就继续攒。这样比固定 N 更省，也比长历史模式更省内存。要验证的是这个判据在真实系统里会不会抖，以及重置太频繁带来的跳数噪声会不会吃掉收益。

3. 拿压缩后的相机组 token 做重访检索

论文在 NCLT 上做过探索，说压缩 token 可能对同会话重访有用，但没有定量评估，接受门限还要逐会话调。这里可以往下做的是把每个相机组的 80 个 latent 当成一个描述子，建索引做检索，再用几何一致性做二次确认。难点在门限的迁移性，论文已经指出它需要逐会话调，要解决的第一个问题就是判据怎么做到跟场景无关，比如用锚点到查询的位移饱和量当作置信度的代理。

4. 在线微调外参，但要算清代价

第一段按 1.5∘ 和 0.1 m 的噪声训练，说明这套设计本来就有吸收标定误差的意图。把外参从固定的输入条件变成可微的状态，让它跟位姿一起在线微调，理论上能吃到更大的标定误差和运行中的外参漂移。代价是把「可训练模块不接收外参」这条干净的边界打破，前端就不再是完全冻结的了。要做就得先证明收益大于边界被破坏的成本，比如在外参被人为弄偏的实验里比较冻结与微调两条路。

上面四条都是读完文章之后的即时联想，我没有做实验，也没有查证过是否已有人在做，更没有验证过可行性。只当选题线索看，不要当结论用。

小结　四条线索，从接惯性到在线自适应，都还没有实验
