机器人不知道自己完了没有

Yufeng Liu, Bohao Fan, Juntu Zhao, Xinyi Wang 等
arXiv:2610.31569 · 2026-11-02 · 精读约 34 分钟
VLA任务状态信号流匹配异步去噪真机操作

它想干什么

插花任务里，机械臂捏着花茎伸向瓶口，位置差了两厘米，花头蹭在瓶沿上，蹭了三次，第四次松手，花落在桌面上。它接着伸手去抓，抓了个空。整段过程里策略一直在稳定输出动作，没有任何一个输出量在说这一步已经废了。看出来的是站在旁边的操作员，按急停的也是他。

视觉语言动作模型缺的就是这一块。这类模型简称 VLA，读进来的是几路相机加一句口令，吐出去的是动作。π₀.₅ 是 Physical Intelligence 的一个 VLA，一个视觉语言模型接一个小动作网络，后者一次给出 60 步的动作。动作很细，判决没有。要不要停，要不要退回去重来，这些决定全在策略外面，而人得一直站在旁边替它判。

现成的做法有两条。一条是外挂监控模型。Robometer 属于这一类，它是一个 4B 参数的视频语言奖励模型，看执行视频打进度分和成功概率，训练时用轨迹之间的偏好比较。好处是完全不动策略，一个模型能挂到不同策略上。代价是每帧多一次前向，而且这个分数落在动作生成之外，进不了动作。另一条是把状态塞进策略内部。CycleVLA 在主策略之外另配一个失败预测和一个子任务回退，VLA-Corrector 在潜空间里比对预测特征与观测特征的走向，偏了就截断当前动作块重新规划。这两条都要额外的模块、额外的监督或者推理期额外的梯度。

Echo 的办法是把判决当成动作的一个通道。动作块本来是一个 H 行 d_a 列的矩阵，它在右边加两列，一列停止信号 SS 一列失败信号 FS，整块变成 H 行 d_a 加 2 列。生成的时候三组数据在同一个 Transformer 里一起走，动作能读两个信号，两个信号能读动作，SS 和 FS 之间不许直接读对方。信号的时间表比动作快，动作走到一半时信号已经解完并冻住，剩下那一半步数里，动作是在知道自己正在失败的条件下继续生成的。

效果落在真机五个任务上，每个任务 30 次试验。Insert Flower 的任务完成分从 π₀.₅ 的 5.67 到 Echo 的 8.33，Open Drawer 从 5.40 到 7.90。差别最大的是分布外位置，Insert Flower 上基线从 9.33 掉到 2.00，Echo 只从 8.67 掉到 8.00。仿真里差距小得多，34.76% 对 32.67%，差 2.09 个百分点。

这节要你记住的是，把停和废写进动作块，策略就能自己报状态。

一、问题背景

1.1 缺的是一个不花标注的状态量

状态这件事的成本两头不对称。段级标签几乎白送，这条 episode 最后成了没有，人和脚本都能判。逐帧进度很贵，第 137 帧完成到几成，得有人一帧一帧标。现有的做法要么去买逐帧标注，要么训一个外部模型来伪造逐帧分数。Echo 想绕开的是这两笔开销。

一切的起点是段边界。一个 episode 什么时候结束是已知的，成功结束还是失败结束也是已知的。Echo 的观察是，停止和失败这两个量都只在边界附近改变取值，段中间的目标是常值。于是一个段级标签加上一个边界位置，就够给出整条动作块上每个位置的 0 或 1。把段级标签摊成逐位置目标，是这套方法里最省的一件事。

1.2 前人两条路各自缺什么

外挂那一路把状态当成外部评分。Robometer 用轨迹对之间的偏好比较训一个通用奖励模型，输出进度与成功概率，部署时对执行视频离线打分。它的优势在可移植，一个模型跨任务用，被评的策略一行不改；短板在分数与动作脱节，模型说你失败了，策略还按原计划走。

内嵌那一路把状态当成策略的另一个头。CycleVLA 是 progress-aware 的 VLA 配一个外部失败预测，判到失败就回退到上一个子任务重做。它的停止信号只在最后一帧有监督，成败判断主要靠进度信号，训练里也不用真实的策略失败数据。VLA-Corrector 不预测状态，它用一个潜空间视觉监视器比对预测特征与实际特征的演化，出现持续偏差就截断动作块，用 Online Gradient Guidance 重新规划。ProgressVLA 走得更远，用一个世界模型把进度梯度传到动作生成过程里，代价是推理期多一次梯度计算。

这三条都在做同一件事，先把状态算出来，再拿它去做决定。动作生成本身不知道状态，状态是在外面算的。

1.3 这篇押的取舍

Echo 押的是少加东西。骨架不动，还是 π₀.₅，动作张量加两列，注意力加一个掩码，生成的时间表加一张，参数增量可以忽略。代价有三条，先说清楚。信号的分辨率被动作块的长度绑住，H 个位置共用一次判决。信号只有两个二值量，说不出完成到几成。信号的学习完全靠段的类型和边界，如果一段轨迹里失败发生在中间而不是结尾，这套目标表达不了。

📌 控制视角　把 padding 边界当成边界条件，这件事在控制里很熟。做轨迹规划时终端约束是给定的，中间怎么走由动力学决定。Echo 换了个摆法，给定段的类型和边界，把 0 或 1 的目标摊到这条块的所有位置上，中间那段不用管。摊的是标签不是状态，摊完就能直接拿去当监督。

这节要你记住的是，段边界白送标签，这是整套监督的地基。

三、方法拆解

3.1 动作块与那条越界边界

先说生成方式。Echo 建在流匹配的 VLA 上。流匹配把生成写成一条直线路径，给定一个干净样本 𝐱0 和高斯噪声 ϵ，中间状态是两者的线性插值。

(3)𝐱τ=(1−τ)𝐱0+τϵ,τ∈[0,1]

τ 是流时间，0 表示干净数据，1 表示纯噪声。网络学的是速度 𝐯θ(𝐱τ,τ,𝐜)，条件 𝐜 是观测、机器人状态和口令的合称。训练时让预测速度去拟合 ϵ−𝐱0，推理时从 τ=1 积到 τ=0，这个反推过程就是去噪。

一次查询只给一段，长度记为 H，记作动作块 𝐀t∈ℝH×da。t 是这一块的起始时刻，da 是动作维数，块里第 i 个动作 𝐚t,i 对应时刻 t+i，并且是相对这一块开始时机器人状态写的增量。

采样出来的块会越过当前段，进入下一个子任务，或者跑出 episode 之外。记这一段最后一个合法动作时刻是 T，越界位置用 padding 掩码标出来。

(1)pt,i={0,t+i≤T,1,t+i>T,i=0,…,H−1

pt,i 取 0 表示这个位置还在段内，取 1 表示已经越界。越界位置的监督目标改成重复最后一个合法动作，免得损失去学一段不存在的动作。

(2)𝐚~t,i=(1−pt,i)𝐚t,i+pt,i𝐚t,T−t

这条掩码顺手干了第二件事。段以成功结束时，越界位置就该报停。段以失败结束时，越界位置既该报停又该报失败。所以监督目标不用人一帧一帧标，只要知道段怎么结束、边界在哪。

3.2 两个信号与一条判决规则

停止信号 SS 管该不该收工，失败信号 FS 管现在是不是失败状态。两条信号和动作共用同一个块长，各自是一个 H 行的列向量。

(4)𝐒t=[st,0,…,st,H−1]⊤,𝐅t=[ft,0,…,ft,H−1]⊤

沿特征维拼起来，得到的就是被生成的那个块。

(5)𝐗t=[𝐀~t,𝐒t,𝐅t]∈ℝH×(da+2)

这里要把未知数的账记一下。一个二值信号只能把还在做和已经结束分开，而要区分成功结束和失败结束至少得两个二值量，21=2&lt;3 不够分。两条信号给四种组合，22=4≥4，正好覆盖执行中、可恢复失败、成功、终局失败四种情形。按块算，未知数是 H(da+2) 个数，形状就是式 (5) 那个矩阵。

监督侧的观测源只有两个，段的类型和边界位置。一条 episode 只贡献 1 比特的段级标签，这个标签靠边界 T 展开成最多 H 个位置的 0 或 1 目标。要让 SS 学得动，最少需要一条以成功结束的段和一条以失败结束的段，否则 0 和 1 两类目标只有一类。要让 FS 学得动，最少需要一条带 padding 的失败段，因为表 1 里不带 padding 的失败块对 FS 完全不监督。两个观测源里，段类型决定哪个信号在边界翻一，边界位置决定在哪里翻。

判决在块内先取均值，再比阈值。

(6)s¯t=1H∑i=0H−1s^t,i,f¯t=1H∑i=0H−1f^t,i
(7)zt={执行中,s¯t<δs,成功,s¯t≥δs∧f¯t<δf,终局失败,s¯t≥δs∧f¯t≥δf.

s^t,i 与 f^t,i 是去噪结束后两条信号在第 i 个位置的预测值，s¯t 与 f¯t 是它们的块内均值，δs 与 δf 是两个阈值，全部实验取 0.5。式 (7) 只列了三种情形，第四种组合是低 SS 加高 FS，论文把它单独命名成可恢复失败，用来触发纠正。

3.3 四类数据怎么给出监督

数据来自四个地方。成功演示靠遥操作采集。终局失败的轨迹来自策略测试时的 rollout，rollout 指策略在真机上自己跑出来的一条完整轨迹。策略执行过程中操作员会介入，介入之前那一段叫接手前失败段，介入之后操作员接管完成的那一段叫 recovery 演示，它可能只做完一次局部修正，也可能把整个任务做完。四类数据合起来更新策略，再进入下一轮采集。

表 1 是这套方法的核心，它把段类型、边界位置和三条监督通道对上了。

动作监督分得很干脆。成功演示整块都监督，包括越界位置。recovery 只在非越界位置上监督，因为 recovery 段可能在任务完成之前就结束，学了它的越界动作会让策略提前收工。终局失败和接手前失败这两类的动作全部不进模仿，避免把失败的行为学进去。

停止信号分得更细。不带 padding 的块，SS 目标全 0，因为执行还没走到头。带 padding 的块要看段怎么结束。成功段和终局失败段都以一个终止事件收尾，两者都用 padding 掩码当 SS 目标，越界位置取 1，整块监督。接手前失败段结束于操作员接管，任务在后面还要接着做，所以它的 SS 目标全 0，包括越界位置。recovery 段的 SS 也全 0，但只监督非越界位置，理由和动作那一侧一样，recovery 的结尾不一定是该停的地方。

失败信号的关键在于段级标签说不出失败从哪一帧开始。不带 padding 的失败块因此不监督 FS。段的终点必然处在失败状态，这一条是确定的，于是带 padding 的失败块用 padding 掩码当 FS 目标，越界位置取 1，其余取 0，整块监督。失败从哪里开始不用标，只要知道它已经发生了。

recovery 段要表达一种过渡，从一个可恢复的失败状态走到能重新开始执行的状态。论文用一条随进度下降的斜坡。

(8)ut=t−t0t1−t0,nt=round(Hut)
(9)rt,i={0,i<nt,1,i≥nt,i=0,…,H−1

t0 与 t1 是 recovery 段的起止帧，ut 是归一化进度，取值范围 0 到 1。nt 是把这个进度乘上块长再取整，rt,i 是第 i 个位置的目标值。首帧的块全是 1，说明整块还在失败里。末帧的块全是 0，说明已经出来了。中间是 [0nt,1H−nt]，均值 1−nt/H 随恢复进度近似线性下降。这一路目标在整块上监督，包括越界位置。

四类数据凑在一起，正好把四种状态在目标上分开。成功段给出高 SS 低 FS，终局失败段给出高 SS 高 FS，接手前失败段给出低 SS 高 FS，recovery 段在前者基础上再补一份纠正动作。段类型决定哪条信号翻，边界位置决定在哪里翻，这一句话就是表 1 的全部。

3.4 一条序列里放三组 token

动作、SS、FS 分别投影成三组 token，和前缀拼成一条序列。token 是序列里的一个位置片，一块数据切成 H 片就是 H 个 token。

(10)𝐇=[𝐇P;𝐇A;𝐇S;𝐇F],𝐇q=ϕq(𝐱τqq),q∈{A,S,F}

𝐇P 是多模态前缀，装着观测、机器人状态和口令的上下文。ϕq 是第 q 组的输入投影，逐组独立。τq 是这一组自己的流时间，后面要用。三组 token 进同一个 Transformer，但特征变换的 MLP 和输出投影各用一套，MLP 就是几层全连接。

一条序列里三组 token 的噪声水平可以不一样，这一点和常见的实现不同。Echo 把流时间从一个样本一个值改成一条序列里每个 token 一个值，批量是 B、生成长度是 L 时，时间张量的形状是 B×L。同一组的 token 拿自己那一组的时间，嵌入之后送进 Transformer 里的 AdaRMS，那一层按条件调制归一化的参数。

注意力在这里被切成三种关系。动作 token 能读前缀，也能读 SS 和 FS 两组。SS 和 FS 能读动作 token。SS 和 FS 之间两个方向都挡住。前面两条让状态估计能引导动作，也让动作特征能反过来帮助状态判断。第三条是防止两条信号互相抄，消融里放开这一条，帧级准确率就掉下来了。

被优化的量是三个速度场。初值从高斯噪声来，三组各自一份。驱动它的是掩码后的速度残差，逐位置、逐通道。

(13)ℒ=𝔼[∑q∈{A,S,F}λq‖𝐌q⊙(𝐯^θq−(ϵq−𝐱0q))‖F2]

𝐯^θq 是第 q 组的预测速度，ϵq 是给这一组采的噪声，𝐱0q 是它的干净目标，𝐌q 按表 1 选出该组哪些位置有方程，并沿特征维广播，λq 是权重。动作项 λA=1，两条信号在不带 padding 的块上取 λS=0.1、λF=1，带 padding 的块两者都取 1。兜底的是表 1 的目标构造，它决定了哪些位置有方程、方程右边是什么；推理时还有一道兜底，信号到达端点之后冻住，不再被后面的步数改动。

3.5 先解状态，再解动作

分成两步走的理由来自一个测量。论文先用同步去噪的对照模型看两条信号什么时候收敛，做法是在第 k 步用当前噪声状态和预测速度反推干净样本的估计。

(11)𝐱^0(τ)=𝐱τ−τ𝐯θ(𝐱τ,τ,𝐜)

𝐱τ 是这一刻的噪声状态，也就是反推的起点，𝐯θ 是网络给的速度，τ 是当前的流时间。这个反推靠的是式 (3) 那条线性路径，速度预测如果正好等于 ϵ−𝐱0，减掉 τ 倍速度就精确回到干净样本。预测有误差时它只是一个估计。论文在附录 A.5 里专门交代，这个重建只用来做分析，推理时并不替换掉那个噪声状态。

原文图 3 里，SS 和 FS 的估计在去噪早期就贴近终值，SS 在最早一步就已经接近它的零目标；右臂竖直方向的动作估计到了第 8、9 步还在变。论文在附录 A.5 里给这条观察加了限度，它不表示每一次信号预测都对，也不表示所有动作维度需要同样多的步数。

于是信号组换一张时间表。设动作组的流时间是 τA，信号组用

(12)τq=max(0,τA−τclean1−τclean),0≤τclean<1

τclean 是信号到达干净端点时的动作流时间。取 0 就是同步去噪，三组时间完全相同。真机上取 0.5，意思是动作走到一半时两条信号已经解完。式 (12) 的分母做了一次归一化，让信号组在自己的 0 到 1 区间里重新铺满，于是它要用两倍的速度跑完同一段路。

推理时三组各自从高斯噪声出发，按自己的时间表更新。信号一旦到达端点就保持不动，动作继续往下走，后续每一步的注意力都能读到这份干净的状态。最终两条信号的块内均值，就是式 (7) 用的那两个数。

一句话概括这套机制，把停与废并进动作块，让它们先解完再去引导动作。

x_A, x_S, x_F ← 三份高斯噪声          # 式 (5) 那个块被拆成三组
for k = 9 … 0:                        # 十步，步数固定
    τ_A ← 第 k 步对应的动作流时间
    τ_q ← max(0, (τ_A − 0.5) / 0.5)   # 式 (12)，q 取 S 与 F
    v_A, v_S, v_F ← 共享 Transformer（联合 token，各自的 τ）
    x_A ← 用 v_A 推一步
    if τ_q > 0: x_q ← 用 v_q 推一步      # 还没到端点，继续解
    else:       x_q ← 保持不动         # 冻结，后面的动作条件化在它上面

这段伪代码只交代一件事，三组 token 在同一次前向里算，但三组的推进节奏不同，信号先到端点就先冻住。它对应式 (12) 和原文 3.2.3 节末尾那句信号到达端点后保持不动的描述。

3.6 推理一趟要多久

一次查询走十步去噪。因为加了两组信号，生成的 token 从 60 个变成 180 个。在 RTX 4090 上，延迟从 115 毫秒变成 120 毫秒，多出来 5 毫秒。查询频率是 5 Hz，也就是每 0.2 秒问一次，判决窗取 15 帧合 3 秒。

输出是动作块加两列信号，没有单独的高层规划器，判决和动作在同一次前向里一起出。策略每 0.2 秒重看一次观测并重新出块，纠错的机会落在查询点上。

这节要你记住的是，两列信号、一个掩码、一张更快的信号时间表。

4.5 干预与失败数据量

想证明信号在改动作，最直接的办法是把信号钉死。论文在每一步去噪之前，按当前噪声水平把两条信号替换成指定的目标。

(14)𝐱τqq←(1−τq)𝐡q+τqϵq,q∈{S,F}

𝐡q 是指定的目标块，ϵq 是高斯噪声，τq 是这一组当前的流时间。SS 固定成 0，FS 分别固定成 0 或 1，就得到正常执行和可恢复失败两种输入。

另一组是失败数据量的扫描。终局失败轨迹从 50、120、190、250 条四档取，250 是主实验用的数量，其他三类数据、训练设置、失败数据的采样比例都不动。

这两条一起读，结论相当干净，数字读自图 6 的坐标轴。失败数据变多，帧级 F1 单调升，完成分不动。原因在监督结构里，终局失败轨迹的动作本来就不进模仿，它只贡献状态监督，所以加它对动作没有任何影响。完成分要靠接手前失败段和 recovery 演示，这两类在扫描里是固定的。

五、局限

先列论文自己写下的，每条都能对到原文的句子。

阈值单一设置不对所有任务最优。 附录 A.8 的原话是一个单一的阈值设置并不能让每个任务的帧级 F1 都最大。Capsule Toy 的帧级 F1 在 SS 阈值 0.1 时是 98.1，0.5 时是 88.3。帧级对 SS 阈值比对 FS 阈值敏感得多。

窗长不是越长越好。 附录 A.8 写了更长的窗补不上某些阈值选择带来的损失。Make Tanghulu 在共享阈值 0.1 时，无论窗长取 5 到 25 帧，轨迹级 F1 都停在 50.0。

窗长只影响轨迹级评测。 论文写明这些离线比较只刻划状态评测，不改录下来的那些 episode 的动作，也不改完成分。

那个动机实验的适用范围有限。 附录 A.5 的原话是它不表示每一次信号预测都对，也不表示所有动作维度需要同样多的去噪步数。

和外部监控、重规划的兼容只是架构上的。 附录 A.9 的原话是某个具体组合系统能不能更好，需要单独评测。

仿真里的超时不是终局失败的真值。 附录 A.10 写明模拟器不提供终局失败的发生时刻，所以这套评测不单独衡量终局失败报得及时不及时。

仿真的统计口径有限。 三个评测种子共用一个 checkpoint，不是独立训练重复。渲染器在固定种子下也不保证像素完全一致。

逐帧的成功与失败召回明显低于执行中的召回。 附录 A.7 的原话是成功和失败的逐帧识别更低。表 9 里执行中召回最低 99.79，成功召回 66.06 到 78.60，失败召回 75.00 到 79.78。

分布内差异小而且依赖任务。 4.4.1 节的原文说法，对应的就是表 4 里 Insert Flower 分布内 Echo 低于基线那一格。

编者补充的几条

下面这些论文没有写进任何一处局限清单，是读下来自己看到的，标清楚以免和上面混。

真机的数据规模只给了比例。 附录 A.3 给的是成功、失败、接手前失败、recovery 四类按 20 比 1 比 2 比 20 的比例采样，失败数据扫描给到 250 条终局失败轨迹，其余三类的具体条数全文没有出现过。数据规模是这类工作最要紧的变量，缺了它就复现不了 4.5 那条曲线。论文未将其列为局限。

动作维数与执行时长没写全。 机器人一共 20 个受控自由度，块长 H 是 60，查询频率 5 Hz。da 的具体取值、一次查询给的 60 步动作要执行多久再重查，原文都没写。我读不出这套系统真实的查询周期。论文未将其列为局限。

消融和干预只在一个任务上做。 4.4.2 到 4.4.5 全部在 Insert Flower 上完成，跨任务只报主结果。表 5 里放开互读、改用同步去噪、三组共用 MLP 这三行的完成分分别比 Echo 低 0.66、1.00、1.66，而单任务 30 次试验的标准误是 0.69 到 0.93，这个分辨率对小的机制判断不够。论文未将其列为局限。

两个基线的口径对它们不利。 Robometer 被降成二分类，所有进行中的样本算失败；CycleVLA 的停止信号只在最后一帧监督。论文在附录 A.6 写明了这两处适配，但它们会让表 3 的差距读起来比实际大。论文未将其列为局限。

任务族偏窄。 五个任务都是桌面单臂操作，最长的一个也就一次插入，没有长程多阶段，也没有可形变物体。两个二值量在长程任务上够不够表达该不该停，没有测。论文未将其列为局限。

这节要你记住的是，阈值和窗长是明写的限制，数据规模是没写的限制。

六、我的评价

做得最好的地方是把状态塞进动作张量，而不是另外接一个头。这个选择的收益很清楚，参数几乎不涨，token 从 60 到 180，延迟 115 到 120 毫秒。它把状态从外部评分变成动作生成的一个条件，整条外挂链都省掉了。控制里的人会认这个结构，状态进了被优化的那个量，后面就不需要额外的仲裁逻辑。

第二件做对的是用 padding 边界白拿标签。这一招的成本接近零，效果是把逐帧标注这件事绕过去。表 1 那八行本身就是一个可复用的构造，换任何动作分块策略都能套。这套监督的巧处在边界，不在网络。

第三件是消融拆得干净。去掉动作到信号的注意力，信号指标还在（帧级 90.78，轨迹级 100.00），完成分掉到 5.00。这一行把信号报得准和信号帮上忙分开了，多数同类工作做不到这么切。

存疑的地方有五处。

一是分布内没有稳定优势。Insert Flower 上 Echo 8.67 低于 π₀.₅ 的 9.33。论文的说法是差异小且依赖任务，我读这个数字更直接一些，多出来的两列和一条注意力路径在这个任务上换不来分布内的收益，收益全在分布外。全篇只有两个任务做了分布内外拆分，样本还不够支撑一个普遍结论。

二是 τ_clean 只有一个工作点。真机 0.5，仿真 0.7，两者之间没有曲线，也没有对 0.25 或 0.75 的扫描。同步与 0.5 的对照确实说明了分时的价值，但 0.5 是最优还是随手取的，看不出来。这个超参又直接影响推理，值得单独看。

三是两个信号损失的权重不对称，没有解释。λS=0.1、λF=1，论文只说这两个权重用来平衡带 padding 与不带 padding 的样本数。停止信号在成功段上只有越界那一小段是 1，信息量本来就少，再压到十分之一还能学到东西，这件事值得单独看一眼。

四是失败数据扫描没看到饱和。50 到 250 条，帧级 F1 从 81.94 一路升到 92.18，最后一段斜率还在。250 条不是拐点，继续加可能还涨。论文用这条曲线论证失败数据的作用，曲线本身没有给出够用的判据。

五是干预实验是定性的。图 5 只有一次实验的两条曲线，没有统计，没有重复，也没有换任务。它说明信号能改动作方向这件事存在，说明不了这件事稳定。

它想走去的地方，我读出来是把执行判决做成生成过程的一个通道。这个模板可以往外推，信号从二值走向连续进度，从一个失败位走向多类失败，从单任务走向长程多子任务。附录 A.9 提了把这两条信号交给高层控制器做校验、请求介入和重规划，也老实写了那只是架构上的兼容，哪个组合系统真能更好要单独评。

这节要你记住的是，设计省得漂亮，分布内的收益还没站住。

七、可以接着做什么

读完顺手想了几个方向，都能在现有代码上做。

1. 扫 τ_clean 的整条曲线

现在只有 0 和 0.5 两个点，仿真用了 0.7。可以在 0.25、0.5、0.75 三点各训一次，同时看信号精度、完成分和轨迹级 F1。这三条曲线不一定单调，信号解得太早，动作还没成形，条件可能没有信息量；解得太晚就退回同步那条路。真机与仿真两套 H 各扫一遍，能看出这个超参跟块长的关系。

2. 把停止信号改成连续进度

两个二值量表达不了完成到几成，这在长程任务上会卡住。可以在 SS 旁边再加一条进度通道，用段内位置当监督，仍然是白拿的那一类标签。接下来要回答的是长程任务上多这一条通道能不能省数据，或者能不能让高层规划器直接拿它做子任务切换。

3. 把失败信号拆成多类

抓空、滑落、碰撞，这三类在动作上要的纠正完全不同。同一套 padding 边界监督可以推广到多类，代价是段级标签不够用了，得给失败类型再标一次。值得试的是这个标注成本能不能靠策略自己的置信度降下来。

4. 让注意力掩码变成可学的门控

现在 SS 与 FS 互不读是硬约束，动作读信号也是硬接的。可以让模型自己决定在哪一步去噪时读信号、读多强，门控参数跟着流时间走。消融里同步去噪只掉了 4.89 的帧级 F1 却掉了 1 个完成分，说明时序关系可能不必是全局固定的。

5. 构造临界失败段

FS 现在只靠带 padding 的失败块监督，越界位置一律取 1。这等于说只要这段最后失败了，越界位置就都是失败。可以主动采一批离成功只差一步的失败段，看 FS 在接近成功时的分辨力能不能提高。这条和分布外的关系最大，因为分布外的失败很少是干脆的失败，多半差那么一点。

6. 把 SS 与 FS 接到决策层做在线切换

论文只做了架构兼容性的声明，没有实测。把这两条信号接到 MPC 或者一个高层规划器上，让停止触发重规划、让失败触发行人介入，这是一个完整系统的问题，不只是策略的问题。最先要确认的是信号的时间尺度够不够，5 Hz 的查询频率对快到毫秒级的碰撞类失败肯定不够。

这节要你记住的是，超参没扫、进度没做、决策层没接，三处都是口子。

上面六条是读完之后的即时联想，我没有做实验，也没有查证是否已经有人在做，更没有验证可行性。只当选题线索看，不要当结论用。
