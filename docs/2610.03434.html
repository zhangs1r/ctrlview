给客服 agent 划一条功能边界，让它在越界时自己收手

Bijeeta Pal, Sridhar Reddy Maddireddy, Muhaimin Bin Munir, Zoltan Puha, Max Zhurovich, Adi Raghavendra, Sean Tout
arXiv:2610.03434 · 2026-10-19 · 精读约 36 分钟
运行时护栏功能边界越域检测威胁模型生产部署

它想干什么

一个订票助手被用户套着问了几句体检报告该怎么看，它答了。这段话里没有一个字算得上违规，没有违规内容，没有泄露系统提示，也没有绕开任何安全策略。它的错在于答了一个自己不该答的问题。

这道裂缝在学界和产品之间挂了很多年。现有的运行时护栏大多盯着攻击，检测提示注入、越狱、有害内容这几类动作，判据是「这句话是不是攻击」。可用户并不需要攻击，他只管往下问，一个订票助手就会顺着他聊到营养学、劳动合同和签证材料。论文把这种现象叫功能边界越界，把越界的请求叫 out-of-domain（域外请求，下文简称越界请求）。它跟攻击的区别很重要，攻击要伪装，越界请求往往干干净净，问的人也不觉得有什么不妥。

Persona Guardrail 的做法是把 agent 的功能范围先写死成一份人能读的规格，然后在两个时刻拿这份规格去核对，请求进 agent 之前核一次，回复交给用户之前再核一次。两次核对都由同一个模型做，模型手里握着这份规格，输出一个词，放行或者拦截。

论文同时放出一个评测集，叫 PAGE。它把 2180 条消息分门别类打了标签，每条都标明属于四个业务域里的哪一个、落在用户这一轮还是 agent 这一轮、属于正常请求还是攻击还是越界请求。这个标注方式让一份评测集同时压到输入和输出两道守卫上。

结果里最值得看的一条是越界检测率。只给模型一段泛泛的 agent 描述当判据，它能挡下 92.6% 的攻击，可越界请求只挡下 57.3%，误放率 25.0%。把这份规格换成逐条列出的允许意图清单，再根据第一轮的错判把清单的措辞磨一遍，越界检测率升到 93.5%，误放率降到 4.7%，总体准确率从 85.7% 升到 95.9%。同一段路上，正当请求被误拦的比例三档都停在 3.7% 上下。

攻击是容易的那一类，一个泛泛的描述就能挡掉九成。难的是认出那些问得挺专业、只是不属于这个 agent 的问题。本文的全部设计都压在这条判断上。

这节要你记住的是，这篇防的不是攻击，是答了不该答的问题。

一、问题背景

1.1 为什么这件事不好做

先看防御要判的是什么。设 Q 是所有可能提交给这个 agent 的用户请求构成的集合。功能边界把 Q 切成两块互不相交的子集

(1)Q=Qallow∪Qblock

其中 Qallow 是这个 agent 按设计该处理的请求，Qblock 是该拒的请求，包含恶意与不安全的那些，也包含部署上选择了拒绝的越界请求。护栏要做的事就是把这个划分近似出来，把正当请求误拒和把该拒请求误放这两类错误一起压低。

难的地方在式 (1) 右边的两个集合都没法显式写出来。自然语言的表达空间实质上没有上界，谁也没法把「一个订票助手可以接的所有话」列完。论文的原话是枚举 Qallow 与 Qblock 不可行，只能用语义描述去近似这条边界。

这条边界还不是静止的。agent 的提示词、工具、接口、检索源、支持的能力都在改，用户的话也在改。判据写死之后，agent 一升级，判据就跟不上。

1.2 前人两条路的短板

第一条路是规则和策略式护栏，论文指的是 NeMo Guardrails [17] 这一类可以编程的护栏工具箱。它把 rail 规则写进对话流程里，采用对话流与规则一起定义，命中规则就按规则给的答复走；好处是确定性强，坏处是异构 agent 一多就铺不开，规则写的是已知模式，没见过的攻击和依赖语境的判断都接不住。

第二条路是模型式护栏，论文指的是 Llama Guard [10] 与 Prompt Shields [15] 这一类。Llama Guard 是一个指令微调过的模型，输入是对话加一份风险分类表，输出是 safe 或 unsafe 加违禁类别，把内容审核做成一次分类调用；Prompt Shields 是 Azure AI Content Safety 里的一项服务，专门检测越狱与间接注入。这条路灵活、泛化好，代价是它按全局的危害类别判，判不出「这个 agent 该不该接这个问题」，而且调用推理模型的开销直接压在关键路径上。

把两条路合起来看，缺口在于没有一条路给出「逐 agent 的功能范围」这种细度的判据，也没有人系统量过这种判据在生产负载下够不够便宜。论文引的 SoK [12] 把现有防御分成运行时保护、设计即安全和组件加固三类，同时点出需要能在真实部署约束下工作的自适应防御。

1.3 最接近的几项工作和它们的差别

论文把它定位成互补，不打算取代谁。挑四项讲清楚差在哪。

Task Shield [11] 把 agent 的中间步骤拿去跟用户任务对齐，检查每一步是不是还在为用户那件事服务。它守的是执行过程，动作发生在 agent 内部；Persona Guardrail 守的是送进来和处理完这两个时刻，中间那段的动作它不看。

LlamaFirewall [4] 是 Meta 生产在用的链式护栏，把越狱检测、思维链对齐、代码扫描几个检测器串起来，覆盖 agent 的输入、推理和输出三段。它按攻击类型堆检测器，判据是「这一步像不像攻击」；Persona Guardrail 用一份逐 agent 的白名单判「这一轮在不在这个 agent 的职责里」，越界请求没有攻击特征也能被它认出来。

CaMeL [5] 走设计即安全那条路，把控制流和数据流分开，让不可信内容没法改写程序本身。这一手能根治间接注入，代价是要求应用按它的结构重写，而 Persona Guardrail 是加在现有链路两端的分类调用，不动 agent 内部。

Constitutional Classifiers [19] 是四项里最接近的。它拿一份自然语言写的政策去训输入和输出两个分类器，训练数据由政策合成，生产开销做得下来。两边的差别落在边界怎么给。它训的是全局危害类别，一份政策管所有场景，判据是内容属不属于某类危害；Persona Guardrail 每个 agent 一份允许意图清单，同一个分类器换一份清单就换一个 agent，判据是请求属不属于这个 agent，越界请求正是靠这一层判出来的。

还有一条训练侧的路。指令层级 [21]、StruQ [2]、SecAlign [3] 都从训练下手，让模型自己学会把系统提示排在用户输入之前、把用户输入排在工具输出之前。这条路的好处是推理时不用多一次分类调用，代价是策略烙进参数，改一次边界要重训一次，而 Persona Guardrail 改的是清单这份文本。

基准这边也要说一句。AgentDojo [6]、InjecAgent [26]、AgentHarm [1]、Agent Security Bench [27] 这几个评测集量的都是攻击成功率或者任务效用。它们没有哪一个标注一条请求在不在 agent 的职责范围里。任务型对话那边倒是有超范围预测的长传统，CLINC150 [13] 就是干这个的，只是它按单轮意图标签判，跟 agent 的功能边界不是一回事。

1.4 这篇的做法

论文的取舍是把判据从「什么是坏的」翻到「什么是好的」，写成一份逐 agent 的允许意图清单，再让同一份清单同时管输入和输出。清单是可读的文本，agent 改了改清单的措辞就行，不必重训模型，所以一个分类器能服务多个 agent。

清单本身分三处攒出来。上线时用代码理解的 LLM 去读 agent 的实现与产品文档，推出它打算支持哪几类请求；上线后先开影子模式，只观察不拦，把规格里没覆盖到的正当交互补进清单；安全那一侧从提示注入、越狱、目标劫持、功能越界、工具误用这些已知手法起头，再靠反馈回路持续改。正因为在线上留了一段只观察不拦的时间，清单才知道自己漏掉了哪类正当请求。

这节要你记住的是，判据从黑名单翻成白名单，防的东西就跟着变了。

二、总体结构

2.1 威胁模型

安全栏目读一篇论文，第一件事是把攻击者的位置钉住。论文第 2.2 节分三段写，知道什么、能改什么、图什么。

知道什么。 攻击者能无限次提问，能看回全部回复，对 agent 的用途、公开接口和预期行为有一般了解。系统提示、中间推理、记忆、工具交互、编排逻辑、内部组件之间的通信，论文逐项写明拿不到。底层模型、基础设施和受信软件组件假定没被攻破。

能改什么。 只有自己送进去的输入。工具、检索到的文档、记忆、执行环境都在射程之外，论文据此把间接提示注入、工具投毒、记忆投毒三类明确划到评测范围之外。

图什么。 三件事。一是套出系统提示或内部策略，也就是指令操纵与提示提取。二是诱导 agent 输出违反政策的内容或执行动作，带来声誉、财务或法律损失。三是把 agent 推出它该管的事，比如逼一个订票助手给医疗建议或者抖出内部运营信息。第三条目标跟前面两条不同，论文把它定义成「让 agent 干出超出自己职责范围的事」，这个目标的成立要先有一个职责范围。

这三条合起来限定了结论的适用范围。论文的守卫看的是送进来的这一轮和处理完的这一轮，不看中间动作。所以一次被间接注入操纵的 agent，只要最终的回复越了界，输出守卫仍可能拦下它；可要是 agent 在中间悄悄调了一次不该调的接口，这道防线看不见。

2.2 一次请求的完整路径

一次交互要过几个环节。用户请求从公开接口进来，前端的应用层可以附加用户状态、会话信息这类上下文元数据。请求先到输入守卫，它拿这份规格判这一轮该不该接，判完要么拦，要么放给 agent。agent 内部可能走多步推理，调内部工具和外部接口，查企业知识库，最后产出回复。回复在交给用户之前过输出守卫，核的是同一份规格。

两道守卫都做阻塞式判断，都站在关键路径上，不能跟 agent 异步跑。论文第 2.3 节把这条写成设计前提，请求必须在 agent 执行前核完，回复必须在返回给用户前核完。这条前提后面所有工程取舍都从它推出来。

三、方法拆解

3.1 边界写成什么形状

论文比较了三种表示方式，只有白名单、只有黑名单、两者都写。

只有白名单，就是逐条列出这个 agent 允许处理的请求类别。安全上更保守，短板在枚举不完。论文说得很直接，正当请求没法穷举，白名单一旦有遗漏，误拦率就会抬高，用户体验先坏掉。

只有黑名单，就是逐条列出该拒的请求。这些条目分两来源，安全驱动的对应已知的攻击手法，功能驱动的对应越界请求。越界请求要不要进黑名单是可配的，有的应用就想当个专才，越界一律拒；有的愿意答一句或者把用户引回正题，Persona Guardrail 两种部署模型都支持。越界请求是不是该拒，论文把它交给每个 agent 自己定，框架不替它决定。

两种都写的时候，论文给了一条工程要求，两份清单要尽量不重叠。重叠处的条目给分类器的是互相矛盾的证据，判断的不确定性会升上去。所以框架会把两份清单里重叠的条目找出来，在构建和迭代阶段判给其中一条规则，让每种能力都落在唯一一条规则下面。

各自会出哪种错，图里画得很清楚。

3.2 边界从哪攒出来

三处来源，论文第 3.1.2 节分开写。

实现与产品规格。 上线初期，用一个面向代码的 LLM 去读 agent 的实现，看它有哪些工具、哪些接口、哪些检索组件、系统提示怎么写、外部资源是什么，推出它打算支持哪几类请求，产出一份初始的语义规格。这条路径把边界锚在实现与产品文档上，不靠人的印象。

生产流量分析。 上线之后先跑影子模式，守卫照看照判，但不真拦。规格里没覆盖好的正当交互补进白名单，边界就跟着用户行为和产品能力一起动。

安全侧的黑名单生成。 起手接的是已知的攻击手法，提示注入、间接提示注入、越狱、目标劫持、功能越界、工具误用都在里面；再加上落在 agent 范围外的越界类别。新攻击出来或者交互模式变了，这份黑名单通过反馈回路持续改。

3.3 两道守卫怎么落地

输入守卫的目标是判这一轮请求该不该交给 agent。输出守卫的目标是判产出的回复跟功能边界、组织政策、安全要求合不合。两份规格描述的东西略有差别。输入侧写的是允许处理的请求类别。输出侧写的是回复该有什么特征、可以做什么动作。输出侧的黑名单收四类，政策违规、不安全或有害内容、机密信息泄露，以及胡编出来的能力。

两边各试了四种架构。基于嵌入的检索把进来的话变成向量，跟白名单、黑名单里的代表样例比相似度，按最近邻加上标定过的相似度阈值定夺。LLM 分类把这一轮的话连同边界规格一起交给一个低时延的推理模型，直接判放行或拦截。检索加 LLM 的混合先看语义相似度，跟已有样例很像的直接用嵌入模型判，信心不够的转给 LLM 做语义推理。微调的专用分类器拿这个 agent 自己的样例去微调一个模型，直接预测类别。

四种架构对应两种相反的推理方式，一种去枚举什么该拒，一种去枚举什么该接。想清楚这一点，后面所有取舍都能自己推出来。枚举该拒的东西要为「所有坏情况」负责，漏一条就多一个缺口。枚举该接的东西要为「自己管什么」负责，写宽一点无非多接几类请求。语料上也是这样，坏话术没有上界，一个 agent 管什么有上界。

四条路的取舍由论文第 3.2 节与表 1 给全。嵌入法时延最低，但要标定阈值，还要给每个 agent 维护一个存代表样例的向量库，agent 一改维护成本就上去了，对语义上没见过的新请求也不稳。微调分类器在训练数据覆盖到的 agent 上表现好，换到没见过的 agent 或者边界一变就掉下来，得定期重训。混合法把快检索和 LLM 推理拼起来，准确率上去了，随之要同时维护向量索引和 LLM 推理服务，基础设施复杂度最高。

论文选了 LLM 分类，模型是 Qwen3-30B-A3B [7]。判据是四条的总体权衡。因为边界是用语义表述的而不是靠 agent 专属样例，同一个模型能搬到多个 agent 上，定制量很小。输入守卫和输出守卫用同一个模型，服务与维护也是同一套。一句话说，换 agent 时换的是交出去的那份规格，不是模型。

这套选择的价格写在表 1 里。混合法在分类性能与跨 agent 泛化上都标着高，LLM 方案也标着高，二者的差别落在时延与运维复杂度两列上，LLM 方案的时延是两档对勾，混合法也是两档，可运维复杂度只有 LLM 方案是低。

3.4 模型怎么选

选型的硬约束写在前面。护栏跑在每一个请求和每一个回复上，它的时间应该只占宿主应用端到端处理时间的一小部分，用户感觉不到才对。论文把这个预算表述成应用时延的固定比例，落到模型这一次调用上是一个低于 100 毫秒的 P90 目标。

论文先试了闭源模型，走 OpenAI 和 Anthropic 的接口。这些调用要发到外部托管的推理端点上，网络与服务的开销让它们没法稳定满足亚百毫秒的要求，于是转向能部署在自己机房里的开源权重模型，推理位置、缓存、硬件配置和别的服务侧优化都能自己控。

本地能部署的里面试了四个加上一个更大的备选。Qwen2.5-3B、Qwen2.5-7B、Qwen3-8B、Qwen3-30B-A3B，外加容量更大的 Qwen3-VL-30B。每个模型在同一批正当请求、越界请求、攻击请求上评，正当那一侧又分三个子集，分别是最高频的请求、随机抽样的请求和一个更大的正当集。

结果在表 2 里，正文只解读哪一列值得看。正当那三行的数越高越好，越界与对抗那两行越低越好，最后一行是时延。

好几个模型的越界和对抗两行比 Qwen3-30B-A3B 更漂亮。Qwen2.5-3B 的中位时延只有 81 毫秒，针对性的攻击请求只放行了 18%，可它在三份正当集上只放行 49% 到 67%，接近一半的正常用户被挡在门外。Qwen2.5-7B 与 Qwen3-8B 把正当那侧拉到 77% 到 93%，中位时延分别是 168 毫秒与 170 毫秒，已经超出预算。Qwen3-30B-A3B 在正当三档上放行 99% 到 100%，中位时延 95 毫秒。

Qwen3-VL-30B 是另一个方向的取舍。正当侧放行 96% 到 99%，越界与对抗两侧的误放率比 Qwen3-30B-A3B 更低，可中位时延 150 毫秒，超出目标。Qwen3-30B-A3B 走的是混合专家结构，总参数约 300 亿，每个 token 只激活约 30 亿，容量够做语义边界分类，推理开销又落在同步护栏能接受的范围里。

3.5 迭代清单

四档配置逐级加码，都跑在同一批 PAGE 划分上。

先是基线，只给分类器一段泛泛的 agent 描述，要它把每一轮标成正当、对抗或越界，不给清单也不给 persona。这一档隔出的是显式功能边界本身带来的增量。

然后是加允许意图，把 persona 的白名单交出去，也就是允许的用户意图与 agent 意图那份枚举清单，只有跟某条允许意图对上的轮次才放行。

再是迭代白名单，回去逐条看上一档误放和误拦的那些轮次，据此改意图的措辞，把过宽的收窄，把边界处的说法讲清楚。论文说明这是一次数据驱动的精修，只走一遍。

最后两档是只写黑名单和白名单加黑名单。论文把这两档写成探索性的，明说显式黑名单能不能超过迭代白名单是个实证问题，让测出来的数决定结论。

这节要你记住的是，唯一在动的参数是清单的措辞，模型不动。

四、结果

4.1 先看评测集长什么样

结论的可信度取决于这套题出得怎么样，所以先把 PAGE 拆开看。

它一共 2180 条带标签的消息，其中 2076 条是围绕四个 persona 合成的，另外 104 条从 AgentHarm [1] 投影过来。四条消息里几乎都带着三重标注，属于四个 persona 里的哪一个，落在用户这一轮还是 agent 这一轮，属于正当、对抗、越界、混淆这四类意图里的哪一类。标签的源头是同一份自然语言白名单，也就是说数据集和它要考的这份策略共用同一个事实来源。这是第一个同时覆盖用户轮与 agent 轮、覆盖四个生产域、并把正当、越界、攻击三类意图放在一起的护栏评测集。

生成过程由人带着走，是一条半自动流水线，四个来源拼起来。

人写的种子来自 AgentDojo [6]。每个套件的原始用户任务提供真实、地道的正当请求，套件里的注入任务目标提供有据可依的攻击意图。

LLM 合成用一个前沿的指令微调模型（Claude Opus 4.8，带推理）扩写正当集，同时生成越界内容，比如诗歌、代码、观点这些，充当 agent 那一轮的「幻觉」回复。生成用的模型家族与待测的分类器不是同一个，这样做是为了避开自评偏差。

确定性对抗模板用来造攻击轮。前沿模型拒绝撰写攻击载荷，论文就改用带参数的模板。模板换来两样东西，一是可精确复现，二是靠槽位填充拿到很宽的词汇变化，同时每条攻击仍落在 AgentDojo 或 AgentHarm 的某个既有模式上。槽位的取值为 9 个外泄地址、6 个外部站点、5 个对抗 IBAN、8 个第三方身份、7 个权威人设、7 个城市、5 个场所、6 个金额，再配上 8 个用户措辞前缀与 5 个 agent 措辞前缀。前沿模型拒绝写攻击载荷这件麻烦事，反倒逼出了一套可复现的模板语料。

跨 persona 投影把一条对 persona A 完全正当的请求投给 persona B，按定义它就成了功能边界违规。这一手造出 288 条又流利又像任务、却明确越界的硬样本，比泛泛的跑题文本难对付得多。

混淆轮是最后拼出来的，把一条越界或攻击的附加指令接到一条正经的正当请求上，比如一个正常的订票请求后面跟一句外泄指令，用来看同一轮里正当意图与恶意意图同时出现时护栏怎么办。

越界一侧有三族，跨 persona 违规 288 条，泛泛的跑题提问，以及 agent 那一轮的越界幻觉。正当一侧是 168 条人写的 AgentDojo 任务加上 836 条 LLM 变体。

消息长度也跟着类别变。正文提到攻击指令最短，中位 14 个词。正当的多步行程和跨 persona 越界请求最长可到 121 个词。混淆轮最长，中位 37 个词、最多 152 个词，因为它要把一段正当载体和一段附加指令接在一起。

指标的定义也要先钉住。论文把「拦」当正类，护栏该拦的是越界内容，该放的是范围内内容。四类决定是正确放行、正确拦截、误放与误拦，两个派生率分别写成式 (2) 与式 (3)。

(2)FAR=FNFN+TP
(3)FBR=FPFP+TN

TP 是该拦且拦下的轮次，TN 是该放且放行的轮次，FN 是该拦却放行的轮次，FP 是该放却拦下的轮次。误放率 FAR 在分母里算的是所有该拦的轮次，所以它衡量的是攻击与越界请求溜过去的比例。误拦率 FBR 的分母是所有正当轮次，衡量的是正常用户被误伤的比例。后面所有的数都按这两条式子读，两个率的分母不同，不能互相比较大小。

这节要你记住的是，这份评测集同时考输入和输出两道守卫。

4.7 生产里的时延

论文第 5.2 节给了这套负载的结构。判别只输出一个 token，生成的部分可以忽略，时延由提示预填充主导。所有请求共享一段静态前置说明，它占了工作负载里约 93% 的输入 token，把它的缓存复用起来，每次预填充只剩下那段可变的部分。超出上下文上限的那 2.1% 请求在 GPU 排活之前就退回去，不会拖累剩下的流量。

工作负载的形态定好之后，模型侧靠混合专家结构省算力，800 亿参数级的容量、30 亿参数级的开销，权重压到 FP8。服务侧把推理拆成 CPU 前端和 GPU 工作池，前端做前缀缓存感知的路由。

4.8 换个角度攻

论文附录 A.2 还试了一组知道内情的攻击者。攻击模型换了好几个，知识水平分三档，只知道架构、知道确切的模型与提示结构、拿到逐字的允许意图清单。第一轮没绕过去的话，允许它们接着多轮尝试。

结论有两条。拿到逐字意图清单给攻击者的帮助最大，而这种情况在现实中风险最低。知道底层模型是哪个，在已经知道有这道护栏之后没有额外好处。就算是最坏那一档，也就是攻击者拿到了完整意图清单，能力最强的那个模型生成的攻击也有 85% 以上被挡下，其余情形下的检测率都在 90% 以上。

这组实验自身有一个论文承认的干扰项。用来当攻击者的闭源模型被安全训练约束住了，经常拒绝生成攻击提示，首轮攻击的拒绝率落在 17% 到 71% 之间。

4.9 上线之后的数

论文第 5.8 节写了生产上的表现。Persona Guardrail 在时延预算内还有余量，跨多个 agent 的误拦率低于 1%，误放率低于 2%。

这两个数跟前面 PAGE 上的 3.6% 与 4.7% 不是一回事，读的时候要分开。PAGE 的数来自 2000 条带标签的轮次，标签由构造时的人工与模板、以及一个更强的评委模型给出；生产这两个数来自线上流量，没有公开分母，也没有说明标签怎么来。两套数的取值条件不同，不能互相印证。

这节要你记住的是，越界检测率从 57.3 到 93.5，误拦率一直没动。

五、局限

论文自己承认的局限集中在两处，一是第 4 节开头对评测范围的界定，二是第 5.8 节末尾的 Scope and Limitations 段。

评测范围只覆盖直接攻击。 论文明说 Persona Guardrail 是在既定威胁模型下、针对直接恶意用户与越界交互评测的纵深防御措施，报告的结果不构成对间接提示注入、组件被攻破、未授权的中间工具调用、多轮攻击以及该模型之外其他威胁的完整保护。部署决策与可接受错误率仍由具体应用决定。

结果不代表端到端防住了间接注入。 论文第 4 节写明只从 AgentDojo 取了域定义，没有跑它的环境、工具与间接注入攻击套件，因此结果不衡量对间接注入或未授权中间动作的端到端防护。

对角线之外的攻击形式。 第 2.2 节把间接提示注入、工具投毒、记忆投毒列在评测的威胁模型之外，并补了一句，本方案仍可能拦下这类攻击造成的违反政策的最终回复，但评测里的护栏不检查中间动作。

边界本身的局限。 第 3.1 节承认显式枚举两个集合不可行，只能用语义描述近似这条边界，3.2 节列出的三处来源也只能把近似做得更贴，做不到穷尽。

攻击者实验的干扰项。 附录 A.2 承认用作攻击者的闭源模型受安全训练约束，首轮攻击的拒绝率在 17% 到 71% 之间。

下面三条是编者在读原文时补的，论文未将其列为局限。

误拦率与误放率的代价不对称，论文没有按业务定价。 生产上误拦一个正当用户和误放一次越界回复，代价差得很远，表 6 里 3.6% 与 4.7% 这两个数被并列放在一起，没有任何一处给出二者的换算口径。论文未将其列为局限。

PAGE 的四个业务域都来自 AgentDojo 的定义，且语料主要是合成与模板。 2180 条里有 2076 条是围绕四个 persona 合成的，其中 972 条出自 LLM、582 条出自确定性模板、288 条来自跨 persona 投影，只有 234 条接的是 AgentDojo 的原始任务。这四个域是不是覆盖了生产里护栏会遇到的请求分布，论文未将其列为局限。

最终误放率是两段的乘积，论文没有把两段拆开报。 一条攻击要成功，得先过输入守卫，再过输出守卫。论文报的是这一轮消息的合并误放率，两道守卫各自漏了多少没有单列，所以「哪一道更弱、该往哪一道加预算」这个问题在现有表里答不出来。论文未将其列为局限。

这节要你记住的是，论文只承诺单轮直连这一种情形，其余都写在门外。

六、我的评价

先说做得对的地方。

把白名单当主判据，这个选择是对的。 攻击空间是开放的，功能空间是封闭的，一个订票 agent 该管的事有边界，一个订票 agent 可能被用来干的事没边界。表 7 里只写黑名单那一档把攻击挡到 87.2% 却在越界请求上只有 14.5%，这组对照把「边界」和「黑名单」是两件事说得很干净。

迭代那一步只动措辞，不动模型。 这个设计让审核、回滚和版本管理都变成读文本的事。附录表 12 在没参与过迭代的分片上把 v3 测到 96.7%，说明涨的那部分不是照着评测集调出来的。

误拦率平线这一条最有信息量。 安全和效用通常是要打架的，这里三档配置的误拦率停在 3.7、3.7、3.6。它给出的经验是白名单的粒度可以往上提，代价落在措辞的维护量上，不落在用户的正常使用上。

存疑的地方有三处。

95.9% 这个数是在 2000 条上量出来的，而且只有 2180 条的总盘子。 表 9 里 47 条误放、36 条误拦，加起来 83 条决定撑起这套结论。这个体量对定位机制方向够用，要支撑「生产就绪」这个形容还偏薄，尤其是跨四个业务域的样本量差异和每个域内的类别分布论文没有逐域列出。

两段守卫的账没算清。 前面第三条编者补充已经写了，这里补一句后果。既然验不出来是哪一段在漏，调护栏时就没有方向，只能整体换模型或者整体改清单。

跨 persona 投影这一招好用，也把自己围住了。 288 条最难的越界样本是这样造出来的，一个对 persona A 完全正当的请求，对 persona B 就是越界。这种做法能造出流利、像任务、又明确越界的样本，质量很高。可它的难度分布是照着「四个人设彼此不可混」这个设定长的，真实的业务域边界比这模糊，一个客服助手和一个订单助手之间的界线不总是这么整齐。

它想走去的地方写在结论里，两条。一条是把单轮的边界判断扩到整段对话，用前面的轮次当上下文，抓那些跨轮次才显形的越界；另一条是把判断下沉到模型执行层，让中间的工具调用在执行前也能对着功能边界核一次。两条合起来，是从轮级判断走到对话级和工具级。

这两条我都觉得方向对，也都不好做。对话级那一条先把多轮攻击拉进评测范围，也就得面对标注问题，一段对话里哪一轮开始算越界，靠什么定；工具级那一条要动执行路径，代价从「多一次分类调用」变成「插进执行路径」，延迟预算和失败处理都得重来。

七、可以接着做什么

把两道守卫的漏检分开量。 现在的表只报合并结果。做法是在评测里造一个 oracle 式的前置条件，把输入守卫换成真值放行或者真值拦截，再跑输出守卫，两段各自的漏检率就出来了。这件事不需要新数据，用 PAGE 现有的标签就能做。

给误拦和误放定一个业务价格。 现在的数都是率，不是钱。拦掉一个正要下单的用户和放过一句越界答复，代价差很多。把每个业务域的这两笔代价估出来，再把率换成期望损失，五档配置的排序可能就变了，尤其是白加黑那一档，98.0 的召回率配上 8.2 的误拦率，在价格不对称的场景下未必输。

拿跨 persona 投影之外的越界样本再测一遍。 现在的硬越界样本是 A 的正当请求投给 B 造出来的。可以换一种造法，找两个真实业务域，从真实工单里挑那些两边都会被答、但只有一个该答的问题，看看 93.5% 这个数会不会掉。

把清单迭代的成本也算进账。 论文说迭代只改措辞，可措辞是人写的，每轮迭代要读错判、改条目、再审、再走影子与灰度。这套人力的量级论文没给，而这恰恰是决定它能不能铺到几百个 agent 上的那个量。

给边界加一个可观测的判据。 现在判断清单改好了没有，靠的是金标集、对抗集、生产集三池的阈值。可以试着定义一组不依赖标注的代理指标，比如允许意图条目之间的语义重叠度、黑名单与白名单的交集大小，看看它们跟误拦率有没有稳定关系。

以上五条都是读到这里时的即时联想，没有做过实验，也没有查证过有没有人已经做过了，只当线索看。
