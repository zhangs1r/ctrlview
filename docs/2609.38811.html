DCM-SAM 把 SAM 拆成两套缺陷专家塞进设备旁的 NPU

Md Mushfiqur Rahaman, Md Mahedi Hasan, Imtiaz Ahmed, Srinjoy Das
arXiv:2609.38811 · 2026-10-01 · 精读约 55 分钟
增材制造X 射线 CT缺陷分割参数高效微调NPU 部署

它想干什么

一台激光粉末床熔合的金属打印机刚打完一个件。激光功率或者熔池行为抖一下，件里就留下气孔、未熔合的空洞，或者混进去的夹杂物。这些东西埋在表面以下，决定这个件的疲劳寿命，也决定它能不能拿到合格证。所以拿 X 射线 CT 把件扫一遍，得到一卷切片，然后要把每张切片里属于缺陷的像素圈出来。

这一步现在最费人。阈值法换一套数据就得重新调参，监督分割网络则把训练集的统计带在身上。而这篇要处理的任务有三个绕不开的性质。缺陷小，把切片升采样到模型的 1024² 输入之后，要紧的缺陷仍然只有几个像素宽。标注少，带标注的真实体积非常稀缺。迁移难，一个在某种合金某台扫描仪上训好的模型，经常被要求去处理另一种合金另一台扫描仪的数据。

还有第四个性质不来自数据，来自模型被允许跑在哪里。上云这条路被数据合规挡掉了，增材检测的数据常是私有或者受出口管制的。给每台设备各配一台工作站，机队铺开之后成本和功耗都不划算。所以推理的落点是一块贴在设备旁的嵌入式加速器。

两件事于是被同时压到同一块小芯片上，一件是基础模型级别的骨干，一件是 1024² 的输入分辨率。这篇有一半的篇幅在这个夹缝里。1024² 是硬底线，同样的权重拿到 512² 上评估，孔隙 IoU 从 36.1 掉到 19.7，在 512² 上重新训练也只能补回到 30.8。

方法本身可以一句话说清。一个冻结的 SAM ViT-B 骨干不动，在上面按缺陷类别各挂一套轻量适配器和一个从零训起的掩码解码器，每个适配器里带一组不同尺度的卷积专家。两类各训一遍，两套头之间不共享任何可训练参数，推理时也不需要给提示。每个头只训 4.13M 个参数，占 ViT-B 的 4.4%。训练数据是几百张合成的切片，合成器是一个无配对的图像转换网络（CycleGAN），训练全程一张真实图像都没见过，在真实的 NIST 扫描上孔隙 IoU 达到 64.2。

部署那半段是这篇信息量最大的地方。作者把 SAM 的三个骨干（89.7M、308.3M、637M 参数）都编到高通的 Hexagon v73 NPU 上，在 1024² 下只有 ViT-B 跑得起来，另外两个编译通过却分配不下内存。限制它们的是激活内存，权重不是瓶颈，所以量化权重在这里帮不上忙。最后他们把注意力改写成一次缩放点积调用，四个计算图才全部落到 NPU 上，没有算子回落到 CPU，掩码和 FP32 参考差 96 个和 0 个像素，总共 1,048,576 个。

这节要你记住的是，缺陷只有几个像素，而模型必须整块跑在设备旁的 NPU 上。

一、问题背景

1.1 这一步在产线里的位置

📌 控制视角　增材检测在产线上的位置很清楚。它在打印完成之后（中间可能夹着去粉、热处理、从基板上切下来这几步），在成品判定之前。上游是粉末床熔合的工艺参数，下游是合格证和疲劳寿命评估。这一环的输入是一卷 XCT 重建切片，输出是每张切片上哪些像素属于缺陷。论文没有给节拍和良率的数字，它给的是单张图的 NPU 推理耗时（附录 F 的表 7），而编码器那两行还是在 512² 下测的。所以「这套东西跟不跟得上产线节拍」这个问题，论文没有回答。能读出来的是量级，孔隙编码器 1980.8 ms，夹杂物编码器 8134.3 ms，两个解码器各 3.8 ms，都不含图像加载。节拍在控制里就是采样周期，采样周期定不下来，控制器做得再好也没有落点。良率这个指标有稳态误差和方差两面，这里的方差一面完全没被触碰，五个 NIST 试样里只有一个用了专门为它标定的后处理。

📌 控制视角　改造量集中在软件栈上，不在机械上。需要一台带 Hexagon NPU 的计算模块，需要走一遍 Qualcomm AI Hub 加 QNN 序列化器的编译流程，还需要在模型代码里动三处（3.5 节展开）。PLC 和 CT 重建那一层怎么接，论文没有描述。停机成本和安全兜底，论文同样没写。自动检测绕不开这一块，误检的代价最终落在人工复核和废件判定上。论文里唯一沾边的是精确率和召回率的分布（附录 H 的表 8）。孔隙头在 NIST 的 test2 和 test4 上召回分别是 100.0% 和 99.9%，精确率只有 74.2% 和 80.6%，行为是倾向多报。多报对安全一侧有利，对产线吞吐不利。

1.2 缺陷为什么难分

困难的第一层是像素尺度。论文附录 A 给了数。test1 那一百张切片在原生 768×768 下，孔隙连通域的中位面积是 14 个像素，95 分位 58 个。夹杂物的中位面积 22 个像素，95 分位 71 个，数量比孔隙少 2.3 倍（625 个对 1429 个）。升采样到 1024² 之后整体尺度变宽，缺陷本身还是几个像素的事。

第二层是类内尺度差。test1 的孔隙连通域，单张切片内最大与最小面积之比的中位数是 40。一个感受野固定的检测头覆盖不了这种跨度，得有一个能拆成阶梯的机制。

第三层是两类缺陷的分布不对称。孔隙常见，夹杂物稀少，一张切片里夹杂物占不到 1% 的面积。这个不对称会咬人的地方在共享参数。两类共用一个低秩子空间，孔隙样本会在梯度里把夹杂物的更新压过去，夹杂物的学习就变得又吵又容易过拟合。

1.3 前人走过的路

从零训一个小网络这条路被数据量堵死了。UNet++ 用嵌套的 U 形结构加密集跳连做多尺度分割，结构本身够用。它缺的是基础模型的分割先验，几百张切片训不出名堂，真实 NIST 扫描上孔隙 IoU 只有 13.4（论文表 2）。所以这一族工作都转向 Adapt 一个分割基础模型。

SAM 本身是这条路的地基。它把一个 ViT 图像编码器、一个提示编码器和一个轻量掩码解码器串起来，用户给点、给框或者给粗略掩码作为提示，解码器据此吐出目标掩码。它在自然图像上见过的东西比任何工业数据集都多，问题在于工业切片上动辄成百上千个缺陷，一个一个给提示不现实。

完全微调 SAM 也走不通。ViT-B 的编码器 89.7M 参数，ViT-H 是 637M，拿几百张切片去全量微调，过拟合是必然的事。常规做法是冻住编码器，只学小的注入模块。

LoRA 是其中一种。它冻结原来的投影矩阵 W0，只训练两个低秩矩阵 A 和 B，用它们的乘积去补权重更新。它的短板在「线性」两个字上。这个更新对每个 token 独立作用，而缺陷只跨几个像素，局部结构它看不到。

Conv-LoRA 补的就是这块短板。它在低秩瓶颈里把特征重排回 patch 网格，插进多尺度卷积专家，再由稀疏门控路由到其中一个。Tabassum 和 Ziabari 把这套东西用到增材 XCT 上，监督信号来自 CycleGAN 合成的图像（参考文献 29）。XCT-SAM 在它前面又加了一个合金显微组织的中间适应阶段（参考文献 8）。这两条路都给每个类别单独训一个模型。

没有一篇问过跑起来要多少钱。它们把类别隔离做对了，代价是每个类别一份模型，而部署预算没有人算。

另一条路是让模型变小。PTQ4SAM 这类训练后量化工作报告的是解析加速比，不是在设备上实测出来的（参考文献 16、15、33、19）。蒸馏出更小的骨干（参考文献 35、36）则放弃了自适应本来要换来的那份容量。医学域那两条路是 MedSAM 和 SAM-Med2D，做法都是在医学图像上接着训 SAM（参考文献 17、4）。它们的统计和金属 XCT 缺陷对不上，后面的表 2 里可以对照。

1.4 这篇选的位置

论文的判断是两件事可以同时要，一件是让两个缺陷类别互不干涉，一件是让两个头共享同一套冻结骨干。做法是一套冻结骨干挂两套互不共享参数的专家库和解码器，各训各的。孔隙那套用 2 个专家，夹杂物那套用 8 个。这个数目是扫出来的，扫出来的结果自己带问题（4.1 节）。

还有一层动机来自部署。共享骨干省下的是训练时的存储，设备上并不省（附录 G 明说），而每类的编码器要跑一遍。这条账在结果一节里是重头。

这节要你记住的是，像素尺度和类别不均衡，决定了两套头必须分开训。

二、总体结构

整套流程可以按阶段拆开看。合成监督绕开的是标注问题。冻结骨干加每类专家绕开的是容量问题，注意力改写绕开的是内存问题。三段各占一章，输入输出并不一样。

📌 控制视角　从集成角度看，这篇的架构选择有一个副产品。两个头完全不共享参数这件事，让编码器必须跑两遍。如果哪天要把检测扩到第三个缺陷类别，代价是多一张编码器图加多一份冻结权重，不是多一个输出通道。这在小芯片上是很硬的约束。反过来看，类别隔离带来的是可替换性。换合金换扫描仪要重标的是标定和后处理，不是整套网络结构。论文里那个随试样变化的后处理（阈值、形态学开运算尺寸、最小 blob 尺寸、某一个试样还要强度反转）就是这个重标工作的实际形态，它比重新训练便宜得多。

这节要你记住的是，两个头共用一套冻结骨干，但部署时各自跑一遍编码器。

三、方法拆解

3.1 不要提示的 SAM

SAM 由三部分组成。ViT 图像编码器 fenc 负责看图，提示编码器 fprm 把提示编成嵌入，掩码解码器 fdec 很轻，负责把前两者合成掩码。给一张图像 x∈ℝ3×S×S，输入边长 S=1024，编码器把它切成 N=(S/16)2=4096 个 patch token，过 L 个 transformer 块，其中四个做全局注意力，其余在 14×14 的窗口内做注意力，输出嵌入 E∈ℝ256×S/16×S/16。编码器装了 96% 的参数（ViT-B 口径，ViT-H 上是 99%），每张图只过一次。

工业切片上有成百上千个缺陷，逐个给提示不现实。所以论文保留 fprm 但不喂任何提示，让它只输出自己学到的无提示嵌入。缺陷定位全靠学到的图像嵌入和一个 4.1M 参数、从零训起的掩码解码器。

3.2 Conv-LoRA 加多尺度专家混合

LoRA 的更新写成 h=W0x+αrBAx，秩 r 很小，两个低秩矩阵的乘积承担权重的补偿量。这个形式对 token 独立作用。Conv-LoRA 在瓶颈里加进空间结构，把 Z=Ax 重排成 S16×S16 的 patch 网格，从 M 个卷积专家里选一个，把它的输出加到 Z 上再投影回去。

(1)h=W0x+αrB[Z+ℰi*(Z)],ℰi(Z)=𝒟i(σ(Conv3×3(𝒰i(Z))))

符号逐个拆。(1) 里 Z=Ax 是降到低秩的中间量。𝒰i 按双三次插值把特征图放大 i 倍，𝒟i 再采样回原尺寸，σ 是 GELU。i* 是门控选中的那个专家的编号，ℰi*(Z) 是它的输出。要在放大了 i 倍的特征图上做 3×3 卷积，等效覆盖的区域就比原来小 i 倍。M 个专家于是给出一串阶梯式的感受野，阶梯有多深由类别的专家数决定。

多尺度在类内也是必要的，因为同一张切片里的孔隙面积有 40 倍的跨度（1.2 节）。这一点是这篇和原版 Conv-LoRA 的差别所在，原版用一套专家服务所有类别，这里按类别各给一套。

门控要防止退化到一个专家包办，所以配了一个负载均衡损失 ℒmoe=CV2(importance)+CV2(load)，CV 是变异系数，也就是标准差除以均值。两项都小表示各个专家的被选中频率和承担的权重都均匀。这个损失函数来自 Shazeer 那篇稀疏门控专家层的经典工作（参考文献 27）。

这里埋了整篇最大的一个分岔。GPU 上每个输入只有一个专家真正执行，被丢掉的专家不花算力。静态的 NPU 图上没有这个条件，稀疏路由会摊成稠密计算。论文用 r=2、α=8，每个编码器块插一个适配器。

3.3 每个类别一套头，梯度隔离

两个类别 c∈{pore,inclusion} 各自有一套适配器 θclora 和一个解码器 θcdec，都长在同一份冻结骨干 θsam 上。两个头并行优化但彼此独立，各有自己的优化器、学习率调度和梯度裁剪。同一张输入图过两个头，得到的嵌入并不一样，余弦相似度 0.87。

每个头的损失是 ℒc=ℒdice+ℒfocal+0.1ℒmoe。夹杂物阳性的图被过采样 5 倍，夹杂物的损失按图平均而不是按整批展平平均，这样一张标注密集的切片不会独占一步更新。

被优化的量拆成三件。初值来自预训练的 SAM 权重（骨干冻结不动）加上随机初始化的适配器和解码器。残差由两部分驱动，一个是 Dice 加 focal 的分割损失，一个是 0.1 倍的门控负载均衡项。兜底靠三样东西，冻结的骨干本身、两个头之间没有任何可训练参数的通道、以及裁剪到 1.0 的梯度。

参数量账本值得摆出来（附录 D 的表 5，ViT-B 口径）。卷积 LoRA 的 A、B 是 73,728 个参数，占 0.079%。卷积专家 3,648 个，占 0.004%。门控 Wg、Wn 是 384 个，不到 0.001%。掩码解码器 4.06M，占 4.33%。加起来每个头 4.13M，占 4.41%，两个头 8.27M。适配器只占 0.08%，而可训练参数里有 98% 在解码器上。另外，适配器折不回冻结权重里去，因为它带着 GELU、卷积和一个依赖输入的门控，推理时必须照常执行（附录 D）。

3.4 部署的三个卡点

第一个卡点是内存，这是全篇最值得记住的一段算术。每个全局注意力块要形成一张每个 token 对每个 token 的表，而 token 数 N=(S/16)2 随输入边长的平方长。H 个头的注意力激活于是按 HN2 长，也就是输入边长的四次方。代入 1024²，N=4096，N2=16,777,216，ViT-B 的 H=12，FP16 下就是 12×4096×4096×2≈384 MiB。ViT-L 和 ViT-H 的 16 个头算下来是 512 MiB。输入边长减半，这张表小 16 倍，精度减半只让它小 2 倍。这就是为什么杠杆是分辨率而不是精度。论文那段 512² 的实验用的就是按 512² 重新对准过尺寸的模型（附录 F）。

第二个卡点是路由。门控靠对输入取 argmax 来选专家，静态图表达不了这个动作。导出前先把 M 个专家全部算一遍，再用 one-hot 掩码选一个出来。论文说这个替换在八张切片上只改了 8.4M 个掩码像素里的 13 个。

第三个卡点是注意力怎么写。SAM 的参考实现把注意力矩阵拆成好几个全尺寸的中间量，静态图必须同时把它们留在内存里。改写成一次缩放点积调用再加一个加法偏置，两者是同一种计算，编码器输出差 1.2×10−5，但需要同时活着的张量少得多。为什么改完就能放进去，4.3 节接着讲。

还有一件事在 §2 里交代了。设备标称支持 INT8，论文部署的是 FP16，全文没报任何 INT8 精度数字。原因就在上面这一条和附录 F，注意力里的乘积取两个激活操作数，后端在 8 位和 16 位下都没有验证过的整数内核。

3.5 换输入尺寸要动三处

把 SAM 对准到 1024 以外的边长 S&#x27;，要改三处（附录 F）。放开 patch 嵌入里的尺寸检查，把学到的位置嵌入从 64×64 网格双三次重采样到 S&#x27;/16，更新提示编码器持有的 patch 网格尺寸。第三处不做，解码器会收到形状不对的张量。相对位置表不用动，它在每次调用时按 query 和 key 的范围插值。

工具链这一层还有一串硬碰硬的改造（附录 F）。精确 GELU 会吐出 erf 算子，转换器对它没有布局推断，只能换成 tanh 近似，输出最大偏差 1.0×10−3（ViT-B）和 3.5×10−3（ViT-L）。部分量化的归一化层数据类型混杂，转换器直接拒绝，于是量化只留给带权重的算子。归一化、softmax 和逐元素算子留在浮点里，这些算子几乎不占参数。静态门控试了三次才成，ScatterElements 的 opset 转换器不收，OneHot 没有验证过的数据类型组合，能用的形式是 argmax 与 arange(M) 的相等比较。序列化解码器时不带编码器权重，产物从 358 MB 降到 15.7 MB。

这节要你记住的是，稀疏门控在静态图上摊成稠密计算，这是上机的第一笔账。

还有一处口径要读清楚。夹杂物在多数切片里根本不出现，IoU 按图平均、把没有缺陷也没有预测的图记 1，这个约定会把数字抬高。选定的 (2, 8) 模型在 test1、test2、test6 上的夹杂物均值是 26.1、89.0、31.3，平均 48.9。只在含缺陷的图上算是 25.3、0.0、10.2，平均 11.8。test2 那 89 张空白切片上一张都没报错，另外 11 张上一律没预测出来。孔隙那两套口径给的是 36.1 和 32.7。论文写明看分割质量要读只含缺陷图的那一套，而表 1 和跟 XCT-SAM 的对比报的是按图平均的那一套。

4.3 骨干是在设备上选出来的

三个骨干都编得过，只有 ViT-B 跑得起来。同样的 ViT-H 权重放到 512² 能跑，1024² 就不行。ViT-L 换上 INT8 权重仍然分配不下。原因是激活不是权重。1024² 下一个全局注意力层要物化 16×4096×4096 的张量，FP16 下 512 MB，后端没有融合内核能绕开它。权重那一侧，三个骨干分别是 171、588、1215 MB，q、k、v 和 MLP 的激活只有 18 到 40 MB。片上那块 8 MB 的向量暂存被每个骨干的注意力矩阵超出 48 到 64 倍，于是都被分块绕过去了，这一条不区分骨干（附录 E）。

量化动不了这条天花板。注意力里的 QK⊤ 和 AV 两个乘积都取两个激活操作数，后端在 8 位和 16 位下都没有验证过的整数内核。分辨率能动。512² 下 ViT-L 和 ViT-H 都能跑起来，单张 4.14 s 和 6.21 s。

4.4 完整模型上机，三笔账

把 (2, 8) 的 ViT-B 装到设备上，四个计算图，每个头一个编码器加一个解码器，因为适配器长在编码器里面。按训练原样导出，适配过的 ViT-B 编码器在 1024² 下要 4.07 GB，而序列化器给的上限是 3.76 GB。原版编码器用同一种 eager 注意力是跑得通的，只有两者叠在一起才超。

五、局限

重复次数不够

论文承认每个配置只训一次，而这个骨干上已经出现过 4.9 个点的种子波动，所以大约 3 个点以内的差别分不出来。选 (2, 8) 是在合成基准上做的，而在 NIST 上它是九组里最低的，虽然只低 2.1 个点，论文也说这不构成真实差别。

基线比较跨了协议和骨干

表 2 的基线数字取自 XCT-SAM，不是在本文协议下重跑的，而且它们是 ViT-H，本文是 ViT-B。论文写明在协议一致的重评之前，这张表只是指示性的。

部署是 FP16，没有整数量化精度

INT8 在算子层面就被挡住了（§3.3），论文没有在任何地方报整数量化后的精度。设备标称支持 INT8，这一点没有被兑现。

上机数值一致性只验了一张切片

设备上的数值等价只在一张真实 XCT 切片上、每个头一次、1024² 下验过，加上原版骨干的编码器输出。逐算子 profiler 在这台设备上挂不到 1024² 的编码器图，所以部署分辨率下的编码器时延没有测量，表 7 报的是 512²。

降分辨率的证据只有一次运行

「分辨率不能换速度」这条结论的支撑是一次 ViT-H 运行、一个种子（附录 A）。这一侧的实验从未在 NIST 上评估过，也从未带着适配器上过设备。

共享骨干省下的存储不在设备上

适配器在编码器里面，编码器每个头跑一次，每个编码器二进制各自带一份冻结权重。共享骨干省的是训练时的存储，设备上一分钱都没省。

编者补充，论文未将其列为局限

下面每一条都是我在读的时候记下来的，论文里没有作为局限提出。

没有产线数据。 节拍、良率、停机时间、现场误检的后果，一样都没有。论文里的「在机」指的是模型跑在设备旁的 NPU 上，不是跑在某条真实产线上。XCT 扫描本身要多久、一个件要扫多少张切片、检测这一步在整条线里占多长，论文都没有交代。论文未将其列为局限。

训练用的全是合成切片，真实数据只做评估，而且只有孔隙有标注。 论文把这一点写成了贡献（数据高效），从产线角度看它是双刃的。夹杂物那一整套数字，包括 48.9 和 11.8，全部来自合成折。真实数据上唯一有标注可评分的是孔隙，64.2 这个数字也只有孔隙有。论文未将其列为局限。

验证集和报告集重叠。 早停和选择最好 checkpoint 用的是合成的 test6，而 test6 是五个报告折里的一个。XCT-SAM 用的是 test3，那一折不在这个数据集里。所以五折均值里含了选择折，选择偏置没有隔离。论文未将其列为局限。

后处理是在测试折上标定的。 阈值、形态学开运算尺寸、最小 blob 尺寸，还有一个 NIST 试样的强度反转加有效区域掩码，都是按折标定一次然后对所有模型统一施加。统一的说法站得住，标定发生在测试折上这件事没有出现在局限清单里。论文未将其列为局限。

一个缺陷实例级的指标都没有。 全文报的是 IoU、Dice 和 Tol-F1，都是按图像素或按容差聚合的量。产线上要回答的问题是「这一个件里有没有漏掉一个关键缺陷」，那需要按缺陷实例统计检出率，还要按缺陷尺寸分层看召回。按像素平均会被大缺陷和背景像素稀释，一个几十像素的关键缺陷漏掉了，IoU 上几乎看不出来。论文附表 8 里 NIST test2 和 test4 的召回接近满分而精确率偏低，说明误报是主要误差模式，漏检这一侧没有分开量过。论文未将其列为局限。

设备侧的功耗和散热没有任何数字。 论文给了四个图的峰值内存和加载时间，没有给功耗、发热或者持续运行下的时钟行为。对一个要长期挂在产线边的设备，这几项往往决定能不能用。论文未将其列为局限。

MoE 的收益有一部分和数据顺序分不开。 论文用数据顺序解释了单头最优拼不起来，又用它解释了种子混淆，两处加起来占了正文和附录的一大块，而重复实验被留在了下一步。也就是说 (8, 8) 那个 25.8 里，有多少是专家太多，有多少是那一轮的数据顺序不好，现在读不出来。论文未将其列为局限。

这节要你记住的是，论文自己列的坑集中在评估协议，产线那一层整个是空的。

六、我的评价

做得对的地方。

最值钱的一条是把「能不能上机」当成第一类结果来报。多数域适应论文到精度就收尾了，这篇把分配失败的内存报告、编译器的原始报错数字、四种注意力与适配器组合的对照表都摆了出来。3.76 GB 这个上限是序列化器给的、不是硬件的，论文主动标注了这一点。这种交代比一个漂亮的加速比有用得多，因为它可以被别人拿去复算。

第二个是对的取舍。类别不均衡压垮一个低秩子空间，这件事是可以预期的，直接用参数隔离去解，代价算得清楚，两个头 8.27M 参数、编码器跑两遍。论文没有回避这个代价，反而在附录 G 里把它写成了共享骨干省不了设备存储。

第三个是附录 B 那段自曝。种子混淆引入了 4.9 个点的波动，不改的话会把好几个结论反过来。很少有论文愿意把这种事情写进附录，而它恰好是这一篇最有方法学价值的一段。

第四个是评估口径交代得干净。夹杂物 48.9 和 11.8 两个数同时给出，并且指明哪个该读。这一条如果藏起来，整篇文章的说服力会掉一大截。

存疑的地方。

第一个是 (8, 8) 崩到 25.8 这件事。论文给的解释是数据顺序，这个解释如果成立，那张表测的东西就模糊了。读者分不清 25.8 是专家太多还是这一轮的数据顺序不好。论文用同一种机制解释了「单头最优拼不起来」，又用它解释了种子混淆，没有任何一次重复实验把数据顺序和专家数分开。附录 G 把重复种子列为下一步，这个安排是对的，只是现在还没有。

第二个是精度的落点。ViT-H 1024² 的孔隙 37.3 和夹杂 52.5 都高于部署模型的 36.1 和 48.9（按图平均）。论文正文的表述是「在 XCT-SAM 报告的基线上全面超过」，这句话成立，而它容易读成「ViT-B 比 ViT-H 强」。表 3 给出的真相是 ViT-B 略低于同配置的大骨干，差的那几个点换来了上机资格。我在正文里把这一条摆开了，因为这是全篇最容易被误读的地方。

第三个是 (2, 8) 被选中的理由有点薄。它在 NIST 上是九组里最低的那个 64.2，论文说 2.1 个点不构成真实差别。这和「3 个点以内分不出来」是一致的态度，代价是 NIST 那一列整列都读不出配置偏好，选择依据全落在合成那一列上。而合成那一列又被数据顺序问题罩着。

第四个是真实数据上的语气要收一收。「训练全程没看过真实图像」是事实，而 64.2 里有 test6 的 85.4 撑着，那个试样用了专门为它标定的强度反转和有效区域掩码，去掉它剩 58.8。为单个试样定制的后处理越多，这个数字的可迁移性就越值得怀疑。论文自己写明了 test6 的特殊处理，这一步做得对，读数字的人该同时读那一行。

第五个是那句上机一致性的引用方式。论文自己在附录 G 里写明了样本量，而正文里「掩码和 FP32 参考在 1,048,576 个像素里只差 96 个」这句话被反复引用，一次都没带上限定。一个数字被复述的频次和它的证据强度不匹配，读者很容易把它当成普适结论。

它想走去哪。附录 G 列了四条下一步，重复种子、协议一致的基线重评、内部共享适配器的消融、1024² 二进制的板上计时。四条都对，而且指向同一件事，现在这套结论的统计强度还撑不住它被引用的方式。

这节要你记住的是，它能跑起来这件事，比它比谁高几个点值钱。

七、可以接着做什么

1. 把「能不能分配」提前到选型阶段

现在的流程是先训好、再导出、再编译、再看序列化器收不收。既然卡点是激活，而激活量主要由 token 数和一个注意力矩阵决定，那就在选定骨干和输入尺寸的时候先算一遍。这个算式论文已经给了，HN2 乘一个元素两字节。把它前置到选型那一步，能省掉一整轮「训完才发现装不下」。

2. 把两个头的编码器合成一次前向

现在共享骨干省的是训练存储，设备上两张编码器图各带一份冻结权重，跑两遍。而两张图在注意力之前的部分完全一样，只有适配器分支不同。能不能在适配器那里分岔、把主干合成一张图跑一次，是个边界清楚的工程问题。省下来的时间直接落在节拍上，因为编码器占了 8134.3 ms 这个量级里的绝大部分。

3. 用跨尺度一致性去补孔隙

孔隙在 512² 上丢得多，在 1024² 上丢得少，这个差本身就是监督信号。同一张切片降采样一次，要求两个尺度上的孔隙掩码在回到同一尺寸后一致，可能比在 512² 上直接重训更能把孔隙补回来。重训那次实验说明「换分辨率再训」不是免费的，一致性约束是另一条路。这一条是猜的。

4. 把评估协议统一，顺便把夹杂物的真实标注补上

表 2 现在跨协议、跨骨干，读起来必须打折扣。真实数据只有孔隙标签，这是整个增材缺陷分割方向的共同缺口，也是这里唯一没法靠重跑实验解决的问题。谁先把带夹杂物标注的真实 XCT 体积放出来，这个方向就会往前挪一大步。

这节要你记住的是，四条线索都落在部署约束和评估协议上。

上面四条都是读完这篇之后的即时联想，我没有做实验，没有查证是否已经有人在做，也没有验证可行性。只当选题线索看，别当结论用。
