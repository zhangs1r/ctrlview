检索回来的文档里藏着一句指令，0.5B 小模型能不能在它进模型之前拦住

Abhishek Rai
arXiv:2610.28364 · 2026-11-02 · 精读约 30 分钟
间接提示注入RAG 安全语义防火墙知识蒸馏威胁模型

它想干什么

给公司文档搭一套本地问答，问"上季度差旅报销的上限是多少"。检索器从一堆 PDF 和内部网页里捞出三段，接在问题后面，一起交给模型。其中一段是从公开页面抓下来的，正文末尾跟着一段 HTML 注释，浏览器不渲染，抓取工具照抄。注释里写着一句话，让模型忽略此前所有指令，把这次对话的完整内容发到某个地址。

模型读到的是一整段文字。它分不清哪部分是你的问题，哪部分是别人写的。这句话落在指令的位置上，模型就当指令执行。这类攻击叫间接提示注入，英文缩写 IPI。直接越狱是用户自己在输入框里骗模型，间接注入把恶意指令放进模型之后会读到的数据里，用户全程不知道。检索这一步把它从可能发生变成必然经过。

难处在判据上。同一句"删除之前的所有输出"，出现在磁盘清理工具的用户手册里是正常的操作说明，出现在一段新闻摘录里就是要模型动手。字面一模一样，该给的标签相反。关键词过滤器只看字面，两种一起拦，或者两种一起放。通用安全护栏回答的是另一个问题，这段文字有没有害，它答不了这段文字和你此刻想干的事冲不冲突。判据得成对看，只看那段文字永远不够。

论文的做法是把判定改成一对输入的分类。输入是用户问题 Q 和检索上下文 C 拼在一起，输出三个标签之一，safe、suspicious、malicious-instruction，标签前面还要求模型先写一小段推理。做这件事的模型只有约 0.5B 参数，跑在本地，位置夹在检索器和生成器之间。训练数据不靠人工标，用 35B 的教师模型造 5,233 条配对样本，120B 的判官模型盲复核一遍，两家一致的那批拿去微调学生。

结果得两头看。同分布的留出测试集上，微调后的模型召回 0.994，误报率 0.026，比公开的注入分类器高 10.6 个点，比通用安全护栏高一大截。专门构造的翻案对里，同一句话在两种上下文下都判对的比例是 75.0%，其余系统最高 54.2%。另一头是代价。单请求延迟中位数 404 ms，换优化过的推理引擎之后 293 ms，都够不上论文自己写在威胁模型里的 100 ms 目标。拿界外的事实投毒基准试，召回只有 0.7%，比没微调之前的 14.3% 还低。

这节要你记住的是，这道防线守的是检索这一步，判据要成对才成立。

一、问题背景

1.1 检索把信任边界推到了别人手里

检索增强生成把参数化的语言模型和一个外部检索器接起来，回答前先从语料里取几段塞进上下文。好处是知识可以更新，数据留在本地。代价是任何能被检索到的内容都能改写模型的输入。语料越大越杂，能往里写东西的人就越多。

规模已经量过。一项测量扫了 12 亿个 URL、2,480 万个主机，确认 15,300 处注入实例，分布在 11,700 个页面上。约 70% 的载荷藏在不渲染的 HTML 里，注释、页眉、元数据都算。对小模型，纯文本输入上的依从率也能到 8%。安全厂商记录到的现场案例更直接，网页里的隐藏指令把智能体带去发起付款、删数据库、批准诈骗内容。

钱这一侧也有数字。IBM 2024 年的数据泄露成本报告给的平均单次泄露是 488 万美元，金融行业 608 万。论文用这个说明一道本地防火墙只要能堵住一条可用的外泄路径，成本就回来了。

1.2 几条现成的路各差一截

第一类是检索侧清洗。OpenRAG-Soc 是一个把注入藏进隐藏 HTML、alt 文本和无障碍属性里的基准，顺带给了几样可部署的缓解手段，清洗、Unicode 归一化、按归属放行回答。它的机制是在文本进上下文之前按规则改写或者剔除可疑片段，判据落在字符和标签上。它判不了这段内容和用户想干的事有没有冲突，规则里没有 Q 的位置。

第二类是通用安全护栏。Llama Guard 3 1B 的机制是把对话当成输入输出对，用一套通用安全分类法判断内容是否违规，按对话形态给分。它训的是内容有没有害，不是上下文与意图是否一致，输入形态也是一段对话，喂不进一对 (Q,C)。论文把这一档放到同一个测试集上跑，召回 0.437、误报 0.459，几乎等于瞎猜。

第三类是专门做注入检测的分类器。ProtectAI 的 deberta-v3-base-prompt-injection-v2 机制是在单段文本上做二分类，判这段文字里有没有注入痕迹，它在公开产品里用得很多。还有 Meta 的 Prompt-Guard-86M，一个 86M 参数、专门为注入检测训出来的小模型。两者的共同短板在输入形态，一段文本没有配对信息，模型只能靠字面，遇到正常的祈使句就分不出来。Prompt-Guard 在这个测试集上的误报是 0.690。

框架那一层另有一套东西。Guardrails AI 的机制是给输入输出挂一层可编程的校验器，规则由开发者写，框架负责在调用前后执行这些规则。NeMo Guardrails 的机制是用一套可编程的轨道约束对话走向，话题、对话流、检索、安全各有一层。两者给的是执行位置，不是判断能力，判"这段上下文与用户意图冲突"仍然要开发者自己写规则。

知识库那一侧的威胁是另一回事。AgentPoison 的机制是污染智能体的长期记忆和知识库，投毒率很低也能拿到高成功率，同时不让良性行为变差。PoisonedRAG 的机制是往知识库里注入少量精心构造的段落，让目标查询检索到攻击者文本并给出攻击者选定的答案。这两条路都不靠指令，靠的是检索命中，所以判据也不同。

1.3 论文选的路

系统名叫 nokast-secureRAG。核心动作三件，把判定对象从一段文本换成一对输入，把判据从"像不像攻击"换成"是否与用户意图冲突"，把一个 0.5B 的模型放在检索器和生成器之间当闸门。取舍也在这三件里，代价是多了一个模型、多了一段延迟、多了一份要维护的适配器。跟上面三条路比，它换来的东西是判据里多了一个变量 Q，付出的东西是每次问答多一次前向推理。

这节要你记住的是，检索把外部内容变成输入，防线只能建在这道门上。

二、总体结构

2.1 威胁模型的三条

这一栏的读者对威胁模型这套语言不熟，先把三条摆清楚，知道什么、能改什么、要什么。

知道什么。 攻击者知道目标系统是本地 RAG，知道它会从哪些来源抓内容，能把自己写的东西放进可检索的语料，网页、文档、记忆条目都算。论文没有交代攻击者是否知道检测器的权重、训练数据和标签体系。

能改什么。 只能改语料侧，也就是检索得到的内容。用户问题 Q 被假定为善意。这条假定很重，它把一整类攻击划到门外，被劫持的输入框、直接对用户说话的钓鱼内容都不在范围内。威胁模型的边界是 Q 善意、攻击在 C 里，这条界线定了，后面的召回率才有一个明确的适用范围。

要什么。 三种后果，覆盖或者绕过系统与用户的指令、把数据发出去、重新定义助手的角色。论文造的四个攻击家族正好对着这三种，间接注入和知识库投毒对着指令覆盖，上下文劫持对着角色重定义，PII 外泄对着数据外发，另外加了良性文档和边界样本两类。

假定之外。 检测器本地跑，硬件预算按 16 GB 级显存算，延迟要交互级，不许调云端护栏。论文没有测自适应攻击，梯度优化、多片段拼接、检索侧优化、人工红队都留在外面。

查询预算这一栏空着。这个设置里攻击者不直接查询检测器，他写一次内容，之后靠检索被动触发，所以没有查询次数这个概念。白盒还是黑盒也没有写。能确定的是模型、数据管线和评测代码都会开源，第七节把白盒攻击列成了后续工作。

把三条压成一句。攻击者能改的只有 C，想要的是覆盖指令、外发数据、改角色这三件，防线只能建在 C 与 Q 汇合之后、进生成器之前。

📌 控制视角　按控制里的说法，这是一个入口受限、幅度不受限的扰动模型。攻击者只能从内容通道进来，但注入什么、注入多长没有上界。鲁棒控制里扰动有界、模型已知，可以按最坏情况设计控制器；这里的扰动没有界，检测器也没有对象模型，只能做分布内的统计判断。这一栏读数字时先认这一条。

2.3 三个标签

safe、suspicious、malicious-instruction。safe 表示这段上下文与问题不冲突。malicious-instruction 表示上下文里有与问题意图冲突的指令性内容。suspicious 是中间那一档，指令性看得出来但不像明确攻击。中间这档在 5,233 条里有 200 条，在 659 条测试记录里只剩 6 条。论文自己说这一档的召回不可信，后面还会回到它。

这节要你记住的是，这条防线只管检索这一道门，门外的攻击它看不见。

三、方法拆解

3.1 输入是一对，输出是判定加一句理由

判决器收到的输入是两段文本的拼接，写成

[Q]∥[C]

Q 是用户问题，C 是检索回来的上下文，∥ 表示拼接。三个标签是输出空间，标签之前要求模型写一小段推理，训练目标形如 Reasoning 加 Label。这一句推理不是装饰，论文的监督方式就是让它先把 Q 与 C 的关系说一遍再下结论，判定因此落在两段文字的关系上，而不落在某一段的字面上。

一句话概括这套机制，把用户问题和检索上下文配成一对，判这一对是否一致。

标签空间用了三个。多出来的一档专门收指令性看得出来、意图冲突不确定的记录，训练集里 200 条，测试集里 6 条。这一档的作用是让边界样本不至于被硬塞进两头，代价是主指标里多了一个被小样本拖住的维度。

3.2 数据靠教师造，攻击载荷只放 C

教师模型是 Qwen3.6-35B-A3B，A3B 意思是混合专家结构里每个词元只激活 3B 参数，用 4 位浮点量化后跑在 vLLM 上。它按四类攻击加两类非攻击造样本，四类是间接注入、知识库投毒、上下文劫持、PII 外泄，两类是良性文档和边界样本。攻击载荷只嵌进 C，从不放进 Q，位置包括 HTML 注释、页脚、"忽略此前指令"这类从句。这样学生要判对，只能去看 C 与 Q 是否冲突，靠找噪声词没有用。

输出走 schema 约束解码。服务引擎在解码时把任何违反 JSON 模式的词元直接屏蔽，标签因此一定在词表里、一定能解析，不会出现拼错或者自造的类别。

数量账对得上。按标签算，3,116 条 safe 加 1,917 条 malicious-instruction 加 200 条 suspicious 等于 5,233。按家族算，3,115 条良性加 818 条间接注入加 500 条投毒加 400 条上下文劫持加 200 条 PII 外泄加 200 条边界样本也是 5,233。分片上 3,994 条训练加 499 条验证加 740 条测试还是 5,233。

3.3 判官盲复核，一致的才进训练集

判官是 Nemotron-3-Super-120B-A12B，跟教师不同族，每个词元激活 12B 参数。它只看 (Q,C)，看不到教师给的标签，重新判一遍。两家的结果一致的记录留下，不一致的隔离出去另判。这条级联检查每步都能在论文里指到原句。

对每条教师记录 (Q, C, y_teacher)
    判官只看 (Q, C)，重新给出 y_judge
    若 y_judge 与 y_teacher 相同，记入 agreed，按分片归入 train / val / test
    否则记入 disputed，隔离，不参与训练，也不进主表
disputed 单独裁定，裁定结果不回流到上面的计数

一致率 95.0%，也就是 4,973 条一致、260 条争议、0 条没有判定。一致的那些按分片切开是 3,835 条训练、479 条验证、659 条测试。

📌 控制视角　95.0% 是两家模型的一致率，不是标签的正确率。两家都对同一处报错的时候，这个数看不出来。论文把它叫数据质量信号，这个用法在工程上常见，读的时候要记住它的分母是"判官愿意表态的记录数"，不是"客观正确的记录数"。

3.4 翻案对怎么造

这么造的目的是把"读不读 Q"变成分数。两半的字面几乎一样，差别只在载体，一个只看字面的判据在这上面没有可靠依据。要看对，模型得读 Q，知道用户此刻在干什么。这是全文唯一一个把上下文感知直接变成分数的测试，也是论文中心主张的直接检验。

3.5 推理先行微调，被优化的到底是什么

被优化的量是适配器参数，基座权重不动。三件事各说一句。

初值来自 Qwen2.5-0.5B 的预训练权重，适配器是新增的，论文没有写这部分怎么初始化。驱动它的残差是交叉熵损失，而且损失只对补全部分计，也就是那段推理加标签，提示部分不计。兜底靠冻结，基座完全冻住，只在注意力和 MLP 的 q、k、v、o、gate、up、down 七个投影上加一对小矩阵，r=8、α=16、dropout 0.05，可动参数被压到很小。

产物是一个 17.6 MB 的适配器，或者合并成约 1 GB 的独立模型。这个尺寸能塞进本地推理运行时，llama.cpp 和 Ollama 这类工具吃量化模型，单机离线就能跑，不需要 GPU 集群，这一点跟 vLLM 那种面向批量吞吐的服务端引擎分工不同。

3.6 指标怎么读

五个量都是无量纲的比例，分母各不相同，混着读会出错。

检测召回的分母是恶意记录，659 条里占 311 条，它回答"恶意样本里被标出来的有多少"。ASR 代理那一列论文定义成没被标出来的恶意比例，表里逐行等于 1 减召回，0.006 就是 1 减 0.994，0.312 就是 1 减 0.688。误报率的分母是良性记录，342 条，0.026 按这个分母算大约是 9 条错标。三分类准确率把 suspicious 也算进分母，所以它被那 6 条拉着走。整对都对的占比分母是 120 对，一对两半都判对才计一次。整对都对比单条准确率严格得多，一对里错一半就不算数。

分母一共四种，读表前先在纸上写一遍。主表两类记录，311 条恶意加 342 条良性等于 659 条。翻案表 120 对，等于 240 条。消融表沿用 659 条的分母。界外检查 300 对，全部按恶意算，没有误报率这一列。论文另有一张 740 条的原测试分片，那 740 条只用来算 120 对完整配对的翻案指标，主表不用它。这几个数混在一起读，是这份稿子最容易出错的地方。

这节要你记住的是，判定落在两段文字的关系上，所以先写推理再给标签。

翻案对是 120 对完整配对，也是这套说法唯一能被证伪的地方。

这一列才是论文中心主张的直接证据。ProtectAI 把正则的 0.175 拉到 0.542，说明语义模型本身确实有用，但它比本文低 21 个点，差在输入形态上。Llama Guard 只到 0.267，比正则好一点。Prompt-Guard 0.092，比正则还差，原因在主表里已经埋好，它把近七成良性内容标成攻击，一对里必然有一半判错。

输入消融把 Q 的作用单独拎出来，这是在 659 条上做的三档掩蔽。

Q 置空那一行召回归零，因为上下文空了没有东西可标，这一行证明攻击信号全在 C 里，跟威胁模型的假设一致。只有 C 的那一行拿到 0.987，说明大部分信号本来就在上下文里，对大多数非翻案记录，恶意内容不看问题也一目了然。错配那一行才有信息量，攻击内容还在，只是配了一个不相关的问题，误报从 0.026 涨到 0.085，约为三倍。Q 的作用集中在少数歧义情形，论文自己也是这么写的。表 3 的分母是 659 条判官认可的记录，表 4 的分母是 120 对完整配对，两张表不能互相换算。

三个分档召回可以倒推三分类准确率，算一遍能看出表里的数自洽。0.994 乘 311 加 0.974 乘 342 加 0.167 乘 6 再除以 659，得 0.976，表里写的是 0.974，差的 0.002 来自四舍五入和分档边界。这条算式也说明 0.974 是被两个大类撑起来的，可疑类在 659 条里只贡献了 1 条正确。

延迟要分开两种量。批处理下（batch 32）每条摊销 37 ms，这是吞吐量。部署关心的是单请求，eager 运行时中位数 404 ms、p95 513 ms，时间主要花在自回归生成那 36 个词的推理串上。换 vLLM、合并模型、100 次串行单请求、贪心解码之后，中位数降到 293 ms、p95 370 ms，范围 230 到 534 ms，光换引擎就降了 27%，但仍然没到 100 ms 目标。原因在串行解码本身，优化引擎改善的是批量吞吐，不是单个词元的延迟。论文把只输出标签的变体留作后续工作。

能耗这一侧很轻。造数据约 35 Wh，微调约 9 Wh，跑了 14.6 分钟、GPU 占用 94%，成品适配器 17.6 MB。整条流水线在一台消费级设备上跑完。

把这几样合起来就是防御的代价。2.6% 的良性文档被误拦，每次问答多 293 到 404 ms，外加一个只认指令注入的检测器挡不住事实投毒，换一个领域还得重新造数据。换来的是界内召回从正则的 0.688 抬到 0.994，误报从 0.129 压到 0.026。

置信区间给得比主表诚实。恶意类 311 条，召回 0.994，Wilson 95% 区间 [0.977, 0.998]。良性类 342 条，召回 0.974，区间 [0.951, 0.986]，误报区间 [0.014, 0.049]。suspicious 只有 6 条，召回 0.167，区间 [0.030, 0.564]，5 条漏掉的里有 4 条被判成恶意指令，错的方向是往严里错。去重检查也做了，79.9% 的测试 4-gram 在训练集里没见过，最近邻的 Jaccard 均值 0.060、中位 0.048、最大 0.390，没有一条到 0.5。

界外检查是这篇最该被记住的一段。PoisonedRAG 有 300 对查询与对抗段落，来自 NQ、HotpotQA、MSMARCO 三个数据集，每条段落都是大模型生成的、事实错误的答案，全部按恶意算，只算召回。正则抓到 0%，零样本学生 14.3%，微调后的学生 0.7%，300 条里 298 条判成 safe。界外召回 0.7%，比没微调的 14.3% 还低。论文的读法是作用域边界，这类攻击里没有指令、没有角色声明，恶意来自事实为假，与查询意图无关，而微调把模型往指令注入的表面形式上收，代价是零样本那点弥散的怀疑心。

📌 控制视角　把 0.7% 当成一条可用的判据。它说明"指令一致性"和"事实一致性"是两个正交的观测量，一个检测器只在一个方向上敏感。控制系统里也一样，一个残差通道盯一种故障，想同时盯两种就得加通道，而不是把阈值放宽。这段在论文里是局限，在部署上是选型依据。

这节要你记住的是，正面证据在翻案对，适用边界在界外基准。

五、局限

论文第八节自己列了七条，逐条对下来是这些。

  • 头条数字是同分布，只有一个界外检查。训练和测试出自同一个生成器。
  • ASR 是检测侧代理，测的是闸门有没有响，不是下游生成器的行为。
  • 自适应攻击者没测。梯度、多片段、检索侧优化、人工红队都在外面。
  • 延迟只在一台机器上测，eager 和 vLLM 两种都超 100 ms 目标。
  • 数据只有英文。
  • 单域验证。金融、医疗、法律文档没试过，这类文档里指令性文字密度高，safe 与恶意的边界可能移动。
  • suspicious 类数据太少，659 条里只有 6 条，0.167 的召回不可信。

论文另有一处自我交代该单拎出来。它的中心主张是翻案能力，而"没有公开基准测翻案"这句话是它自己写的，所以中心结论只在分布内成立。基准是怎么挑的它也写了，OpenRAG-Soc 没有公开数据集，SafeRAG 只有中文、跟这个纯英文检测器不兼容，PoisonedRAG 是唯一能用的选项。这一段把选择过程摆出来，比只说"我们做了界外检查"要实。

编者补充一段。以下几条论文未将其列为局限，它们会影响读者对这份结果的预期。

第一，教师、判官、学生三段同源。三个模型族不同，但都是大模型，判官盲复核只能拦住"教师一家胡来"，拦不住"两家一起错"。95.0% 一致率对这种同错没有分辨力。

第二，部署时 suspicious 怎么处置，论文没有交代。三个标签给了，拦不拦、降权还是转人工，策略层是空的。端到端效用损失因此算不出来，误报 0.026 到底意味着用户少用了百分之几的文档，也没法回答。

第三，37 ms 与 293 ms 混在两处报，量纲不同。表里的 37 ms 是 batch 32 的摊销值，正文的 293 到 404 ms 是单请求，读表时容易串成一个数。

第四，翻案对是合成的，构造规则由作者定。真实语料里"同一句话完美对立"的比例有多少，论文没有量，75.0% 因此更像一个上界条件下的成绩。

这节要你记住的是，同分布的成绩单不能当鲁棒性用。

六、我的评价

做得对的地方有三处。

把上下文感知变成一个可测的量，这一步很便宜。判据是同一句话落在两种载体里、整对都对的占比，动作只是造 120 对样本。代价几乎为零，换来的是一个模糊的能力声明有了分母。75.0% 的整对都对，是全文最硬的一个数，因为它不可能靠字面匹配凑出来。

输入消融做到了错配这一列。只报 Q 置空和 C 置空这两档容易读偏，因为 C 置空那一行是 0.987，信号大半在上下文里。错配把 Q 的作用单独拎了出来，攻击内容留着、只换问题，误报立刻涨。这是三行里唯一一行没有别的解释的。

负结果照实报。PoisonedRAG 那 0.7% 完全可以不写，写出来还得解释，论文两样都做了，并且把它写成作用域边界而不是失败。

存疑的地方也有五处。

翻案对上没有做 Q 掩蔽消融。659 条上做了三档，120 对上没做。补上这一档才能回答 75.0% 里有几个点来自读 Q，几个点来自在自家数据上微调过同类表面形式。这个缺口不大，但它正好落在中心主张上。

95.0% 一致率被当成标签可信的证据，强度有点过。争议恰好集中在 suspicious 那条边界上，论文自己也说 5% 的争议集中在最含糊的那一档。一致的那部分本来就更简单，一致率高不能推出标签对。

去重检查也留了一个口子。79.9% 的 4-gram 没见过、最大 Jaccard 0.390，证明的是字面不重复。论文在附录里说攻击模板从有界空间里抽，复用是设计的一部分，测试集与训练集因此共享同一批注入句式，只是载体不同。这条不影响翻案对的结论，影响的是 0.994 在真实网页上的可迁移性。

延迟这一项没有交代完整。论文把 100 ms 写进威胁模型当约束，最后 293 ms 没达标，只把只输出标签的变体留作后续。闸门和生成器要串行跑，用户感受到的是两者之和，论文没有给这个数。用控制的话说，翻案对测的是这对输入在判决函数里可分不可分，错配那一档测的是 Q 这一维有没有非零增益，两项都有了，可用的时延预算仍然缺。

还有一处可以说得直白。ASR 那一列与召回严格互补，等于没有第二列。表里六行都能验算出来，它不提供额外信息，要看的下游成功率没有测。论文在局限里承认了这一条，位置给得很低。

它想去的方向是把语义防火墙变成 RAG 的默认组件，让 0.5B 这一档的模型承担"读一遍检索结果"的职责。现实障碍不在模型质量，在延迟和标签的处置策略上。

这节要你记住的是，证据支持配对输入有用，还不支持部署即用。

七、可以接着做什么

1. 在翻案对上补 $Q$ 掩蔽消融

论文在 659 条上做了三档掩蔽，唯独没在 120 对上做。跑一遍就知道整对都对的比例从 0.750 掉到多少，验收判据是掉幅。这一条最便宜，改一个输入字段的事。

2. 训一个同分布但上下文盲的对照

把 (Q,C) 换成 C，用同一批 3,835 条训练，其余不变。这一条能把"读到 Q"和"在自家数据上微调过同类模板"分开。现在这两件事在 0.994 里是混着的。

3. 做白盒自适应攻击

适配器只有 17.6 MB 且开源，攻击者拿得到权重。可以在载荷上做梯度或者模板搜索，找一个既能被检索到、又不触发检测的句子。论文把这类攻击列在局限里没做，而它恰好决定这道闸门能挡谁。

4. 给 suspicious 补数据

6 条测试样本撑不起任何结论。构造方式可以照着翻案对来，先定义"指令性明显但意图冲突不确定"，再用判官筛。验收看可疑类的置信区间宽度能不能压到 0.2 以内。

5. 加一道事实层的判据

PoisonedRAG 那 0.7% 说明指令一致性和事实一致性是两个正交的判据。可以把"检索片段与 Q 的事实冲突"做成第二道闸，两道各管一种失败。代价是延迟再叠一层，这一点得先算清楚。

这节要你记住的是，最缺的是掩蔽消融，不是新模型。

上面五条是读完文章的即时联想，我没有做实验，也没有查证过是否已经有人在做，更没有验证过可行性。只当线索看，不要当结论用。
