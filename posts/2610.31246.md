## 它想干什么

你把人脸照片传给云上的年龄预测服务。平台跑在 SGX 里，输入、中间激活、输出都在隔离区内，云厂商按合同和 PIPL、GDPR 都不许看。这套保护在纸面上是完整的。论文说它漏了一个口子，漏在时间上。

漏法是这样的。这家云厂商同时也是模型的供应方。它在部署前交给你一个动过手脚的多出口网络，让白人男性的照片大概率停在第 1 个出口，其他人的照片停在别的出口。上线以后它什么也不读，只在服务层给每个请求掐一次表。第 1 个出口比最后一个少跑好几层，0.73 毫秒和 1.96 毫秒分得开。看到 0.73 毫秒，它记下一条，这个人是白人男性。你拿到的那条年龄预测没有变，精度也没有变。

效果量得很硬。四套数据、十个属性、三种骨干，平均精度 78.84%，平均召回 71.00%，F1 是 **0.73**。三个基线里最强那个的平均 F1 是 0.25。主任务精度掉不到 **1.3** 个百分点，加速比在十个设置里有八个的降幅小于 **0.1**。

==早退规则本来用置信度表达这题难不难，这篇把它改成表达这张图有没有某个属性。== 出口号于是从"算得快不快"变成了一个比特的答案。

这节要你记住的是，它读不到你的数据，但它能决定你的数据在哪层停下。

## 一、问题背景

### 1.1 省算力的那套结构

多出口网络在中间层挂若干分类器，每个分类器叫一个出口。这一类结构以 BranchyNet [3] 和 Shallow-Deep Networks [5] 为代表，做法是把一个深网络切成几段，每段末尾接一个和主任务同类的分类头。推理逐层往前走，某个出口的最高 softmax 概率越过预设阈值就停，把该出口的预测当结果返回，后面的层不跑。图 1 画的是三个出口的样子。

设计这类网络的人关心平均算力。这篇把供应方当成对手，同一套结构于是多出一个问题。

云平台已经在卖这种模型。Hugging Face 的 Inference Endpoints 与 Google Cloud 的 Vertex AI 上都能一键部署带多出口的 GPT-Neo 与 BERT 变体 [9][10][11]。卖点是精度和时延，用户按这两个指标挑。

### 1.2 为什么难

难在信号弱。每次查询能拿到的只有一个标量时延。正常部署里这个标量只够回答"这次跑了多少层"。

把这件事按自由度记一遍账。未知数是 1 个比特，记 $z \in \{0,1\}$，表示这条输入有没有目标属性。每个请求给攻击者的观测只有 1 个时延值，把它离散化之后得到 1 个出口号，取值 0 到 $K-1$，$K$ 是出口个数。所以单次查询最多贡献 $\log_2 K$ 个比特，$K$ 取 4 到 6 时是 2 到 2.58 个比特。判 $z$ 只需要 1 个比特，__最少 1 次查询就够__。

这条路能成立，靠的是那个映射可以被改。模型是攻击者供的，它能在部署前决定"哪一类样本在哪一层停"。时延本身不带属性，带属性的是这个安排。

第二处难在三个要求互相拉扯。精度要高，召回要高，模型还得看起来正常。把置信度往一个方向拧，主任务精度与平均加速比都会跟着动，论文实验里 BreakHis 那一组就掉得厉害。

第三处难在属性可以与主任务无关。部署给人脸年龄预测的模型，可以被拿来判断性别或族裔。这类信息在训练时没被当成目标，模型没有理由把它编码进出口选择。要它编码，只能靠改造。

### 1.3 前人两条路

第一条是针对训练集的推断攻击。成员推断（Shokri 等 [23]）判断某条样本是否在训练集里，靠模型对见过与没见过的样本给出的置信度差异。属性推断（Ganju 等 [27]）估训练集的统计属性，比如某个敏感属性占多大比例。模型反演（Fredrikson 等 [31]）从输出重建训练样本。三条路都要拿到输出，或者更强的梯度与参数，问的也都是训练集的事。

第二条是多出口网络上的时延侧信道。Li 等 [18] 用推理时间和出口模式反推模型的超参数，也就是出口个数与深度，再拿这些超参数去加强成员推断，目标仍然是训练集。Kannan 等 [33] 让被动的观察者看一条查询停在哪个出口、花了多久，据此判断这条查询属于哪个类别。Akinsanya 与 Brennan [34] 做同一件事，把目标扩到超类，以及这条输入是不是对抗样本。这两篇都不动模型，能读到的只有模型自然形成的出口分布所对应的类别。

差别落在两处。他们是被动观察者，泄露什么由训练决定；这篇的攻击者是供应方，能在部署前重新安排出口分布。他们读的是主任务给出的类别，这篇可以读与主任务无关的属性。

### 1.4 这篇的做法

先定目标属性 $z$ 与一个指定出口 $T$。在 $T$ 上把带属性样本的置信度顶过阈值，把不带属性样本的置信度压到阈值以下。在 $T$ 之前的每个出口上反过来做，让带属性的样本被压住，一路往后走。两组损失一个守精度，一个守召回。改造从干净模型的权重出发做微调，主任务精度靠这个初始化兜住。一句话概括，它训练模型让带属性的输入只在指定出口停下。

这节要你记住的是，信号只有一个数，能改的却是一整张映射表。

## 二、总体结构

### 2.1 威胁模型

三条要一起看，缺一条后面的数字都没有意义。

**攻击者是谁。** 云服务提供商（CSP）自己，一面是模型供应方，另一面是推理基础设施的运营方。它按正常商业流程准备模型、部署服务、按次计费，全程不需要越权，也不需要绕过任何运行时保护。

**它不读什么。** 原始输入、模型输出、中间激活，一概不读。运行时也不改推理流程。挡在中间的是 SGX 一类可信执行环境（TEE），论文的实现在 Occlum 0.31.0 上跑 PyTorch，Python 运行时、框架、权重、数据全在 enclave 内。TEE 的做法是把用户数据和云厂商的基础设施做硬件级隔离。==它能挡住读内存，挡不住掐表。== 合同里的隐私条款和 PIPL、GDPR 这类合规要求是第二道约束。

**它只拿什么。** 每个请求的一个时延数字。论文把它称作基础设施层仍然可见的量。

**它还能做什么。** 部署前供应任意模型，包括从头训、微调公开模型、给预训练骨干挂出口。它还需要一批带目标属性标注的样本。论文说训练集里本来就有，占不到 20%，不够的话可以从公开数据集或网上收集后自己标。

### 2.2 假设的边界

白盒还是黑盒。对攻击者是全白盒，模型是它自己交出去的，阈值、出口位置、权重都在手上。对用户是黑盒，用户看到的只有精度、加速比和一个返回的预测。

要不要事先知道模型结构。不需要从外部推断，攻击者就是结构的设计者。用户侧也不需要知道，按公开指标挑模型就够。

需要多少次查询。每个请求 1 次。判断在线做，不需要对同一个输入反复试探。这一点把它和那些要成百上千次查询的成员推断分开了。

还有一条边界要说明。主表在"出口号已知"的前提下报数，把"从时延反推出口号"单独测。第 V-F 节在真机上量，出口号推断准确率 **99.2%** 以上。主表回答的是"假设这一步不出错，攻击能做到多好"。

### 2.4 一个控制视角

> 📌 **控制视角**　可观性讲的是状态能不能从输出反推，取决于观测矩阵的秩，跟测点堆得多密无关。这里系统给用户的输出只有一个时延标量，秩本来就低。攻击者做的事是把状态空间重新排一遍，让待估的那 1 个比特落进那个唯一可观测的方向。出口号这个传感器的量程有 $\log_2 K$ 个比特，正常部署只用它表达难度，剩下的部分被这篇挪去编码属性。挡住读内存的那套保护对这件事无能为力，泄露走的是网络的入口，不是内存。

这节要你记住的是，它能改模型、能掐表，读不到你任何数据。

## 三、方法拆解

### 3.1 落点是早退规则

把早退写成一条规则。

$$\hat{y}(x) = f_{i^{*}(x)}(x), \qquad i^{*}(x) = \min \{\, i \mid \max_{c} f_{i}(x)_{c} \ge \tau \,\}$$

$f_i$ 是第 $i$ 个出口输出的概率向量，对 $|y|$ 个类别做过 softmax。$\tau$ 是早退阈值，论文固定取 0.9。$i^*(x)$ 是这条输入实际停下的出口号。$\hat{y}$ 是返回给用户的预测。

这条规则有一个可以被利用的自由度。停不停只看该出口的最高概率有没有越过 $\tau$，跟预测对不对无关。所以被操纵的量是"最高概率越过 0.9 没有"，argmax 指向哪个类可以不动。__预测类别不变、只变置信度，这是隐蔽性的来源__。

服务期那一步是把时延换成出口号。这里没有迭代求解，观测就是时延 $t$，判定是把它落到哪个出口的区间里。论文在消融里用核密度估计（KDE，把一维样本拟成若干峰的非参数方法）把时延拟成 $K$ 个峰，取峰中心当各出口的标称时延。兜底靠的是峰之间的间隔远大于抖动，TEE 下最小相邻间隔 **1.04** 毫秒，GPU 下 **0.26** 毫秒。

### 3.2 指定出口上的选择性标签平滑

标签平滑是一个正则化手段，把 one-hot 标签里的 1 降到 $1-\epsilon$，剩下的 $\epsilon$ 平摊到其余类别。用软标签训出来的模型，最高概率会被压低，输出分布更平。

这篇把它拆成两半用。记数据集 $D = \{(x,y,z)\}$，$x$ 是输入，$y$ 是主任务的 one-hot 类别标签，$z \in \{0,1\}$ 是属性标签。$f_i$ 是第 $i$ 个出口的输出，$\theta$ 是模型参数。指定出口 $T$ 上的损失是

$$L_{\text{smooth}}(D,T;\theta) = \frac{1}{|D_0|} \sum_{x \in D_0} L_{\mathrm{CE}}\left(f_{T}(x;\theta),\, y_{\text{smooth}}\right) + \frac{1}{|D_1|} \sum_{x \in D_1} L_{\mathrm{CE}}\left(f_{T}(x;\theta),\, y\right) \tag{1}$$

符号逐个说。$D_0$ 是 $z=0$ 的那一半，$D_1$ 是 $z=1$ 的那一半，$|D_0|$ 与 $|D_1|$ 是各自的大小，求和遍历各自那一半里的输入。$L_{\mathrm{CE}}$ 是交叉熵。$y_{\text{smooth}}$ 是软标签，把真类的概率从 1 降到 $1-\epsilon$，再把 $\epsilon/(|y|-1)$ 分给其余每个类，$|y|$ 是类别数。两项各除以自己那一半的样本数，是为了两个子集规模不同时量级仍然可比。

第一项让 $T$ 对不带属性的样本给低置信度。第二项用 one-hot 顶高带属性样本的置信度。这一项守的是精度，也就是"停在这里的确实带属性"。

### 3.3 熵协方差

平滑只能压，不能顶。要把差距再拉开，论文加了一项，把每个样本的预测熵 $H\left(f_T(x;\theta)\right)$ 与属性标签 $z$ 的协方差往负里推

$$L_{\mathrm{cov}}(D,T;\theta) = \mathrm{Cov}_{(x,z) \in D}\left(H\left(f_{T}(x;\theta)\right),\, z\right) \tag{2}$$

$H$ 是熵，$H(p) = -\sum_{c} p_{c} \log p_{c}$，分布越尖熵越小。$\mathrm{Cov}$ 是协方差，量两个量的线性相关强度。

这一项调的东西值得说清楚。==协方差约束的是整批样本上的统计关系，逐条样本的阈值它不管。== 它只要求这一批里 $z=1$ 的样本平均熵比 $z=0$ 的低，且低得成比例。负得越多，两组置信度分得越开。

> 📌 **控制视角**　拿一个整批的统计量当损失，和逐条样本设阈值，是两种约束。前者只要求两组在平均意义上分开，后者要求每条样本都达标。控制里也有这一对，鲁棒控制盯着最坏情形，逐点约束跟着具体轨迹整定，后者更容易把解逼到边上。论文选前者，代价是它只保证统计意义上的分离，单条样本仍可能落在错的一侧。

标准协方差要全集的均值，mini-batch 上拿不到，论文用批均值近似。这是个有偏的估计，批越大越接近真值。论文没有讨论批大小对这一项的影响，实验里批大小固定为 64。

$T$ 上的总损失是两项相加。

$$L^{T}(D,T;\theta) = L_{\text{smooth}}(D,T;\theta) + \lambda L_{\mathrm{cov}}(D,T;\theta) \tag{3}$$

$\lambda$ 控制后一项的权重。VGG-16 上 $\epsilon = 0.6$、$\lambda = 1.5$，ResNet-56 上 $0.3$ 与 $0.5$，MobileNet 上 $0.6$ 与 $0.5$。BreakHis 是二分类，$\epsilon$ 改取 0.4，论文说大 $\epsilon$ 在二分类下会伤训练。

### 3.4 前置出口上把标签反过来

只在 $T$ 上做，带属性的样本可能更早就被前面的出口放走，召回就没了。所以排在 $T$ 之前的每个出口都要用相反的策略。做法是把属性标签取反，记 $\bar{D} = \{(x,y,1-z) \mid (x,y,z) \in D\}$，令

$$L^{P}(D,i;\theta) = L_{\text{smooth}}(\bar{D},i;\theta) + \lambda L_{\mathrm{cov}}(\bar{D},i;\theta) \tag{4}$$

标签一反，带属性这一组在 $i$ 上落进软标签那一项，置信度被压低，过不了阈值，于是继续往后走。不带属性的样本在 $i$ 上照常预测，路由基本不动。==同一个式子换个标签，作用就反过来了==。

$T$ 之后的出口不做处理。带属性的样本已经在 $T$ 停了，更深的出口影响不到攻击。这些出口用普通交叉熵训，保住主任务。

$$L^{A}(D,i;\theta) = \frac{1}{|D|} \sum_{(x,y) \in D} L_{\mathrm{CE}}\left(f_{i}(x;\theta), y\right) \tag{5}$$

三段加起来是总目标。

$$L = L^{T}(D,T;\theta) + \sum_{i=0}^{T-1} L^{P}(D,i;\theta) + \sum_{i=T+1}^{K-1} L^{A}(D,i;\theta) \tag{6}$$

$K$ 是出口总数。

### 3.5 两阶段训练

直接拿式 6 从随机初始化训，主任务精度会掉。论文在实验里看到了，归因于模型容量被过多目标分摊，留给主任务的学习空间被挤。表 VI 里 Direct 那一行就是这条路。

所以分两步走。第一步训一个干净的多出口网络，把式 6 里的 $L^{P}$ 与 $L^{T}$ 换成普通交叉熵。先训骨干 100 个 epoch，SGD，初始学习率 0.01，在第 35、65、85 个 epoch 各降十倍；再插出口，Adam，25 个 epoch，学习率 0.001。第二步定下属性与指定出口 $T$，用式 6 微调 100 个 epoch，SGD，学习率 0.001。

按三个被优化的量对一遍账。被优化的量是各出口的置信度分布。初值来自第一步的干净模型，这一步保证起点处主任务已经是好的。驱动它动的是式 6 的梯度，$T$ 上是平滑加协方差，$T$ 之前是反标签的同一对。兜底有两样，初始化本身限制权重能走多远，$T$ 之后的出口继续用普通交叉熵把主任务锚住。三样齐了，机制才算接上。

指定出口的选择上，主实验统一取倒数第二个出口。第 V-I3 节把 $T$ 放在 15% 到 90% 层深的六个位置扫过一遍，越深效果越好，代价是加速比往下走。

### 3.6 指标的量纲

攻击效果看三个数，都定义在"这条输入是不是停在 $T$"这件事上。

$$\text{Precision} = \frac{|\{x \mid z=1,\ i^{*}(x)=T\}|}{|\{x \mid i^{*}(x)=T\}|}, \qquad \text{Recall} = \frac{|\{x \mid z=1,\ i^{*}(x)=T\}|}{|\{x \mid z=1\}|}$$

精度是停在 $T$ 的样本里真正带属性的比例，召回是带属性样本里停在 $T$ 的比例，F1 是两者的调和平均。三个都是比例，没有量纲。__这里的精度衡量一次二值判决，判据是出口号，不是分类正确率__。

隐蔽性看两个数。主任务精度是部署后的 Top-1。加速比定义为整个骨干的浮点运算量除以多出口模型的平均浮点运算量，无量纲，越大越省。

读法上有一件事要注意。精度和召回可以互换。把效应往召回那边拧，停到 $T$ 的样本变多，精度就掉。BreakHis 那一组正是这个形状。

### 3.7 两个扩展

同时推断多个属性。每个属性 $p$ 分一个指定出口 $T_p$。在 $T_p$ 上只把属性 $p$ 当目标，其余样本（含带别的属性的）全当非目标，这个出口就专门为 $p$ 服务。在 $T_p$ 之前的出口上，带任一属性的样本都当目标压住，防止它们提前跑掉。

只给骨干。用户自己插出口的情况下，攻击者不知道插在哪。论文按已有设计 [5]、[48]、[49] 的经验估一个范围，__后 40% 的层里至少有一个出口__。然后把这段范围里所有可能的位置都当指定出口，范围内的按式 3 处理，更浅的按式 4，更深的按式 5 照常训。训练时冻结分类器只训骨干，最后只发布骨干。

这个"骨干加用户自插出口"的场景不是这篇提出来的，论文说它在 [5]、[48]、[49] 里已经被研究过。那几篇在同一场景里做的是后门注入，落点在效率上，这篇换成问属性泄露。

这节要你记住的是，一套损失配一套标签，出口号就成了属性位。

==两个防御都靠削掉加速比来换隐私。== 按定义看，随机化退出让样本以概率 $p$ 才真的停，$p$ 一小，停在中间出口的样本就少，平均跑的层数往整网靠，加速比也就往 1 掉。哑计算是在停下之后多花一段随机时间，按墙钟算的加速比跟着掉。两样都是攻击变难的同时用户变慢。

⚠ 论文第 VI 节只给这两条曲线，没有给 $p$ 与 $\sigma$ 换算出的延迟开销、额外算力与效用损失的表。这一格是空的，读完别当成"代价不大"。

> 📌 **控制视角**　故障检测里把阈值调低能抓出更小的异常，代价是误报变多。这里把 $p$ 调小、$\sigma$ 调大能压住泄露，代价是加速比变少。两件事形状相同，都是在一条权衡曲线上挑工作点。区别在于故障检测的误报是虚警，这里的代价是实打实的算力，用户会直接感觉到服务变慢。检测那一侧几乎没有成本，部署前审一次交上来的模型，看每个出口的置信度条件分布有没有被拉开就够了。

论文还提了两个方向，用可信数据微调、部署前检查参数，两者都留作未来工作，没有做实验。

这节要你记住的是，十组里有八组，攻击几乎没让服务变慢。

## 五、局限

### 属性比主任务难的时候隐蔽性撑不住

BreakHis 上加速比掉 0.55 与 0.71，剩下的加速比是 2.62 倍与 2.18 倍。论文的归因是这条属性（组织病理亚型）比主任务（良恶性）难得多，微调时多出来的目标挤占容量，中间出口的置信度分布被打乱，更多样本往深处走。原文用的是 we attribute，是解释不是证明。

### 从零训练会掉精度

第 IV-D 节说直接优化式 6 从随机初始化开始会有可见的精度下降。表 VI 里是 88.91 与 89.10，两阶段是 91.06 与 93.94。原文给它一个归因（容量被多个目标分摊），没有单独验证这个归因。

### 扩展场景可能全落空

论文写明"可能一个出口都没插在后 40% 的层里，此时精度、召回、F1 全为零"。这是它自己给出的失效条件。

### ε 对精度的影响方向不一致

第 V-I2 节说 $\epsilon$ 变大时精度在 CIFAR-10 上下降、在 VGGFace2S 上上升。论文原话是把这一现象的细查留给未来工作。超参怎么选，有一个方向没解释清楚。

### 阈值取到 0.99 时 CIFAR 的召回掉出这个范围

第 V-I4 节写除 CIFAR-10 上的 0.99 阈值以外召回都在 67% 以上。0.99 那一格仍然高于最好的基线（57%），但它是唯一掉出范围的点。

### 只做图像分类

第 II-A 节把范围限定在图像分类，理由是这类模型在多出口推理里被研究得最多。语言模型那一支 [21]、[22] 只在相关工作里提了一句，没有实验。

### 只评估了两个防御

第 VI 节说可信数据微调、部署前检查参数这两条留待未来工作。哑计算那一条是仿真，论文写明是因为哑计算的具体形式随部署环境变化。

### 防御代价那一格没有数（编者补充，论文未将其列为局限）

图 7 只给曲线，没有给 $p$ 与 $\sigma$ 对应的延迟开销、额外算力与效用损失。用户要为隐私付多少毫秒，这一格读不出来。也没有做自适应攻击，也就是让攻击者知道防御存在之后重新训一遍，所以那两条曲线只能当一次性的效果看。

### 主表在出口号已知的前提下报数（编者补充，论文未将其列为局限）

十个设置的对应数字都是这个前提，端到端只在一台 RTX 4090 上补了一组。真实服务里并发、批处理、排队抖动都会让单查询时延不再干净地对应出口号，论文没有在这种条件下测。

### 没有做检测侧的评估（编者补充，论文未将其列为局限）

隐蔽性只用主任务精度与加速比两个宏观指标衡量。做模型审计的人可以看每个出口的置信度条件分布，也可以看带属性与不带属性的样本是否系统性落在不同出口，这两件事在部署前就能做。==属性必须在中间层可线性分开，这是论文没有写出来的前提。== 论文把参数检查列为未来工作，承认了检测面存在但没有测。

### 单次运行可能明显偏离均值（编者补充，论文未将其列为局限）

表 II 的精度标准差最高到 16.28（CIFAR-10 的 Speckle Noise），F1 标准差最高 9.98。论文报的是五次试验的均值，一次部署拿到的那个模型可能明显偏离它。

这节要你记住的是，作者承认的边界在难度与超参，其余账本没打开。

## 六、我的评价

这一节是我的判断，不是论文的结论。

做得对的地方，首先是威胁模型写得干净。三条能力配一条禁令，读者不会误读成"它能看输出"。把投毒与侧信道接在一起也干净，一个在部署前，一个在服务期，两段时间各有明确的可操作对象，责任划分清楚。端到端那一组是加分项，三十个格里二十一个差异小于 0.5%，说明时延这条通路在真机上没有想象中脏，主表的假设站得住。

存疑的地方，第一条是属性难度这个隐藏自变量。96.37 与 43.08 差 53 个百分点，差别全在"这个属性能不能被中间层线性读出"。论文把它归给属性复杂度，没有把它抬成一个前提写进方法节。要复述这套方法，我会补一句，属性必须在中间层近似线性可分，否则精度会掉到基线附近。

第二条是隐蔽性的基线不稳。五个设置里攻击后的主任务精度比干净模型高，最高 +2.14。对照的干净模型因此还有余量。拿一个没榨干的模型当隐蔽性参照，报出来的"没掉精度"就打了折。更严的做法是把干净模型调到同样的精度，再比加速比。

第三条是判错一个人的代价不对称。分类任务里 F1 0.73 算不错，用在这里，==每四个人里就错一个==，错的那一个是真人的敏感属性被记下。论文的评估口径按分类任务的习惯走，没有按这种单条判决的代价来算。

第四条在防御那一节。两个防御都靠牺牲加速比，等于把多出口网络的存在理由削掉一块。这对防守方是个坏消息，代价落在用户身上，收益是隐私。论文没有给出"隐私换多少毫秒"的兑换率，这一格空着，工程上就没法选工作点。

它想往哪走有两条线。一条是把防御做实，把 $p$ 与 $\sigma$ 换算成实际延迟与算力，给出帕累托前沿。另一条是把检测补上，在部署前审出口条件分布。第二条比第一条便宜得多，也更容易被平台采纳。

这节要你记住的是，机制干净，前提没写全，代价不对称。

## 七、可以接着做什么

### 1. 并发条件下的时延归因

整个攻击的地基是"一次查询的时延能对上它的出口号"。批处理、多租户、动态批大小都会让这个对应变模糊。把请求按并发度分组，量一遍出口号推断准确率随并发度的衰减曲线，就能给出这套攻击的适用边界。这条实验不贵，只需要一台服务器和一份带属性标注的数据。

### 2. 把检测做成一个审计器

拿供应商交上来的模型，冻结权重，跑一遍公开数据，统计每个出口上带属性与不带属性样本的置信度分布，算两组分布的散度。若机制如论文所述，这个散度在被动模型上是小的，在被操纵模型上会明显变大。这条路的成本是几百次前向，比任何运行时防御都便宜。

### 3. 一组自适应攻击

让攻击者在知道随机化退出与哑计算存在的前提下重新训一遍。$p$ 越小，可用的路由信号越少，但损失函数里仍然可以用 $p$ 做加权。这组实验能回答图 7 那两条曲线是上界还是终点。

### 4. 把属性难度当自变量

构造一组属性，从与主任务正交（比如图片加了噪声）到比主任务更难（比如病理亚型），逐档量 F1 与加速比。这条曲线能定位攻击的失效点，也能解释 BreakHis 为什么掉得那么厉害。

### 5. 防御代价的帕累托表

把 $p$ 与 $\sigma$ 各扫一遍，每一档记录 F1、延迟、额外算力、主任务精度四个数，画出前沿。这张表防守方可以直接用，也能量出"隐私换毫秒"的实际兑换率。

这节要你记住的是，五条线索都指向同一件事，把检测与代价补齐。

※ 上面五条都是读完文章的即时联想，没有做实验，也没有查证过是否已有人在做，更没有验证过可行性。只当选题线索看，不要当结论用。

## 名词速查

| 词 | 一句话解释 |
|---|---|
| **多出口网络** | 在中间层挂若干分类器的网络，置信度够了就提前返回，省掉后面的层 |
| **出口** | 中间层上的一个分类头，带自己的预测和置信度 |
| **早退** | 某个出口的置信度越过阈值就停止推理，返回该出口的预测 |
| **置信度** | 该出口输出概率向量里的最大值 |
| **指定出口 T** | 攻击者挑出来承载属性的那个出口，默认取倒数第二个 |
| **目标属性** | 攻击者想推断的那条敏感信息，可以跟主任务无关 |
| **目标样本与非目标样本** | 带目标属性的输入，与不带目标属性的输入 |
| **one-hot 标签** | 真类为 1、其余为 0 的硬标签 |
| **标签平滑** | 把 1 降到 1 减 ε，把 ε 平摊给其余类别，压低输出置信度 |
| **软标签** | 标签平滑之后得到的那个分布，形式上像概率 |
| **交叉熵** | 衡量预测分布与标签分布差异的损失 |
| **熵** | 分布的不确定度，分布越尖越小 |
| **协方差** | 两个量的线性相关强度，负值表示一个变大时另一个变小 |
| **批均值** | 用一个 mini-batch 上的平均代替全集平均，是有偏估计 |
| **主任务** | 模型本来要做的那个分类，比如年龄预测或良恶性判定 |
| **隐蔽性** | 被操纵的模型在精度与加速比上与干净部署的接近程度 |
| **CSP** | 云服务提供商，这里一面是模型供应方，另一面是推理设施运营方 |
| **TEE** | 可信执行环境，用硬件把用户数据与云厂商的基础设施隔离 |
| **SGX** | 英特尔的一套 TEE 指令集，enclave 内的内存对宿主不可读 |
| **Occlum** | 一个在 SGX 上跑 Linux 应用的库操作系统，论文用它跑 PyTorch |
| **侧信道** | 不读数据本身，靠时间、功耗、缓存这类附带信息推断内容 |
| **时延** | 一次查询从提交到返回花的时间，这里唯一的观测量 |
| **出口号** | 这条输入实际停下的那个出口的编号 |
| **精度** | 停在指定出口的样本里真正带属性的比例 |
| **召回** | 带属性样本里停在指定出口的比例 |
| **F1** | 精度与召回的调和平均 |
| **加速比** | 整网浮点运算量除以多出口模型平均浮点运算量 |
| **KDE** | 核密度估计，把一维样本拟成若干峰的非参数方法 |
| **投毒** | 在交付前把模型权重改成对攻击者有利的样子 |
| **随机猜** | 基线之一，按固定 50% 概率猜每条输入带属性 |
| **频率法** | 基线之一，把带属性比例最高的出口当指示出口，其余判为不带 |
| **逻辑回归基线** | 基线之一，拿出口号当特征训一个二分类器 |
| **随机化退出** | 防御手段，达到阈值后以概率 p 才真的退出 |
| **哑计算** | 防御手段，退出后补一段随机计算，把时延与深度解耦 |
| **只给骨干** | 扩展场景，供应方只交付骨干，用户自己插出口 |
| **成员推断** | 判断某条样本是否在训练集里的攻击 |
| **属性推断** | 估训练集统计属性的攻击，比如某个敏感属性占多大比例 |
| **模型反演** | 从模型输出重建训练样本的攻击 |
| **威胁模型** | 一句话说清攻击者知道什么、能改什么、要得到什么 |
| **白盒与黑盒** | 前者能看权重和梯度，后者只能看输入与输出 |
| **自适应攻击** | 知道防御存在之后重新优化攻击，用来检验防御的上界 |
| **帕累托前沿** | 两个目标互相拉扯时，那些无法同时改进的点连成的曲线 |
