## 它想干什么

温室过道一米二宽，番茄叶子垂到镜头前。一台差速轮机器人沿垄走到头，转身时镜头正对白墙，画面里能用的特征点掉到个位数。ORBSLAM2 在这一刻跟丢，位姿不再更新，直到车退回有纹理的地方重新认出场景。中间那两秒，轨迹上是一段空白。

这段空白在导航里很要命。控制器还按上一帧的位姿往前开，两秒能走出八十厘米。加 IMU 是常规办法，麻烦在于 IMU 的零偏和重力方向得先解出来，而这一步依赖视觉连续工作十几秒。视觉正好在这时候断，初始化就无从谈起。

论文加的第三个传感器很朴素，两个驱动轮上的霍尔编码器。它读的是轮子转速，换算出来是车体的前进速度和转向角速度。它没有零偏这一类要在线上估的量，上电就能用，代价是只管平面上的三个自由度。

把轮速接进 BA 不是接根线就完事。轮子在一段时间里一直在转，这段转动累积出来的位移是一条弧，不是一个点。论文把 IMU 预积分那套推导搬到轮子上。预积分就是把两帧之间的高频测量提前积成一个相对运动量，省得优化时反复重算。搬完之后写出残差、雅可比和协方差递推，再把纯编码器的边接进 ORBSLAM2 的图里。

三个自建场景跑下来，ORBSLAM2 的估计时长只覆盖 39%、46%、21%，接上编码器之后是 100%。ATE 落在 2 到 7 厘米这一段，和 ORBSLAM2 基本打平，个别场景略差。这篇的分量不在刷精度，它解决的是另一件事，让系统在视觉断掉的那几秒里还有一条边连着。

## 一、问题背景

### 1.1 视觉为什么会在两秒里整段消失

特征点法的前提是画面里有能重复检测到的角点。白墙没有，逆光没有，运动模糊把角点糊成一条线之后也没有。Kinect v2 的彩色图在弱光下会自动拉长曝光，帧率从 30 掉到 15，掉帧又让相邻两帧之间的位移变大。

论文把失效原因列成五类，缺特征、光照差、运动快、帧率低、板子执行不稳。这五类只有一个共同后果，跟踪线程报不出位姿。ORBSLAM2 的处置是转进重定位，等重新认出场景再恢复。重定位要认出场景，就得先看得见东西。

墙角、门口、有贴纸的机柜，这些地方能救回来。整面白墙的过长廊道救不回来。

### 1.2 IMU 能补，但补不齐

IMU 给的是角速度和比力，两帧之间积分一次就得到相对运动，跟画面里有没有纹理无关。这条路线的代表是 VIORBSLAM，它在 ORBSLAM2 上加一层 IMU 预积分，再用一个分治式的初始化把尺度、重力方向、速度和零偏一次解出来。差别在这儿，那套初始化要求纯视觉先活够大约十五秒，零偏和重力方向才可观。视觉活不下来，初始化这一步就卡住。

同一族的还有几个系统。OKVIS 在关键帧上做非线性优化，把视觉重投影和 IMU 预积分放进同一个窗口。VINS-Mono 是单目紧耦合的优化型估计器，紧耦合的意思是把图像与惯性测量写进同一个问题里一起解，它的初始化同样要靠视觉先撑一段。文献 [11] 那条线用 EKF 做紧耦合的直接法，滤波器的状态里也没有轮速。这三条路的机制各不相同，共同点是尺度或者初始化全押在视觉上。

单目还有一层麻烦，起步时没有视差就定不出尺度，[6] 里专门讨论过这件事。双目能解，代价是两张图都要算一遍。这篇选 RGB-D，深度直接给米制尺度，图像那一侧只要算一张。

### 1.3 编码器这条路自己缺什么

编码器不是位姿传感器。它测的是轮子转多快，要经过轮半径、轮距、安装外参才能变成车体运动。中间任何一环错了，位移就跟着错。地面不平、轮胎打滑、标定偏一点，误差都会混进来。论文把这些统称成模型噪声，和编码器自身的白噪声分开建模。

论文写了他们走的弯路，这一段比结论有意思。第一版是把纯编码器的边直接塞进图里，视觉断掉时确实接得上，精度却掉得厉害，原因是这些边没有协方差。第二版才给编码器做预积分、推协方差、写雅可比。==先加一条没有权重的边，再补上它该有的权重，这个顺序很常见，肯写出来的不多==。

### 1.4 这篇的做法

机制一句话，把两轮转速当成一段弧的弦，预积分成两帧间的相对位姿残差，写进 BA。

取舍落在两条路之间。走重定位那条路，系统在断掉之后要重新认场景，认不出来的时间就是缺口，成本为零。走加传感器这条路，缺口被填上，代价是多了标定、多了残差项、多了把不准确的地图点引进来的风险。论文选后者。

可检验的推论有两条。若编码器边真的补上了视觉的空洞，累计有输出的时间跨度应当接近图像总跨度，估计比例也就该从三四成升到接近百分之百。第二条是精度不该因此崩掉，ATE 该留在厘米级。表 II 与表 III 里这两条都成立。

失效情形也清楚。车开上坡、轮子打滑、编码器安装外参标偏，弦这条假设就破了。模型噪声项能吸收一部分，吸收能力有上限，这一点放到第五节说。

> 📌 **控制视角**　这是一次可观性上的加法。纯视觉在少纹理时秩不够，加 IMU 补的是角速度和比力，可 IMU 自己带零偏，零偏又要靠视觉活够时间才可观，等于向一个还没准备好的传感器借力。编码器没有这个循环依赖，它的未知数里就没有零偏这一项，所以它能当那个先撑着的角色。判断一处融合值不值得做，可以先看两路的零空间有没有错开。编码器缺的是高度和姿态，视觉缺的是连续性。

这节要你记住的是，视觉的缺口要靠一个不带零偏的观测去补。

先说这条流水线原来长什么样。ORBSLAM2 有跟踪、局部建图、回环三条线程。跟踪线程逐帧估位姿，局部建图收关键帧，回环线程用词袋找相似帧。关键帧是从这些帧里挑出来的少数几张，只有它们进建图和优化。论文没有动这个骨架，加的是三处。

第一处是两个缓存线程。编码器和 IMU 各自缓存，跟图像帧做时间对齐，允许一定的对齐误差。超过这个误差，两个关键帧之间那段 IMU 数据直接丢掉。

第二处是纯编码器边允许进入生成树。生成树负责把修正过的位姿传播到全图关键帧，视觉断掉时它是唯一还在更新的通路。==编码器边的作用就在这儿，它还连着两个状态，视觉断了这两个状态也还被约束着==。

第三处是回环阈值的临时放宽。引入纯编码器边之后把回环检测的门限降下来，回环一触发再改回去。降了多少，论文没给数。

这节要你记住的是，改动只有三处，缓存、进树、放宽回环门限。

## 三、方法拆解

### 3.1 状态量与坐标系

四个坐标系先摆清楚。$W$ 是世界系，$B$ 是 IMU 系，$C$ 是相机系，$E$ 是编码器系，取在两个轮子的中心。传感器刚性固定，$\mathbf{T}_{BC}$ 与 $\mathbf{T}_{CE}$ 由先验标定给出，论文的做法是一次精心设计的测量，或者 Kalibr 一类的工具。

两套状态量对应两个系统。VEOS2 只用相机的 SE(3)。

$$
\mathbf{x}_i = \mathbf{x}_{\mathrm{WC}i} \doteq [\mathbf{p}_i, \mathbf{R}_i] = [\mathbf{p}_{\mathrm{WC}i}, \mathbf{R}_{\mathrm{WC}i}]
\tag{6}
$$

$\mathbf{T}_{\mathrm{WC}i}$ 把相机系里的点搬到世界系，由平移 $\mathbf{p}_{\mathrm{WC}i}$ 和旋转 $\mathbf{R}_{\mathrm{WC}i}$ 组成。每帧 6 个未知数。VEOS2 不吃 IMU，也就不需要速度和零偏。

VIEOS2 的状态量跟 VIORBSLAM 一样，挂在 IMU 上。

$$
\mathbf{x}_i = \mathbf{x}_{\mathrm{WB}i} \doteq [\mathbf{p}_i, \mathbf{R}_i, \mathbf{v}_i, \mathbf{b}_i], \qquad \mathbf{b}_i = [\mathbf{b}_i^{g}, \mathbf{b}_i^{a}]
\tag{7}
$$

$\mathbf{v}_{\mathrm{WB}i}$ 是该关键帧的速度，$\mathbf{b}_i^g$ 和 $\mathbf{b}_i^a$ 是陀螺与加速度计的零偏，各 3 维。每帧 15 个未知数。

被刻意排除的量有两个。编码器没有零偏项，模型噪声当成零均值高斯，状态里就不出现编码器的偏置。角速度 $\omega$ 也没有进状态，代价是不能在速度上挂编码器残差，这一条在 3.7 节展开。

现在算账。平面上的一台差速车只有三个自由度，$x$、$y$ 和偏航角。轮速模型把这三个方向全给了，滚转、俯仰、高度它一个都不给。落到方程上，一条编码器边在 $i$ 与 $j$ 之间产生 6 维残差，其中带独立信息的只有三个方向，另外三个方向被地面近似水平的假设压成近乎常量。

写成算式是这样。$N$ 帧、每帧 6 个未知数，共 $6N$ 个。编码器边有 $N-1$ 条，每条给 3 个独立方程，共 $3(N-1)$ 个。首帧位姿固定，再给 6 个约束。剩下的欠定方向是 $6N-3(N-1)-6=3(N-1)$ 个，正好对上每段的高度、滚转和俯仰。__这三个方向只能由图像补__，RGB-D 的一次观测给 3 个方程，对应 $u_L$、$v_L$ 和由深度换算出来的右图坐标，单目只给 2 个。

VIEOS2 的账不一样。每帧 15 个未知数，IMU 边给 9 个相对方程，旋转 3、位置 3、速度 3，再加 6 个零偏随机游走方程。编码器边仍然只补那 3 个平面方向。

最少需要几个观测，从纯编码器这一路看很清楚。两帧加一条边只够定相对位姿，整条链必须靠首帧钉住。要定绝对位姿，至少还要一帧视觉观测或者一条回环边。这也是为什么这套系统不能退化成纯编码器 SLAM。表 II 里纯编码器的 ATE 是 0.211 米和 0.639 米，带视觉的版本是 0.047 米和 0.069 米，差了四到九倍。

### 3.2 两个轮子的转速怎么变成 v 和 ω

编码器的读数就是两个轮心相对地面的速度，表达在编码器系里。

$$
\tilde{v}_{\mathrm{EE}}^{\mathrm{l}}(t) = v_{\mathrm{EE}}^{\mathrm{l}}(t) + \eta^{\mathrm{el}}(t), \qquad \tilde{v}_{\mathrm{EE}}^{\mathrm{r}}(t) = v_{\mathrm{EE}}^{\mathrm{r}}(t) + \eta^{\mathrm{er}}(t)
\tag{12}
$$

上标 $\mathrm{l}$ 和 $\mathrm{r}$ 是左右轮，$\eta^{\mathrm{el}}$ 与 $\eta^{\mathrm{er}}$ 是零均值白噪声，协方差 $\boldsymbol{\Sigma}_e \in \mathbb{R}^{2\times 2}$。

从两轮速度到车体运动，用的是差速轮的模型。

$$
v(t) = \frac{v_{\mathrm{EE}}^{\mathrm{l}}(t) + v_{\mathrm{EE}}^{\mathrm{r}}(t)}{2}, \qquad \omega(t) = \frac{v_{\mathrm{EE}}^{\mathrm{r}}(t) - v_{\mathrm{EE}}^{\mathrm{l}}(t)}{2 r_c}
\tag{14}
$$

$v$ 是两个轮速的平均，方向朝车头。$\omega$ 是两个轮速之差除以轮距，$r_c$ 是半轮距，所以分母是 $2r_c$。这一式的前提是不打滑，转向瞬心落在两轮轴线上。整段推导还额外要求两帧之间的运动近似落在一个平面上。

有了 $v$ 与 $\omega$，运动学写成两条微分方程。

$$
\dot{\mathbf{R}}_{\mathrm{E}i\mathrm{E}} = \mathbf{R}_{\mathrm{E}i\mathrm{E}} \, \boldsymbol{\omega}_{\mathrm{EE}}^{\wedge}, \qquad \dot{\mathbf{p}}_{\mathrm{E}i\mathrm{E}} = \mathbf{v}_{\mathrm{E}i\mathrm{E}}
\tag{13}
$$

下标 $\mathrm{E}i\mathrm{E}$ 的意思是，把 $t_i$ 时刻的编码器系当成参考，看之后的编码器系怎么动。旋转那一条可以直接积分成指数映射，位置那一条要沿时间积，麻烦就出在这儿。

噪声有两层，缩放的规矩相反。编码器白噪声是连续谱噪声除以采样间隔，$\boldsymbol{\Sigma}_{\mathrm{ed}} = \boldsymbol{\Sigma}_e / \Delta t$。模型噪声随时间跨度线性增长，$\boldsymbol{\Sigma}_{\mathrm{emd}} = \Delta t \, \boldsymbol{\Sigma}_{\mathrm{em}}$，论文把它当成布朗运动处理。采样密了，前一项变大，后一项变小，两个方向拉着跑。

### 3.3 一步位移是弧的弦

一步之内，旋转是确定的，位置不是。

$$
\mathbf{R}_{\mathrm{E}i\mathrm{E}}(t+\Delta t) = \mathbf{R}_{\mathrm{E}i\mathrm{E}}(t)\,\mathrm{Exp}\big(\boldsymbol{\omega}_{\mathrm{EE}}(t)\Delta t\big)
\tag{15}
$$

位置那一半要积 $\int_t^{t+\Delta t} \mathbf{R}(s)\mathbf{v}(s)\,ds$。车在这一步里转了一个角度，速度方向也跟着转，积出来的不是直线。把 $\omega$ 与 $v$ 在 $\Delta t$ 内当常数，积分能解析积出来。

$$
\Delta\tilde{\mathbf{p}}_{t,t+\Delta t} \approx \tilde{v}_t\Big[\,S_{\tilde{\omega}_t,\Delta t}\ \ C_{\tilde{\omega}_t,\Delta t}\ \ 0\,\Big]^{\mathrm{T}} - \boldsymbol{\varepsilon}_{t,\Delta t}^{\mathrm{p}}
\tag{19}
$$

$S_{\omega,s}=\sin(\omega s)/\omega$，$C_{\omega,s}=(1-\cos(\omega s))/\omega$，$\boldsymbol{\varepsilon}^{\mathrm{p}}$ 是这一步的平移噪声。==这一步的位移是弦，不是轮子滚过的弧长==。弦长 $2R\sin(\omega\Delta t/2)$ 永远小于弧长 $R\omega\Delta t$，$R=v/\omega$ 是转弯半径。

$\omega$ 趋于零时两项都退化，$S$ 趋于 $\Delta t$，$C$ 趋于零，式子回到沿 $x$ 轴走 $v\Delta t$。所以位置这一支是积出来的，几何上就是圆弧的弦，没有在 $\omega$ 上做小角度展开。论文强调自己给的是平面分段假设下的精确结果，[17] 给的 IMU 预积分是近似解。

### 3.4 把整段折成一个预积分量

两帧之间有很多个 $\Delta t$。逐个叠起来，旋转连乘，位置逐段转轴后累加。

$$
\mathbf{R}_{\mathrm{E}i\mathrm{E}j} \approx \prod_{k=i}^{j-1}\mathrm{Exp}\big(\tilde{\boldsymbol{\omega}}_k\Delta t\big)\mathrm{Exp}\big(-\boldsymbol{\varepsilon}_{k,\Delta t}^{\mathrm{R}}\big), \qquad \mathbf{p}_{\mathrm{E}i\mathrm{E}j} \approx \sum_{k=i}^{j-1}\mathbf{R}_{\mathrm{E}i\mathrm{E}k}\Big(\tilde{v}_k\big[S\ \ C\ \ 0\big]^{\mathrm{T}} - \boldsymbol{\varepsilon}_{k,\Delta t}^{\mathrm{p}}\Big)
\tag{20}
$$

预积分的意义在于相对量不随线性化点变。定义 $\Delta\mathbf{R}_{\mathrm{E}i\mathrm{E}j}=\mathbf{R}_{\mathrm{E}i\mathrm{E}i}^{\mathrm{T}}\mathbf{R}_{\mathrm{E}i\mathrm{E}j}$ 之后，这两个量只跟测量有关，优化过程中状态怎么改都不用重积分。这一步跟 [17] 的动机完全一样。

$$
\tilde{\theta}_{\mathrm{E}i\mathrm{E}j} = \sum_{k=i}^{j-1}\tilde{\omega}_k\Delta t, \qquad \Delta\tilde{\mathbf{R}}_{\mathrm{E}i\mathrm{E}j} = \mathrm{Exp}\big(\tilde{\boldsymbol{\theta}}_{\mathrm{E}i\mathrm{E}j}\big)
\tag{23}
$$

位置的迭代式写成下面这样，这就是能在代码里直接循环的形式。

$$
\Delta\tilde{\mathbf{p}}_{\mathrm{E}i\mathrm{E}j} = \Delta\tilde{\mathbf{p}}_{\mathrm{E}i\mathrm{E}j-1} + \frac{\tilde{v}_{j-1}}{\tilde{\omega}_{j-1}}
\begin{bmatrix}
\sin\tilde{\theta}_{\mathrm{E}i\mathrm{E}j} - \sin\tilde{\theta}_{\mathrm{E}i\mathrm{E}j-1}\\
\cos\tilde{\theta}_{\mathrm{E}i\mathrm{E}j-1} - \cos\tilde{\theta}_{\mathrm{E}i\mathrm{E}j}\\
0
\end{bmatrix}
$$

前两行的正弦差与余弦差，几何上就是弦的两个端点相减，跟示意图 B 是同一件事。这一支解在 [22] 的式 (5.9) 里出现过，但那本教材没有配现在这套噪声模型。

### 3.5 残差与位姿预测

把式 (23) 与式 (24) 带回定义，残差就成型了。

$$
\mathbf{e}_{\mathrm{R}} = \mathrm{Log}\big(\Delta\tilde{\mathbf{R}}_{\mathrm{E}i\mathrm{E}j}^{\mathrm{T}}\mathbf{R}_{\mathrm{E}i\mathrm{E}j}\big), \qquad \mathbf{e}_{\mathrm{p}} = \mathbf{p}_{\mathrm{E}i\mathrm{E}j} - \Delta\tilde{\mathbf{p}}_{\mathrm{E}i\mathrm{E}j}
\tag{25}
$$

$\mathbf{r}_{Eij}=[\mathbf{e}_{\mathrm{R}}^{\mathrm{T}}\ \mathbf{e}_{\mathrm{p}}^{\mathrm{T}}]^{\mathrm{T}}$ 是 6 维的。$\mathrm{Log}(\cdot)$ 把旋转矩阵拉回旋转向量，限制在 $\|\theta\|\le\pi$。$\mathbf{p}_{\mathrm{E}i\mathrm{E}j}$ 与 $\mathbf{R}_{\mathrm{E}i\mathrm{E}j}$ 由状态 $\mathbf{x}_i$ 经先验标定 $\mathbf{T}_{BC}$、$\mathbf{T}_{CE}$ 变换得到。

预测顺手就有。

$$
\hat{\mathbf{T}}_{\mathrm{E}i\mathrm{E}j} = \begin{bmatrix}\hat{\mathbf{R}}_{\mathrm{E}i\mathrm{E}j} & \hat{\mathbf{p}}_{\mathrm{E}i\mathrm{E}j}\\ \mathbf{0}_{1\times3} & 1\end{bmatrix}, \qquad \mathbf{T}_{\mathrm{WC}j} = \mathbf{T}_{\mathrm{WC}i}\,\mathbf{T}_{\mathrm{CE}}\,\hat{\mathbf{T}}_{\mathrm{E}i\mathrm{E}j}\,\mathbf{T}_{\mathrm{CE}}^{-1}
\tag{26}
$$

这条链在视觉断掉时就是唯一的初值来源，也是图 1 上那个 <b>Pose Prediction</b> 框在干的事。

被优化的量是位姿，三件套齐一下。初值来自上一帧位姿左乘编码器预积分，视觉活着时还可以用运动模型或者重定位结果。驱动它的残差有三类，重投影式 (8)、IMU 式 (10)、编码器式 (25)。兜底有两层，一是滑窗里被固定住的那批状态，二是先验项 $\mathbf{r}_0$，代码里只作用在窗口最后一帧上，做法跟 [16] 一致。

### 3.6 噪声怎么传

噪声递推是线性的，写成矩阵就是一式。

$$
\boldsymbol{\eta}_{Eij} = \mathbf{A}_{j-1}\boldsymbol{\eta}_{Eij-1} + \mathbf{B}_{j-1}\boldsymbol{\eta}_{j-1}^{\mathrm{ed}} + \mathbf{D}_{j-1}\boldsymbol{\eta}_{j-1}^{\mathrm{emd}}
\tag{29}
$$

$$
\boldsymbol{\Sigma}_{Eij} = \mathbf{A}_{j-1}\boldsymbol{\Sigma}_{Eij-1}\mathbf{A}_{j-1}^{\mathrm{T}} + \mathbf{B}_{j-1}\boldsymbol{\Sigma}_{\mathrm{ed}}\mathbf{B}_{j-1}^{\mathrm{T}} + \mathbf{D}_{j-1}\boldsymbol{\Sigma}_{\mathrm{emd}}\mathbf{D}_{j-1}^{\mathrm{T}}
\tag{30}
$$

$\mathbf{A}$ 传的是上一刻的累计噪声，$\mathbf{B}$ 传编码器白噪声，$\mathbf{D}$ 传模型噪声，初值 $\boldsymbol{\Sigma}_{Eii}=\mathbf{0}_{6\times6}$。$\mathbf{B}$ 里带一个 $1/(2r_c)$ 的因子，轮距越窄，同样的轮速差被放大成更大的角速度噪声。

### 3.7 怎么接进图里

目标函数是四项相加，每一项都用 Huber 核 $\rho$ 压外点。

$$
\mathrm{X}_k^{*} = \arg\min_{\mathrm{X}_k}\ \|\mathbf{r}_0\|_{\Sigma_0}^2 + \sum_{i\in \mathrm{K}_k}\sum_{l\in C_i}\|\mathbf{r}_{\mathbf{z}_{il}}\|_{\Sigma_{\mathbf{z}_{il}}}^2 + \sum_{(i,j)\in \mathbf{K}_k}\Big(\|\mathbf{r}_{I_{ij}}\|_{\Sigma_{I_{ij}}}^2 + \|\mathbf{r}_{E_{ij}}\|_{\Sigma_{E_{ij}}}^2\Big)
\tag{5}
$$

前两项是重投影，第三项是 IMU，最后一项是编码器，$\|\mathbf{r}\|_{\Sigma}^2=\rho(\mathbf{r}^{\mathrm{T}}\Sigma^{-1}\mathbf{r})$。

全 BA 里还多一个公共变量，名字就叫尺度。论文只说它能带来更好的结果，尤其在 EuRoC 上，没有交代它怎么初始化，也没有给先验。

### 3.8 图优化里的协方差赋值

纯编码器边要进位姿图（只优化位姿、不碰地图点的那种图），得有一个协方差，而编码器本身给不出这个量。论文的做法是一句话，先在所有纯编码器边里找出最小协方差，假设它能达到一条用图像观测的边的精度，再按这个基准给每条边定相对协方差。__协方差越大的边，在优化里被改得越多__，因为它的误差大，本来就该被拉回来。

另外加了一条限制，连续多条纯编码器边不许引入太多不准确的地图点。回环阈值先降后升，二节说过。

这套赋值是启发式的，没有一个从数据里估出来的过程。第五节会回到这一点。

### 3.9 初始化谁给尺度

RGB-D 的深度直接给米制，尺度这一格不用估。这是它比单目省事的地方，也是它第一帧就能出位姿的原因。

VIEOS2 的 IMU 初始化沿用 VIORBSLAM 的分治做法，要求是一样的。差别在于纯编码器边让这段初始化在视觉断掉时还能继续推进，论文把这一条列进了设计的收益里。

重力方向来自加速度计，在 IMU 初始化里解。编码器不给重力，它压根没有这个量。

初值链条串起来是这样。关键帧位姿由上一帧乘编码器预积分给，速度与零偏由 IMU 初始化给，尺度由深度给，三样拼起来就是优化的起点。视觉断掉时，链条上少的是 IMU 那一环，剩下两环还在。

※ 公式编号沿用论文原编号。本文没有展示的编号，需要时回原文对照。

这节要你记住的是，编码器只约束平面三个方向，其余靠视觉补。

## 五、局限

论文自己承认的有六条。

户外那一段没有真值。原文写的是没有测量户外序列真值，鲁棒性可以从估计比例看出来，精度只能拿 VEOS2 与纯编码器轨迹做定性对比，理由是这类场景该走成一个回环，终点要回到起点附近。

采样率是硬要求。原文说 7/15 Hz 数据集的同步误差更大、频率更低，误差明显大于 15/200 Hz 那套，所以在实际应用里必须用高频测量。

精度是拿来换的。原文写 VIOS2 与 ORBSLAM2 通常比 VEOS2 与 VIEOS2 略准，原因就是后两者引入了纯编码器边，而这条边同时带来误差和鲁棒性。

点云图有冗余。原文写由于纯编码器边带来的误差，点云里还能看到一些多余的部分，可以靠更多回环、更多图像观测和更好的先验标定来减少。栅格地图那一步，论文留给以后。

误差项可能换成滤波。原文用的是 may，设想把编码器与 IMU 的误差项换成一个更复杂的滤波误差项，好让平面假设只需要在两帧之间成立，而不是在两个关键帧之间成立。

与 ROS 导航节点的接口还没做。

以下是编者补充，论文未将其列为局限。

平面与无滑动这两个前提，论文在方法一节里写明是假设，没有放进局限清单。这套推导的全部几何都建立在"两帧之间近似落在一个平面上"之上，坡地、门槛、地毯边缘都会破坏它。

运动速度压得很低。数据集里最大速度约 0.4 米每秒，最大角速度约 0.8 弧度每秒，这个量级下平面假设很容易成立。机器人跑快之后这套假设还剩多少余量，论文没有测。

没有消融。纯编码器边的协方差赋值、连续多边不许引入太多地图点这条限制、回环阈值下调，==三处都只有描述，没有哪一处被单独拿掉过==。哪一处真的在起作用，从现有数据看不出来。

基线只有 ORBSLAM2 与自家几个变体。行进中常用的 VINS 系、OKVIS 系没有进对比，EuRoC 上那组数字是引用别人论文的发表值，不是在同一台机器上重跑。

数据规模也不大。三段自建序列，覆盖一间实验室、一条走廊、一小块农田，图上的时间轴到 60 秒。**在大场景里连续跑十几分钟，这套系统的回环和漂移表现没有数据。**

这节要你记住的是，它承认的都是口径与假设上的软肋。

## 六、我的评价

做得对的地方，头一条是把弯路写出来了。先加一条没有协方差的纯编码器边、发现精度掉下来、再回头补预积分，这个顺序比直接给终版方案有用。读的人能看见设计是怎么被问题逼出来的，而不是看一份成品清单。

第二条是推导给全了。论文明确说 [17] 没有给清晰的迭代形式，而它给了，还给了协方差递推的 $\mathbf{A}$、$\mathbf{B}$、$\mathbf{D}$ 三个矩阵和两套雅可比。==对着这三样能直接把代码写出来，这是工程论文该有的样子==。代码和数据也开源了，还专门造了一套带编码器信息的数据集。

第三条在做法上。先用 EuRoC 证明自家 VIOS2 的实现水平与发表值相当，再在自建数据上比。这一步很关键，否则自建数据上的任何优势都可以被一句"你的基线没调好"消掉。

存疑的地方也有几处。协方差赋值那条策略是整篇里最薄的一环，靠"假设最小的那条纯编码器边能达到视觉边的精度"来定基准，这个假设本身没有验证。==位姿图里的边权重直接决定优化结果，这里却是拍出来的==。

走廊里 VIOS2 只有 34% 的覆盖率，比不带 IMU 的 ORBSLAM2 低十一个百分点，论文一句解释都没有。我的猜测是引入 IMU 之后关键帧判定和滑窗外推的行为变了，视觉断掉时 IMU 外推把位姿推得很远，重新看见时反而更难过重投影门限。这只是猜测，原文没有支持。

两套数据的对比也不完全对等。7/15 Hz 那套用 imwrite 加轮询记录，多传感器同步误差可能到 1/15 秒，15/200 Hz 那套用 rosbag 加缓冲，串口延迟约 5 毫秒。两套记录条件之间的精度差里就混着记录方式的影响，不只是采样率这一项。

它想走去哪儿，论文末尾给了两条，误差项换成滤波、接上 ROS 导航。这两条都是工程收尾，不算新方向。

这节要你记住的是，推导给得实在，边的权重定得草率。

## 七、可以接着做什么

### 1. 把平面假设换成在线判据

现在的编码器残差全部依赖"这两帧之间近似在一个平面上"。可以直接把这条假设改成可检测的量。用 IMU 的重力方向估出地面法向，再用轮速积分出来的位移与该法向的夹角做判据，坡度超过阈值就把编码器残差的协方差放大，或者干脆降级成只约束偏航。

这个改法的好处是==把一个硬假设变成一条软的权重曲线==。代价是多了一个要调的阈值，而且坡道上精度还是会掉。

### 2. 用打滑检测给编码器边加一道闸

轮子打滑时弦这条假设直接破，残差会变成一个巨大的外点。Huber 核能压住一部分，但它压的是数值，不是物理。可以加一层显式的检验，把轮速积分出来的位移与视觉位姿的变化量做差，超过若干倍新息标准差就判打滑，这段时间的编码器边降权或者标记为不可信。

这跟卡尔曼滤波里用新息协方差做门限是同一套思路。区别在于这里没有现成的协方差，得用滑动窗口里的残差统计去估。

### 3. 把协方差赋值换成从数据里学

论文用"最小协方差乘一个相对系数"这套启发式给纯编码器边定权。可以直接改成用数据标定，让机器人在同一段路上分别跑纯视觉和纯编码器，统计两种边残差的协方差比，把这个比当成先验写进配置。

如果能拿到不同地面、不同速度下的这个比值，就能做成一张按场景切换的表。这比一个固定的相对系数可信得多。

### 4. 让轮速去收窄回环搜索

回环检测现在的候选来自词袋，范围靠距离和时间窗粗筛。轮速积分能给一个相当准的短时相对位姿，用它把候选帧的位姿先验往前推一步，可以把搜索范围收窄，也可以用来给几何校验提供一个初值。

这条的价值在长走廊和重复纹理的场景里最大，那里词袋最容易给出错误的候选，而轮速在几百毫秒内的相对位移是可靠的。

这节要你记住的是，下一步该往假设最软的地方使劲。

## 名词速查

| 词 | 一句话解释 |
|---|---|
| **编码器** | 测轮子转速的传感器，本文用的是无刷电机里的霍尔元件 |
| **差速轮** | 两个驱动轮各转各的，靠转速差转向的底盘 |
| **预积分** | 把两帧之间的高频测量提前积成一个相对运动量，省得优化时反复重算 |
| **弦** | 一段圆弧两端连起来的直线，是本文里一步位移的真实形状 |
| **轮距** | 两个驱动轮之间的距离，本文用 $2r_c$ 表示 |
| **零偏** | 传感器静止时读数不为零的那部分系统性偏差，会缓慢漂移 |
| **紧耦合** | 把各类测量写进同一个优化问题里一起解，而不是先算里程计再融合 |
| **纯编码器边** | 只用轮速测量连接两个关键帧位姿的约束，视觉断了它还在 |
| **VEOS2 与 VIEOS2** | 本文在 RGB-D ORBSLAM2 上的两个变体，前者只加编码器，后者编码器与 IMU 都加 |
| **重定位** | 跟丢之后靠认出场景把位姿接回来的流程 |
| **关键帧** | 被选出来参与建图和优化的图像帧，不是每一帧都算 |
| **局部 BA** | 只优化滑动窗口内关键帧与地图点的光束法平差 |
| **全 BA** | 优化整张地图所有关键帧与地图点，通常在最后跑一次 |
| **位姿图** | 只优化位姿不优化地图点的图优化，跑得快 |
| **生成树** | 负责把修正后的位姿传播到全图关键帧的一条连通结构 |
| **协方差** | 描述一个量有多不确定的矩阵，权重就是它定的 |
| **Huber 核** | 残差小时按平方算，大时改成线性，压外点用 |
| **秩** | 独立方程的个数，和方程总数不是一回事 |
| **可观性** | 某个状态能不能从观测里解出来，由系统结构决定 |
| **尺度** | 轨迹的绝对大小，单目要从 IMU 或别的观测里解，RGB-D 由深度直接给 |
| **估计比例** | 累计有输出的时间跨度除以图像总跨度，本文的主指标 |
| **ATE** | 绝对轨迹误差，估计轨迹与真值对齐后的均方根偏差 |
| **Horn 对齐** | 用闭式解求两组三维点之间的刚体变换，用来对齐两条轨迹 |
| **ORBSLAM2** | 开源的视觉 SLAM 系统，本文所有变体都以它为骨架 |
| **VIORBSLAM** | 在 ORBSLAM2 上加 IMU 预积分的版本，本文的主要对照 |
| **RGB-D** | 同时输出彩色图和深度的相机，本文用的是 Kinect v2 |
