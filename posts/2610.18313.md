## 它想干什么

产线上的一台边缘盒子同时跑着好几个 AI 服务。一个扭矩控制模型，一两个视觉质检，一个预测性维护例程，再加一个遥测采集。它们共用同一块 CPU、同一段内存、同一条网络。网络一堵，这些服务不会崩。它们照旧往外吐结果，只是结果不再对应现场的真实情况。

论文把这类情形叫静默的部分失效。从外面看系统是正常的，进程都在，接口都在回数据。失效要等到一个缺陷漏过去、一条线停下来、某个控制指令落在不再可信的推理上，才会显形。

已有的监控抓不到它。看门狗和编排层盯的是容器活着没有、CPU 和内存用了多少，盯不出一次输出错到会造成物理后果。==它们逐个服务地看，几个服务一起变慢时，没有一把尺子能把它们排成一队==。这篇要做的就是这把尺子。

它的答案叫运行时关键度分数，简称 RCS。每个服务被当成一个有自己输入、输出和存活紧迫度的 agent，每个监控周期算一个分。分由六个已归一化到零到一的维度加权求和。权重每一轮都在变，取值从几套模板在线混合出来，换哪一套取决于此刻推断出的扰动类型，网络拥塞、热节流还是内存压力。

分数算出来给谁用。agent 把分发布到一条点对点的发现通道上，同伴之间据此协商三件事。一是在本机执行阈值响应，二是当本机护不住它时迁到愿意接收的同伴那里，三是当协调者自己受损时把协调角色交出去。整个过程没有中心控制器。

先把预期放平。论文只有四页，是一篇框架性文章，硬件实验、实测曲线和一个跑出来的延迟数字都没有。它自己在讨论部分写明，注入网络、热和内存压力的完整硬件评估还是下一步。所以下面读到的所有机制都是设计承诺，公式是完整的，数字是缺的。这一点决定了这篇稿子能给什么，不能给什么。

**这节要你记住的是，一台盒子上多个服务一起变坏，缺的是一把横向排序的尺子。**

## 一、问题背景

### 1.1 物理过程与回路在哪一段

被监测的对象是产线上一台算力有限的边缘设备，上面跑的是控制模型、视觉质检、预测性维护和遥测采集。它们的计算共用一份 CPU 和内存，往外通信共用一条网络链路。控制模型直接指挥执行器，视觉质检给零件打标，维护例程出评分，遥测只管上报。

时间尺度上，论文给出的基本单位是控制周期。它说框架要回答的问题是，在争用中的设备上，哪个 agent 下一个控制周期里最输不起。__执行器一旦收到基于过期输入的指令，物理后果当场发生__。安全关键类 agent 直接驱动执行器，它们的降级可以立刻造成伤害。

==信息层在这里插在测量和决策之间==。传感器数据要先经过这条共享链路和共享算力，才能进到某个 agent 的推理里。链路一堵，数据晚到；算力被抢，推理变慢。两者都不改变 agent 的代码，只改变它拿到的东西有多新、算出来的东西有多准。论文明确写了，网络拥塞、热节流、内存压力是从网络延迟、CPU 温度和本地队列深度反推出来的，这三个量都是设备自己能观测的。

### 1.2 为什么难

难点在于几个服务同时退化时，缺少一个共同的度量把它们摆在一起比。进程还活着，接口还在回数据，任何单服务的健康检查都会判它正常。

第二条难点是每个服务的退化原因不一样。网络堵了，受害最重的是那些输入更新频繁、时间敏感的服务。CPU 被热压降频了，受害最重的是推理耗时长的服务。同一时刻这两种情况可能同时存在于不同设备上，甚至存在于同一台设备的不同服务之间。

第三个难点出在坐标上。物理后果的严重度和软件指标的单位不一样，一个是伤害，一个是毫秒和百分比。论文的处理方式是归一化，==六个维度都在注册时映射到零到一==。

### 1.3 耦合机制是哪一个

L1 栏目要问的是，延迟、采样、丢包、量化、通信约束里，具体哪一个在起决定作用。这篇的答案是输入新鲜度，也就是数据从传感器到推理之间过了多久。

论文没有做丢包分析，也没有给排队模型。它把耦合写成一条时限，注册时每个 agent 自己声明最大可容忍输入年龄，超过这条线，它给出的推理就不该被采信。IFR 这个维度量的就是输入相对这条线的陈旧程度。

这条写法的后果很直接。链路拥塞先变成输入变旧，输入变旧先变成推理不可信，推理不可信再变成执行器收到错的动作。中间没有一道硬闸门拦着，服务会继续输出。==服务不会崩，所以监控看不见它==。

论文没有给控制周期的具体数值，也没有给输入年龄到后果之间的传递函数。这套机制的时间基准是空的，判断硬实时可行性还缺最关键的一个数。

### 1.4 前人两条路各自缺什么

一条路是边缘编排与监控。KubeEdge 把云上的编排能力接到边缘，用容器的方式管资源；一篇雾与边缘资源管理的综述把这类架构、基础设施和算法摊开讲了一遍。这类系统盯的是容器活着没有和资源用了多少。它们在单服务层面上判得准，判不出一行错的控制指令和一行错的建议之间有什么区别，也没有跨服务的排序。

另一条路是推理层面的自适应。Edgent 按当前带宽给单条设备上的 DNN 推理管线做联合优化，让推理跟着网络波动伸缩。它做得比编排层细，落到模型的分区和退出策略上，代价是每个服务各调各的模型，服务之间还是不存在权衡。

第三条视线来自分布式系统。Raft 做的是让多个节点对同一份日志达成一致，leader 挂了重新选一个；epidemic 算法讲的是用传染的方式把更新传遍整个副本集合。这些解决的是"谁说了算"和"状态怎么传"，前提是大家先对同一个共享状态有一致的认识。这篇要问的是另一个问题，多个服务一起退化时谁先被保护。

## 二、总体结构

### 2.1 三个区

论文把部署分成三个区，云端、工业边缘区和现场区。云端只负责分发模型更新和配置，不参与运行时决策。__所有运行时协调都发生在工业边缘区__，单台设备跑一个或多个 agent，外加一层薄协调子层，负责本地算分、跟同伴交换、在阈值越界时动作。同一时刻有一台设备担任协调者角色，每台同伴都存着足够的状态以便接管。现场区是传感器和执行器所在的地方。

### 2.3 处理类别决定响应力度

注册的时候，agent 要声明四样东西，这四样基础设施自己推不出来。工作负载类型、降级输出的物理后果严重度、仍然可信的最大输入年龄，以及本机可以代它执行哪些保护动作。协调者据此把它分进三个处理类别。

安全关键类直接驱动执行器，降级可以造成立刻的伤害。监督类隔着一层影响工艺结果。分析类的输出是建议，是资源紧张时最先被让掉的那一类。__这个类别同时决定阈值参数和 RCS 计算的基础权重__。==控制高压阀门的 agent 和只会建议设定值调整的 agent 不会被同样对待==。

**这节要你记住的是，分区分三层做，分数跨设备共享，类别决定响应力度。**

## 三、方法拆解

### 3.1 六个维度怎么合成一个分

对每个已注册的 agent $s$，RCS 是六个归一化维度的加权和，每个监控周期算一次。

$$\mathrm{RCS}_{s}(t) = \sum_{i=1}^{6} w_{i}(t)\, d_{i,s}(t). \tag{1}$$

$d_{i,s}(t)$ 是 agent $s$ 在 $t$ 时刻第 $i$ 个维度的归一值，取值落在零到一之间，注册时就完成归一。$w_i(t)$ 是这一维当前的权重，随主机上观测到的扰动类型在线变化。$\mathrm{RCS}_s(t)$ 就是这一个标量，同伴之间比大小的依据只有它。

六个维度各自管一件事。PCS 是物理后果严重度，指降级输出在物理上会造成多大危害。IFS 是推理质量相对该 agent 自己基线分布的漂移。IFR 是输入相对注册时声明的新鲜度上限有多陈旧。HAS 是这台设备最近的争用压力历史。ACD 是执行器耦合深度，到阀门只有一跳的路径比许多跳的管线得分高。DCD 是设备剩余控制深度，指主机把可用的隔离和限流手段用掉之后还剩多少余地。

论文给这六个维度的选择写了理由。它们横跨从传感器输入到物理输出的整条因果链，后果、模型状态、输入新鲜度、主机压力历史、执行器耦合、剩余保护余地各占一段。这套说法是设计辩护，论文没有给维度之间的相关性分析，也没有证明这六个维度够用。

**这节要你记住的是，六个物量被压成一个标量，同伴只比这一个数。**

### 3.2 权重怎么跟着扰动走

权重的模板有三套，一套对一个扰动类型。论文说这三个类型覆盖了共享边缘部署里观察到的主要失效模式，并且分类表是可配置的，部署方可以自己加类型。

令 $c$ 取 network、thermal、memory 之一，表示当前生效的扰动类型。观测向量写成

$$o_t = (l_t, \tau_t, q_t), \tag{2}$$

$l_t$ 是网络延迟，$\tau_t$ 是 CPU 温度，$q_t$ 是设备上还没处理的消息条数。刷新周期论文没有写。

每台设备的协调层维护一个关于扰动类型的贝叶斯后验。

$$p(c \mid o_t) \propto p(o_t \mid c)\, p(c). \tag{3}$$

这个式子说的是，在观测到 $l_t$、$\tau_t$、$q_t$ 的条件下类型为 $c$ 的概率，正比于该类型下出现这组观测的似然乘以类型先验。论文没有给似然函数的形式，也没有给先验怎么初始化。

当前生效的权重向量取模板与后验的加权混合。

$$w(t) = \sum_{c} p(c \mid o_t)\, w^{(c)}. \tag{4}$$

$w^{(c)}$ 是扰动类型 $c$ 对应的权重模板，部署时固定，来自一次短标定运行里的估计。论文把 $w(t)$ 叫做后验加权混合，也就是三套模板按概率凸组合。后验之和为一，所以权重之和也为一。

方向上有两个例子。==网络延迟下 $w_{\mathrm{IFR}}$ 上升，因为数据发旧成了主要威胁==。热节流下 $w_{\mathrm{IFS}}$ 和 $w_{\mathrm{DCD}}$ 上升。同一个服务在两种工况下会被排到不同的位置，这就是这套权重在线调整的用处。

**这节要你记住的是，扰动类型决定哪几个维度被放大，排名随工况换向。**

### 3.3 自由度账本

这一段专门数未知量。按契约的要求，凡是出现"估计"或"求解某个量"的地方，要把未知数、每个观测源最多给几个独立方程、最少需要几个观测都写出来。

先说单个时刻的打分。第 $s$ 个 agent 在 $t$ 时刻有六个维度值是未知的，RCS 只给一个方程。

$$\#\{\text{未知数}\} = 6, \qquad \#\{\text{方程}\} = 1, \qquad 6 - 1 = 5.$$

单轮之内对六个维度做可辨识性分析是没意义的，因为 RCS 的定义本来就不是要反解出 $d_{i,s}$。它的用途是把这六个已知量压成一个能比大小的标量。六个维度由各自的传感器和统计流程直给，不经过这个方程反演。

再说权重这一侧。模板矩阵 $w^{(c)}$ 有六个维度乘三个扰动类型，共十八个分量，每行和为一，独立参数十二个。论文只对其中两行给了方向，网络那一行的 IFR 分量升，热那一行的 IFS 和 DCD 分量升。另外十来个独立参数，论文一个都没给。

最后说扰动分类。在 $t$ 时刻未知的是三类后验，加起来等于一，所以独立未知数两个。

$$\#\{\text{未知数}\} = 3 - 1 = 2, \qquad \#\{\text{观测源}\} = 3, \qquad \text{每个源最多 } 1 \text{ 个独立方程}.$$

三个观测量各算一个独立方程，前提是它们之间不退化。最少需要几个观测取决于要分开几类。两类只要有一个能把它们分开的观测就够。三个扰动类型至少要两个独立分量，因为三类后验落在二维的概率单纯形上，一个数标不出一个点。三个观测源都在的时候，多出来的那一维只用来做冗余校验。

这套贝叶斯更新没有迭代求解，没有循环，后验就是一步乘除。所以这里不需要初值从哪来的讨论，只需要说明论文把似然和先验都留在了外面。

**这节要你记住的是，六维取值靠传感器直给，权重靠模板与后验混合。**

### 3.4 阈值响应怎么分级

阈值按处理类别参数化，一共三档。

低档越界触发本地资源保护，论文举的例子是 CPU 预留，也就是把算力先划一块给这个 agent。

中档越界通知操作员，连同当前分数和贡献最大的那几个维度一起报上去。

高档越界启动安全状态切换。低优先级的 agent 可能被挂起，受影响的 agent 切到降级但安全的模式，或者迁到同伴设备上。每一条响应都挂在同一个分数和同一个类别上，论文的原话是行为因此成比例而且可追溯。

**这节要你记住的是，分是六个维度的加权和，权重由扰动类型当场决定。**

### 3.5 外部方法差在哪

外部系统里最关键的一条差异在这里说清。前面已经分散交代了 KubeEdge、Edgent、Raft 和 epidemic 各自的做法与短板，服务迁移那一线还缺一句。

服务迁移这条线本身有成熟的形式化。Wang 等人的动态服务迁移把移动边缘云里的迁移写成一个马尔可夫决策过程，状态是用户与设备的位置和系统代价，动作是迁或不迁，策略靠求解或学习得到。这套形式化可以直接复用，代价在于它的触发条件是用户移动，而且代价模型里一次错误的推荐和一条错误的执行器指令没有区别。

这篇不学策略，排一次序。触发条件从用户位置换成物理关键度，比较的对象从迁移成本换成六个维度的加权分，中间不需要训练，也不需要求解。换来的是它没有最优性保证，也没有把迁移本身的算力和带宽成本写进目标函数。

### 3.6 迁移怎么排序

迁移在当前主机护不住某个 agent 时触发。论文的原话是当前主机在它要求的分数水平上无法继续保护它。越过迁移阈值的 agent 里，分最高的先走。

对每个候选的同伴设备 $k$，先算一个迁移后的预测分数。算法是把 PCS、IFS、IFR 三项按住不动，只按目标设备的资源状态重算 HAS、ACD、DCD。

$$\widehat{\mathrm{RCS}}^{(\mathrm{k})}_{s}(t) = \sum_{i=1}^{6} w_{i}(t)\, \hat{d}^{(\mathrm{k})}_{i,s}(t).$$

$\hat{d}^{(\mathrm{k})}_{i,s}(t)$ 是 agent $s$ 在设备 $k$ 上第 $i$ 维的预测值。选预测分数最大的那台同伴。并列的时候选剩余 DCD 余地最大的那台。如果没有任何一台同伴能让它超过迁移阈值，就退回本地的高档响应。

这里有一处记号不一致需要说明。论文那条迁移预测式子的上标，在公式里写的是 $p$，同一段的说明句里写的是 $k$，两处指的都是候选同伴。我按 $k$ 写。

关于被优化的量，三件套得补齐。初值方面，预测值只重算后三维，前三维直接沿用当前设备上的观测值，所以初值是现成的。残差方面，这套流程里没有残差，也没有迭代求解，选谁靠一次遍历比较。兜底方面，兜底的是迁移阈值本身和并列时的 DCD 余量规则。==判断的代价是，迁移决策只做一次前视==，没有考虑迁移本身要花的时间。

### 3.7 协调者挂了谁来接

如果主协调者降级或者联系不上，一个有资格的同伴接管。接手的一方继承成员记录和当前的分数值。论文的原话是协调因此继续，而不是重启。停机窗口里谁负责维持成员记录的一致性，论文没有规定。

这一步去掉了两个假设。协调者不再是单点，任何单一管理域必须替其他域保持健康的假设也一起去掉了。正文把这一套叫做后果加权的协调者故障转移，加权具体乘在哪个量上，论文没有写出来。

**这节要你记住的是，迁移按分排序，故障转移继承状态，两边都不依赖中心节点。**

所以这一节不摆数字，摆论文明确写下的机制性判据。每一条都能对回原文某句话，最后一列是它现在的验证状态。

### 4.2 哪一列值得看

这一节只看缺口分布。七条判据里，只有两条有明确方向，一条明确缺失，四条是响应规则。方向类判据依赖的模板值论文一个没给，响应类判据依赖的阈值论文也一个没给。

==三个扰动类型里，论文只把两个的方向写进了正文==。内存压力作为三分类里的一员，它的权重模板长什么样、哪些维度该升，全篇没有交代。**把这些权重合起来数，模板矩阵有 18 个分量、12 个独立参数，论文给出了 2 行的方向。**

### 4.3 反直觉的一处

网络延迟和热节流改动的维度刚好接在不同的环节上。延迟先打到输入，所以 IFR 上浮；热节流先打到算力，所以 IFS 和 DCD 上浮。这条分工有个设计上的后果，扰动类型一换，排名的依据就换了，连被排名的对象有什么特征都跟着换。

论文没有把这件事做成一节讨论，只是把它当成权重在线调整的用处说了一句。它也没有说明，当两个扰动同时成立、后验分成两份的时候，混合出来的排序会落在哪里。

⚠ 论文没有实验一节，第四节的所有判据都是设计承诺。要判断这套机制成不成立，需要先有硬件压力注入，这是论文自己写明的下一步。

**这节要你记住的是，论文没有结果，只有七条可查的设计判据。**

## 五、局限

### 5.1 论文自己承认的

三条，全部出现在讨论与结论里。

一是扰动分类和权重模板在部署时固定。论文说，在线更新能把适应性往前推一步而不改接口，现在还没有做。这一条限制的是对没见过的工况的应对能力。

二是协议信任每个同伴如实上报自己的分数。论文说，防住策略性上报和对抗性同伴很难。这一条限制的是多所有者场景下的可信度。

三是没有硬件评估。论文说，注入网络、热和内存压力的完整硬件评估仍是重要的下一步工作，它同时是一个有物理后果的试验台，用来检验协调与信任机制。按论文自己的说法，这类机制最终要跨管理域运行时，必须先过这一关。这一条限制的是全部机制结论的可核验程度。

### 5.2 编者补充

以下几条论文未将其列为局限。

没有实验数据之外，论文也没有给出任何参数取值。阈值的具体数值、三套权重模板的分量、先验如何初始化、似然函数取什么形式，这四样全篇一处都没有。

迁移成本没有被写进模型。那条预测分数的式子只算迁移之后 agent 自己的分，不算迁移本身的代价，也就是序列化的时间、要传的数据量、以及迁移窗口里原主机上谁来兜底。

故障转移的状态继承没有定义到什么程度算一致。继承的是当前分数还是几轮历史，成员记录在停机窗口里会不会分叉，论文都没有规定。

零延迟假设被默认掉了。==分类用的观测向量里没有一项是设备之间的通信时延==，而迁移目标和故障转移的判断都要跨设备问一圈。这一项如果要算进去，观测向量得先扩维。

安全的硬约束被略过。现场区的图上画着 PLC 和 HMI，这两个名字本身就带着控制网络与安全联锁的语义，论文没有正面处理。

控制周期的量级决定这套东西能不能满足硬实时。论文全篇没有给一个数。

**这节要你记住的是，论文承认只有三条，其余五条都是编者补的。**

## 六、我的评价

这一节是作者观点。

做得对的地方有四处。

物理后果确实进了分数，没有停在口号上。PCS 和 ACD 都是物理含义清楚的量，一个量降级输出会造成多大伤害，一个量执行器路径有多短。这让"先救谁"这个问题至少在形式上有了可计算的答案，而不是靠运维经验拍。

把基础设施状态和物理后果放在同一个加权和里，是这篇最干净的一步。同一份分数既反映设备现在有多挤，也反映挤坏以后有多严重，操作员拿到通知时能直接看到是哪些维度把分推上去的。

接口很薄，这是可部署性上的优点。agent 注册时声明四件事，之后照着原样跑自己的模型，协调层负责打分、比较和行动。对已有产线的侵入面小。

这套机制有可检验的方向。注入网络延迟时高 IFR 敏感的服务应该排到前面，注入热节流时排名应该按 IFS 和 DCD 走。同一组服务在两个工况下排名不变，机制就没生效。这是一条不依赖具体参数的检验。

存疑的地方也有五处。

==论文自己承认扰动分类和权重模板固定，但更早的一步还缺一个数字==。三套模板的分量、三个观测量的似然形状、先验怎么起，论文一处都没给。别人拿不到这些值，就没有办法复现这套打分，也没有办法在纸上核对那两个方向性结论。它现在是一套接口定义，还不是一个可以照着跑的算法。

==热节流那一行的方向我读出了张力==。DCD 写成设备把隔离和限流手段用掉之后剩下来的余地，余量越小意味着越危险。同一份高权重乘在它上面，余量本来就小的 agent 分数反而被压低。按论文写的加权方向，热节流期间最缺保护余地的那个服务，排位会被往下压。要让排序在物理上讲得通，热那一行里 DCD 的权重得是负的，而论文把它说成升。这一处我读原文读不出来，只能留在这里等待验证。

这套设计要落到现场，判据得压在可观测量上。论文给的三个观测量是延迟、温度和队列深度，都是设备自己就能测的。问题在权重和阈值，它们全是可调参数。参数一多，任何一次上线的表现都能用"标定没调好"解释过去。

分数是个即时量，后果在晚一步才出现。RCS 算的是此刻的紧迫度，物理后果要等这个输出真的被用掉以后才发生。这套设计的立足点就压在后果发生之前，提前量有多大，论文没有讨论。

要往前走，最该先确认的是失去物理信息耦合这道门槛以后，这套东西还剩什么。按信息物理系统这个栏目的判别口径，这篇的物理侧目前只有两个声明式字段，一个后果严重度，一个执行器路径。它们进分数的方式是归一化之后加权求和，与控制器状态、执行器动力学、过程时滞都没有关系。耦合确实存在，落在输入年龄这一条时限上，方向是对的。缺的是这条时限的数值，以及超过它之后输出错到什么程度。这两样拿到之前，它还停在接口设计上。

**这节要你记住的是，接口写得干净，数值全缺，热节流那一行的方向自相矛盾。**

## 七、可以接着做什么

先把最小可验证版本做出来。在一台带核显的边缘盒子上跑三个服务，控制回路用简单的 PID，质检用一个小卷积网络，维护用一条时序回归。在 tc 里注入网络延迟，在散热受限的机器上打满 CPU 制造热节流。只测一件事，排名会不会按预期换向。

把缺失的标定补上。三套权重模板可以用短标定运行里的维度统计量来估，似然函数先用高斯或者核密度，先验用均匀。做完以后再看那两个方向性结论还剩不剩。

给权重模板做在线更新。论文自己把这条列成了下一步，真要做，麻烦的地方在跨设备的可比性。每台设备在线上看到的样本分布不同，模板各自漂移之后，两个设备上的分数还能不能直接比大小，这是一个独立的问题。

把迁移成本写进目标函数。现在的选法只看迁移后的分数，可以把序列化时间、传输量和迁移窗口里原主机上的风险一起算进收益，让迁移变成一个带代价的决策。

把通信时延加进观测向量。迁移和故障转移都要互相问一圈，观测向量扩到四维以后，分类和阈值都要重新标。

把物理层的约束接上。输入年龄的超限直接对应执行器动作误差，如果能给出一条从延迟到过程量的传递关系，阈值就可以按允许的过程偏差反推，而不是靠运维设定。

在协议层加一道校验。分数由 agent 自己算自己报，任何排序都能被一个多报分数的 agent 搅乱。可行的起点是让协调者用可观测的旁证做交叉检查，比如实测的输入年龄和本地资源占用。

**这节要你记住的是，先补标定和最小实测，再谈在线更新与跨域信任。**
