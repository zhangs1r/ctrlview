## 它想干什么

机器狗站在一块灰色地垫上，背上驮着一条六轴臂。前面放着一个红色塑料方块，地垫边缘划出一块有颜色的目标区。它得先迈步走到方块旁边，把身子压低或者抬起，让臂够得着，再合上夹爪，把方块搬到目标区放下。

<figure src="2610.32271-fig1.jpg" caption="三帧">
<figcaption>（从左到右）图 1 的三帧。依次是接近、抓住、搬运。三帧里身子的倾角一直在变，这一幕在固定底座的实验里看不到。原图被解析器拆成三张单图，这里按原顺序拼成一行。</figcaption>
</figure>

这一整套动作，论文交给一个视觉语言动作模型。VLA 是视觉语言动作模型的缩写，读图像和一句口令，直接输出机器人动作。这个函数后面统称策略，控制语境里的控制器说的就是它。它看两路画面、口令和机器人自己的状态，吐出一串 11 个数字，管底盘往哪走、身子俯仰多少、六个臂关节转到哪、夹爪开还是合。没有上层规划器，没有逆运动学求解，也没有先导航再操作那种阶段切换。

论文是一篇扩展摘要，篇幅不长。架构上没有新东西，它用一个现成的开源 VLA，微调之后直接上机器狗。它报的是一份工程选择的清单，采集台怎么搭、标签怎么记、模型怎么裁、一次推理吐多长的动作，每一项都附了理由。然后补一个数据实验，问性能到底被什么卡住。

答案落在身子这一维上。演示从 131 条加到 233 条，没参与训练的那批演示（留出集）上的末端定位误差从 68.7 mm 降到 48.2 mm，降幅 **30%**。论文把这份收益归到起始接近段，那一段策略得在方块还没进入画面中央的时候就把身子摆好。

再补 25 条"推"的演示，抓取误差几乎不动，48.2 mm 到 47.8 mm，推的误差从 74.3 mm 降到 67.0 mm。同一张表里还有一格更值得盯，加抓取演示的过程里，推那几行的夹爪准确率从 50% 掉到 27%，补进推的演示才回到 57%。论文没有讨论这一格。

**这节要你记住的是，这篇的贡献是一条指令边界和一份数据账。**

## 一、问题背景

### 1.1 可达域跟着身子走

固定底座时，臂能碰到哪里由基座决定。桌子摆远一点，臂就够不到，这件事不用解，也没有解。所有演示都在同一个参考系里，底座动力学是静止的，策略要学的只是看到什么就动哪个关节。轮式移动平台是这一路的延伸，论文提到它们已经在上面跑通，但没有展开。

把同一条臂装到四足上，==可达域跟着身子走==。方块不在手边，策略得先让身子过去。身子是浮动基座，抬腿压髋既改臂能够到的高度，也改重心和支撑。论文写得很直接，在这类平台上伸手够一个物体天生是协调行为，迈步、俯仰和臂的动作要一起决定。

<figure src="2610.32271-svg-reach.svg" caption="可达域">
<figcaption><b>示意图 A</b>　（编者绘制）俯视图。横纵轴是地面坐标，圆半径是臂能够到的水平距离。落点一时臂怎么动都碰不到方块，落点二把方块圈进来之后才轮到末端精度。<b>表 I 的末端误差只描述后一种情形</b>，读 68.7 mm 与 48.2 mm 时要知道方块已经在可达域内。俯仰角改的是圆心在竖直方向的位置，俯视图里看不出来。论文没有给半径数值，这里只画关系。</figcaption>
</figure>

> 📌 **控制视角**　把末端位置写成底座位姿与六个关节角的复合函数，会看到一件控制里很熟悉的事。__同一个末端点对应不止一组底座位姿与关节角的组合__，多出来的那几个自由度由底盘提供。固定底座时这些自由度被钉死，问题缩成六个关节的逆解。腿足平台上它们活着，于是"够到"变成一个要在可达性和支撑之间挑点的规划问题。这也解释了论文为什么把俯仰角单独放进动作向量，它同时是可达域的输入和平衡的输入。

### 1.2 采集这一头就窄

要的是"协调的底盘加臂"的演示，这件事在腿足平台上不好采。采集靠遥操作，也就是人实时操纵机器人把任务做一遍，动作和画面一起录下来。论文把现有做法归成两类。一类给操作员穿动捕。参考文献 [3] 那篇就是这样，用 IMU 动捕把操作员的躯干和手臂动作映成机器狗的指令。人能全身一起动，代价是设备要穿在身上。底盘那一侧记下来的是人走到哪儿，不是一条下发的速度指令。另一类把底盘运动的一部分交给自主策略，[4] 走的是这条路，不加额外设备做全身遥操作，底盘往哪走由策略补，人只管剩下的部分，落点同样不在标签里。

两条路都留下同一个缺口。论文的说法是，这样一来__底盘落点的决定不在记录的数据里__。落点恰恰是本文后面要说明的那个瓶颈。

### 1.3 这篇的做法

做法是把填指令的人换掉，接口不动。采集时操作员通过手柄和主从臂填那 11 个数，部署时策略填同样的 11 个数，机器人侧的执行栈是同一套。用一句话说，采集和部署共用同一条十一维指令，策略顶替操作员的位置。论文的原话是策略可以坐到操作员的位置上，模型和机器人之间不需要逆解，也不需要控制器重定向。==人和策略填的是同一条边界==，后面几节都围着这条边界展开。

训练方式是模仿学习，拿演示当监督，和示教编程是一路。两者的差别落在泛化上。示教编程复现的是同一条轨迹，模仿学习要的是没见过的起始位姿也能做对，于是分布偏移（测试时的观测和训练时不一样）就得自己扛。

**这节要你记住的是，可达域跟着身子走，落点因为难采而缺。**

## 二、总体结构

图 2 是整条通路。左边虚线框里并排放着两样东西，遥操作栈和 VLA，二者择一。中间是那条指令接口。右边是机器人侧的执行，状态估计、运动策略、底盘控制、臂控制、相机节点。

<figure src="2610.32271-fig2.jpg" caption="接口">
<figcaption>图 2 的左框里，遥操作栈与 VLA 并排。部署时 VLA 推理顶替主手那一侧。中间的指令接口就是式（1）那 11 个数。右边是机器人侧的执行，底座状态来自状态估计器，速度与俯仰进运动策略，六关节进臂控制，画面从相机节点回来。</figcaption>

最该看的是左边那两格并排。它们是同一个接口的两个填写者，采集时是人，部署时是策略，中间没有"采完再换一套"的切换动作。==一条边界换个人来填==，整个方法的价值都在这个安排里。

| 阶段 | 输入 | 输出 |
|---|---|---|
| 采集（论文 II） | 主臂位姿、两个手柄、两路画面 | 5 Hz 的 11 维标签与同步图像 |
| 训练（论文 III） | 图像、口令、标签 | 秩 512 的适配权重与动作专家 |
| 推理（论文 III） | 两路画面、底座状态、口令 | 10 步乘 11 维的动作块 |
| 执行（论文 II、III） | 动作块 | 底盘速度与俯仰参考、六关节轨迹、夹爪开关 |

把任务写成三个集合，这篇的定义算清楚。观测是两路彩色图像加底座状态和一句口令，腕部相机 22 至 27 Hz，头部相机 10 Hz。动作是那 11 个数，一次给十步，论文把这一串连续动作叫动作块。成败判据这一栏论文没有给显式定义，真机那段只说跑通了接近、俯身、合爪、搬运、放下，是定性观察。留出集上量的是动作预测误差，不是成功率。

语言指令来自模板，动词、措辞、物体颜色这三样在变。==口令空间的宽度只到模板这一层==，读后面的泛化说法时要记住这一点。

下层那两个模块值得单独点一句，因为策略的边界正好卡在它们上面。底座状态由机载的 MUSE 状态估计器给，那篇工作把多路传感器实时融合成四足的底座位姿与速度。它内部怎么融合，论文一句没写，本文也不猜，策略和执行栈都把它当成既定的状态源。速度与俯仰指令进的是一个知道臂存在的强化学习运动策略。这条策略来自 BinWalker 那个四足加臂的野外作业平台，负责把两条速度指令和一条俯仰参考变成四条腿的关节命令，同时保持平衡。它的存在把 VLA 从腿的关节上摘了出去。

**这节要你记住的是，一条接口顶替一个人，机器人侧不动。**

## 三、方法拆解

### 3.1 一条指令，两个填写者

$$
\mathbf{a} = [v_x, v_y, \omega_z, \theta, q_{\mathrm{arm}}^{1\dots6}, g]^{\top} \in \mathbb{R}^{11}
\tag{1}
$$

符号按顺序来。$v_x$ 与 $v_y$ 是机体坐标系下的前后与横向速度，$\omega_z$ 是转向角速度，这三个合起来是底盘的一个平面速度。$\theta$ 是机身俯仰角的参考值，正负方向由控制器的约定决定，论文没有写。$q_{\mathrm{arm}}^{1\dots6}$ 是六个臂关节的绝对位置目标，$g$ 是夹爪的开合指令。

数一遍这条向量。前三个是速度，第四个是俯仰参考，接着六个是关节角，最后一个是夹爪，算式是 3 + 1 + 6 + 1 = 11。观测这一侧没有要解的东西，策略把图像和口令直接映到这 11 个数上。一次推理出十步，十步乘十一位，一共 110 个数，这就是一个动作块。

标签有四条约定，每一条都在防一个具体的坑。底盘那一项存的是操作员下发的速度，机器人实际跑出来的速度不进标签。俯仰角按控制器期望的参考空间记，策略输出可以原样转发，不用换算。臂目标是绝对关节角，==每一次预测都覆盖上一次==，误差不会像增量指令那样经时间积分累积。夹爪记的是开合意图，不记测量到的开口宽度，否则学到的会是方块有多宽。

> 📌 **控制视角**　前两条约定合起来是一句话，标签里存的是指令，也就是被控对象的输入。示教编程里若把机器人走出来的轨迹存成标签，学到的映射会把控制器的动态特性一并吸进去。换个控制器，它就失效。存输入等于把控制器当成已知的、固定的那一半，只学人此刻想让它做什么。数据集和控制器版本于是被绑在一起，这条接口换了底层栈就得重采。

四条约定的完整形式是，__底盘记下发速度，俯仰记参考空间的角，臂记绝对关节角，夹爪记开合意图__。

### 3.2 采集台怎么搭

机器人是 Unitree Go2 加 AgileX Piper L 臂，平行夹爪，腕上装一台 RealSense D435，头上装一台 D405 看前方。采集时第二台 Piper 当主臂，从臂跟着做镜像运动。俯仰、转向、夹爪开关和底盘速度由两个手柄给，其中一个绑在主臂把手上，于是同一只手能同时驱动臂、夹爪和俯仰，另一只手给底盘速度。主从之间是双边耦合，不加力传感器也能让人感觉到接触。

这样采到的是协调动作。论文强调边驱动底盘边驱动臂能采到自然的伸手和摆位，避开"先导航一段再操作一段"那种拼接出来的动作。一次任务（论文里叫 episode）的起止标记也走这条接口，由操作员按手柄给。

数据按 5 Hz 记录，跟着较慢的那一路走。头部相机 10 Hz，腕部相机 22 至 27 Hz，标签降到 5 Hz 是为了让每一步都能配到同一时刻的画面。三个数据集的演示全部由同一个操作员采完。

### 3.3 模型与动作块

基座模型是 MolmoAct2，论文选它的理由是权重开放、训练配方透明。它把视觉语言主干和一个流匹配的动作头接起来，一次观测产出一段动作块。流匹配是生成式动作头的一种做法，学一个速度场，把噪声沿着插值路径推成动作。这个家族还有一个带场景深度预测的推理变体，能做得更多，代价是延迟。论文实测那个延迟在四足上撑不住闭环控制，于是用普通版，把深度推理关掉。

微调只动一小块。视觉语言主干用秩 512 的低秩适配，主干的大部分权重不动，动作专家则全量训。硬件是一张 RTX 6000 Pro，96 GB 显存。

这里把三件事写清。被优化的量是整个策略的参数，初值来自 MolmoAct2 的预训练权重。驱动它的是演示本身，论文没有写出损失式的形式，只说沿用这个家族的动作头。兜底的是低秩这一层，更新被限制在秩 512 的子空间里，主干不被重写。三样凑齐，微调才是一次受控的外推，而不是重新训练一遍。

动作块的长度是试出来的。常见选择是预测一秒，按 5 Hz 切成五步 200 ms，与采集频率相同。这个长度在这套系统上产生抖动而且不精确的动作，计划在动作稳定下来之前就被换掉。反过来，十五步的计划会继续执行已经和当前画面对不上的指令。==十步落在两者中间，一段两秒==。

两个执行端的待遇不同。臂一次吃掉整块，当成一条多点轨迹下发，中途换目标不会打断它。底盘只接受瞬时指令，所以在两次推理之间靠一个 50 Hz 的保活线程撑着，保持俯仰参考，把速度清零。

闭环落在感知这一端。每两百毫秒重新看一次画面，臂在那两秒里执行的是一条固定轨迹，中间不再看。所以块内是开环，块与块之间是闭环，恢复只能发生在块的边界上。

```
每次推理，5 Hz，每 200 ms 一次
  读入两路图像、底座状态、口令
  输出一段十步的动作块
  臂接收整块，作为一条多点轨迹下发
  底盘接收瞬时指令，控制器只接瞬时量
保活线程，50 Hz，独立跑
  保持绝对俯仰参考
  把底盘速度置零
```

### 3.4 三个嵌套的数据集

这批数据全部来自真机遥操作，没有仿真，也没有人类视频。D1 是 131 条抓取，起点范围窄。D2 在这批之上加进起点更宽、接近方向更多、站姿不同的抓取，共 233 条。D3 再加 25 条推的演示，共 258 条。三个集合是嵌套的，D1 全在 D2 里，D2 全在 D3 里，其余设置一律不动。==三种数据量的差别只有覆盖广度与行为种类==。

留出集分两份。26 条抓取对三个模型都同分布，是公平比较的那一列。5 条推只对 D3 同分布，D1 与 D2 那两行量的是分布外迁移。__表 I 的前三列可以横着比，后三列只能竖着看__，这条决定了那六格该怎么读。

指标换过一次。论文说平均关节误差会饱和，分不出哪个训练阶段的权重更好，所以改用运动学链算出来的末端位置误差，单位毫米。毫米这个单位能和抓放需要的定位精度直接对上，也就有了物理含义。

**这节要你记住的是，标签存指令，动作块两秒一换。**

## 四、结果

数字来自论文表 I。前三列是抓取，26 条同分布，横向可比。后三列是推，只有 D3 那一行同分布，D1 与 D2 那两行是分布外参考。误差是运动学链算出的末端位置误差，单位毫米，不是成功率。

| 训练集（演示条数） | 抓取 末端 mm | 抓取 俯仰 ° | 抓取 夹爪 % | 推 末端 mm | 推 俯仰 ° | 推 夹爪 % |
|---|---|---|---|---|---|---|
| D1（131） | 68.7 | 5.01 | 94 | 77.5 | 8.53 | 50 |
| D2（233） | 48.2 | 2.24 | 99 | 74.3 | 2.36 | 27 |
| D3（258） | **47.8** | **1.87** | 98 | **67.0** | **1.63** | **57** |

值得看的是俯仰那一列。抓取上从 5.01 度掉到 2.24 度再到 1.87 度，推上从 8.53 度掉到 1.63 度。==末端误差从 D2 到 D3 停在 47.8 mm 不动的时候，俯仰还在往下走==。两列不同步，说明这两个量在数据加宽的过程中被喂饱的先后并不一致。论文把 D1 到 D2 的改善归到起始接近段的身体摆位，俯仰这一列和那个说法同向。

反直觉的是推那两行的夹爪准确率。50% 然后是 27%，D3 才回到 57%。如果只记"演示越多越好"这一句，这两格是反例。这套做法的劣势场景就在这里，推的演示缺位时，加宽抓取数据反而把推的夹爪准确率从 50% 压到 27%。

D1 到 D2 的总降幅是 68.7 减 48.2，也就是 **20.5 mm**，对 68.7 mm 是 29.8%，摘要和结论都写成 30%。图 3 把抓取误差沿 episode 摊开，横轴是从接近到释放的进度。

D1 那条线在开头高出一大截，三条约在进度 0.2 之后就并到一起。论文据此把 D1 到 D2 的改善定位在起始接近段，那一段策略必须在方块还没框好的时候就决定身子往哪摆。论文还给了一个数，说这一段单独贡献了约 65 mm 的误差下降。

口径上有一处对不上。表 I 里 D1 到 D2 的总降幅是 20.5 mm，65 mm 比它大两倍还多。图 3 第一条竖线处两条线的高度差倒是接近 60 mm 出头。这两个数说的不是同一件事，我在第六节把它当口径问题写。

论文还做了另一次排除。把适配从低秩换成全量微调，验证误差没有离开 D1 上的那个平台。把数据加宽之后，它离开了。原话是在这个演示数量下，数据覆盖率比模型容量更限制性能。这一组没有给数字，只有方向。

真机上的结论是另一个类型。给定两路画面、机器人状态和一句口令，策略完成接近、俯身、合爪、搬运、在目标区释放这一串动作。论文自己写明这是定性结果，不是成功率研究。两个失败模式与离线分析对得上。方块离开那个还能操作的视野之后，策略不会可靠地转身重新把它框进来。底盘指令给得太保守时，臂开始动的时候目标底座还在可达域的边缘。两处都落在起始接近段，也就是图 3 里最不准、又被数据改善得最多的那一段。

**这节要你记住的是，收益落在姿态上，推那两格是反例。**

## 五、局限

论文自己承认的有四条，另有一条是作者明确交代过的取舍。

**真机结果是定性的。** 原文写的是 preliminary result is qualitative rather than a success-rate study。跑通了接近、俯身、合爪、搬运、放下，给的是画面帧和失败描述，没有成功率，也没有每格的试次计数。

**离线误差不能说明闭环之后会不会累积。** 论文说离线结果拿预测和录好的演示对比，单靠它不足以判断能不能上硬件，因为它看不出误差在闭环里会不会越滚越大。这也是它非要跑真机的原因。

**只覆盖一个任务、一个平台、一个操作员。** 采集那节写明每条演示都由同一个操作员采，任务是取放方块。论文把整篇定位成初步工作，说这是朝更复杂的移动操作走的第一步。

**动作块长度是试出来的。** 原文用的词是 set empirically，没有给判据，只给了五步抖、十五步滞后的定性描述。

**带深度推理的变体被放弃，理由是延迟。** 这个能力留在桌上，论文没有报它的准确率，也没有报它的延迟数值。

### 编者补充的几条

以下四条论文没有写进局限，是读下来自己看到的，标清楚以免和上面的清单混淆。

**26 条留出集上的分辨力有限。** 抓取留出集 26 条，==一个百分点约等于 0.26 条 episode==，所以抓取夹爪 94 到 99 再到 98 这一列的抖动很难读出含义。推的留出集只有 5 条，一格就是 20 个百分点，50 与 57 的差落在一条之内。

**底盘在两次推理之间到底怎么走，没说清。** 保活线程把速度清零这句，和底盘只接受瞬时指令那句放在一起，读者没法判断底盘是按 5 Hz 走脉冲，还是按某种保持策略连续走。复现的人会卡在这里。

**65 mm 与 20.5 mm 的口径不一致。** 见第四节。

**操作员的技能被当成地面真值。** 演示全由一个人采，底盘落点的选择带着这个人的偏好。换个人来采，标签的方差有多大，论文没有测。

**这节要你记住的是，真机定性、样本少、时域靠试。**

## 六、我的评价

以下是我的判断。

做得对的地方有这么几处。

最值钱的是那条接口。让操作员和策略填同一个向量，这件事把一整类问题消掉了，不需要逆解，不需要重定向，也不需要"人怎么动"和"机器人怎么动"之间的映射。四条标签约定是这条接口的细节，每一条都指向一个具体的失效模式。绝对关节角防积分漂移，记录指令而非实测防控制器特性被吸进模型，记开合意图防把物体宽度学成动作。这三条各自对应一个具体的坑，写进论文有复用价值。

第二条是把"更多同类"和"更多种类"分开。D1 到 D2 是同一行为的覆盖加宽，D2 到 D3 是新行为的引入，两种改动对指标的含义完全不同。表 I 的脚注写明了推那两行是分布外参考，这个脚注比数字本身重要。没有它，74.3 到 67.0 会被读成规模效应，而它量的是这个模型在没见过的行为上能迁移多少。

第三条是那次全量微调的对照。花不了多少算力，却把"数据不够还是容量不够"这个问题切开了一半，答案也很干脆。

第四条是失败分析和离线曲线对得上。两个真机失败都落在起始接近段，与图 3 的拐点一致。定性观察只有一例 rollout，可信度不高，方向至少是自洽的。

存疑的地方五条。

⚠ **65 mm 这个数和总降幅对不上。** 表 I 的降幅是 20.5 mm，论文说起始接近段单独贡献约 65 mm。看图 3，D1 与 D2 在第一条竖线处的高度差确实是 60 mm 出头，之后收窄，所以 65 mm 更像是指那一段的高度差，而不是总降幅的一部分。这句话按现在的写法没法直接引用，需要作者补一句口径。如果原意是"这一段的高度差被压掉了 65 mm"，那它和 20.5 mm 并不冲突，两句话讲的是曲线的形状和端点。

**动作块的选取缺量化。** 五步抖、十五步滞后都是定性描述，没有给轨迹的抖动指标，也没有给末端误差随块长变化的曲线。两秒这个数换到别的任务上大概率要重调，论文没给调的判据。对控制读者来说这一格最想知道的是，块长和闭环带宽之间的关系有没有一个可以测的量。

**推那一格的夹爪准确率没人解释。** D2 的 27% 比 D1 的 50% 还低，而且这两格本来就是分布外。一种可能是加宽的抓取覆盖把夹爪的决策边界压向了"合"，于是面对推的场景更倾向去抓。这只是猜，论文既没有给混淆矩阵，也没有给失败帧。

**语言条件的宽度没有被测。** 口令来自模板，动词、措辞、颜色三样在变。这样的口令集合训练不出真的语言理解，也不需要，但读者容易把"换了措辞还能做"读成语言泛化。这个读法要收住。

**5 Hz 的底盘指令值得怀疑。** 底盘速度每 200 ms 更新一次，两次之间还被清零。如果真按零速保持，机器人是在脉冲式前进，位姿精度会被这个采样保持过程本身限制住。论文没有讨论这一层，也没有把它和起始接近段的误差联系起来。这条是我的推断，原文没有说。

它想走去的地方，我读出来是这样。这篇没有想赢一个成功率榜，它想把"数据覆盖决定成败"这句话变成采集的指导，把落点这一维从"操作员走得凑巧"变成"按缺口去补"。==按缺口采，比按数量采难得多，也值钱得多==。

**这节要你记住的是，接口选得对，口径还得再拧一遍。**

## 七、可以接着做什么

读完这篇，我顺手想了几个方向。都只是即时联想，没有实验也没有查证，给正在找题的人当线索。

### 1. 把底盘的保活方式做成一个自变量

现在底盘速度在两次推理之间被清零。可以对比三种做法，零速保持、保持上一段速度、给底盘也做动作块缓冲。测的量是终点落点误差和行进过程的抖动。这三种做法的差别在控制里属于采样保持器设计，成本很低，却可能是起始接近段误差的一个来源。

### 2. 给"起始接近段"单独设一个指标

现在整段 episode 共用一个末端误差，起始接近段的问题被后面几十步平均掉。可以在方块第一次进入视野的时刻记一次底盘落点，再算一次"从那一刻到臂开始动"的时间。这个指标能直接对采集下指令，缺什么样的起始位姿就补什么样的。

### 3. 采多个操作员的落点分布

标签里的底盘落点是人给的。换三个人采同一批场景，量一下落点的离散程度，就知道"落点"这个量本身有多大的不确定性。如果三个人给出的落点差得比策略的误差还大，那么用单人示教当监督就是在拟合一个人的偏好。

### 4. 让动作块长度自适应

固定两秒在一块场景里是折中。可以按图像变化率或者臂到目标的剩余距离来调，走的时候用长块，靠近到接触前后用短块。这就把一个超参变成一个调度问题，也正是控制里熟悉的那类设计。

### 5. 把技能选择显式化

现在推和抓都压在同一个策略里，靠口令里的动词区分。可以试一个两层结构，上层选技能，下层出动作块，再看新行为需要多少条演示。这条线索的判据很干净，加了新技能之后旧技能的误差有没有动。

### 6. 补仿真里的危险起始位姿

真机采"臂够不到"的样本很费时间，也容易磕碰。仿真里可以把底盘落点扫一遍，==先把可达域的边界扫出来==，再回到真机补那附近的一小片。这篇没有仿真，这条线要从零搭起。

**这节要你记住的是，缺的是落点覆盖，不是演示总数。**

※ 上面六条都是读完文章之后的即时联想，我没有做实验，也没有查证过是否已经有人在做，更没有验证过可行性。只当选题线索看，不要当结论用。

## 名词速查

| 词 | 一句话解释 |
|---|---|
| **VLA** | 视觉语言动作模型，读图像和口令，直接输出机器人动作 |
| **策略** | 控制语境里的控制器，这里是那个从观测和口令算动作的函数 |
| **动作块** | 一次推理吐出的一串连续动作，本文是十步，按 5 Hz 算两秒 |
| **流匹配** | 生成式动作头的一种做法，学一个速度场，把噪声沿插值路径推成动作 |
| **低秩适配** | 只训练一小块低秩增量的微调方法，本文秩取 512，主干权重不动 |
| **遥操作** | 人实时操纵机器人来采数据，本文靠主从臂和两个手柄 |
| **主从臂** | 一台臂当主手由人推动，另一台从臂镜像跟随，双边耦合还能传接触感 |
| **浮动基座** | 底座没有被固定在地面，位姿本身是被控量，四足和无人机都属这类 |
| **俯仰角** | 机身绕横轴的倾角，本文把它当动作的一维，既改可达域也改平衡 |
| **机体坐标系** | 挂在机器人身上、跟着它转的坐标系，本文的速度指令在这个系下给 |
| **关节轨迹控制器** | 接收一串关节角目标并按轨迹执行的底层控制器，不做逆解 |
| **末端误差** | 夹爪中心实际位置与演示位置的差，本文由运动学链算出，单位毫米 |
| **状态估计器** | 把多路传感器合成底座位姿与速度的模块，本文用 MUSE |
| **运动策略** | 这里的强化学习控制器，把速度与俯仰指令变成四条腿的关节命令 |
| **episode** | 一次完整的任务尝试，从开始到放下或失败 |
| **留出集** | 没有参与训练、只用来评估的那批演示 |
| **分布内** | 留出样本的起始位置与姿态落在训练覆盖范围内 |
| **分布外** | 留出样本的行为种类在训练里没出现过，本文的推对 D1 与 D2 就是这种 |
| **模仿学习** | 拿专家演示当监督，学一个从观测到动作的映射，相当于示教编程 |
| **保活线程** | 推理之间按固定频率重发指令的后台线程，本文 50 Hz，保持俯仰、清零速度 |
| **动作时域** | 一次推理覆盖多长时间，本文十步乘 200 ms |
