## 它想干什么

一条直路上，目标车 T 跟着前车 A1，后面还有一辆 A2 跟着 T。路侧的攻击者把 A1 的回波往外推了一段。T 的前向测距读到偏大的车距，就按宽裕的余量继续跟车。真实间距在收缩，等 T 的制动来得及生效，车头已经贴上去了。

同一套装置，同一个推进量，换一批车流就可能什么都撞不到。A2 离得太远，A1 正在加速，或者 T 正前方那辆车根本不是 A1。参数没变，结局翻了。

TACTIC 处理的就是这件事。它把物理 LiDAR 攻击的执行看成一个==依赖场景的战术规划问题==，攻击参数不再由人预先钉死，每一轮按当前车流重算。系统里放了一个多模态大模型（MLLM，能同时读图像和读文字的模型），但它的职责被切得很窄，只管判断车与车之间是什么关系、该挑哪一路攻击。物理量由路侧感知提供，可行范围由标定出来的常数卡住。

两个攻击原语吃的是两种不同的车流关系。push-away 吃 T 与前车 A1 的跟车几何，把 A1 的测距往外推，让 T 以为自己还有余量。phantom-braking 吃后车 A2 与 T 的关系，在 T 前方放一堵不存在的墙，逼 T 急刹，让 A2 追上来。

让这篇和普通攻击演示拉开距离的是一个反直觉的发现。论文试过等一个更脆弱的窗口再动手，成功率从 **20/20** 掉到 **9/20**，平均耗时从 34.5 s 涨到 43.7 s。时序可行域太窄，等待会先把它吃掉。

论文在 CARLA 里跑了 **280** 次随机多车试验。完整策略的碰撞率是 **100%**，固定规则 **35%**，随机选择 **60%**，只让大模型挑模式而参数取默认值的受限版本 **75%**，四组都来自同一套混合实现，每组 20 次试验。

**这节要你记住的是，攻击能不能成由车流关系定，参数表定不了。**

## 一、问题背景

### 1.1 威胁模型，攻击者知道什么、能改什么

论文设的是灰盒模型。攻击方是一套路侧设备，同一根杆上装了 LiDAR 和一个 RGB 相机，部署形态参照 Moving Vehicle Spoofing System（MVS）。那套系统用一辆行驶中的车把假回波打给高速行驶的受害车，证明的是真车条件下单个原语在长距离上能奏效，参数与路形由人事先设定，不随周围车流重选。TACTIC 沿用它的部署形态，把在线选择加进去。

攻击者能改的东西只有一处，受害车对物理世界的量测。它通过感知信道往受害车的测距里塞偏移量和虚假目标，除此之外碰不到受害车。它自己的感知栈以 **20 Hz** 检测并跟踪周围车辆，拿到目标级的位置、速度、加速度、车距和 TTC。

==攻击者能碰到的只有受害车对外部世界的量测==。__它可能知道受害车的传感器型号与车辆控制配置，但拿不到受害车的原始点云、内部滤波状态与整车报文__。这条边界决定了后面所有的设计。

目标是让指定的目标车 T 与某个邻近交通参与者发生碰撞。受害车这一侧按智能驾驶员模型（IDM，把期望车速和期望车距一起纳入的跟车模型）行驶，另挂一个两段式自动紧急制动（AEB）控制器。感知 TTC 低于 3.0 s 时施加部分制动，低于 1.6 s 时施加全力制动，这两个门槛取自 Euro NCAP 的测试协议。TTC 是 time-to-collision，按当前相对速度算出的相撞剩余时间。

### 1.2 为什么难

难在可行域由车间几何和剩余时间一起决定，而这两样随车流连续变化。

以推远为例。位移太小，受害车读到的车距没宽裕多少，它照旧按原来的间距跟车。位移要够大，前车又得留在路侧感知的覆盖范围里，覆盖约 **50 m**，推得越远越容易把假目标推出量程。位移还必须在前车被真正追到之前完成，爬升速率于是有个下限，$\Delta d / t_{\mathrm{arr}}$。速率又不能太高，受害车的量测一致性检查会把它识破。

两头一挤，可行域变成一个窄带。论文量出来的位移下限是 **11 m**，上限随点火位置 $o$ 走，等于 50 减去 $o$。速率上限是 **3.0 m/s**。这些数来自 III-C 的标定和 V-B 的锁定位移扫描，全部在 CARLA 仿真里取得。

幻影刹车那一侧的约束形状完全不同。它不需要位移，只需要在 T 前方立一堵墙，把感知 TTC 压到 1.6 s 以下。墙位直接由目标车速定，$w = 1.5v$，落在 5 到 15 m 之间。真正卡住它的条件是后车 A2 得能跟上来，也就是 A2 与 T 的间距。

==同一个原语在不同拓扑下的结局可以相反==。T 前方那辆车可能是它的领车，也可能是邻道上无关的参与者。同样的扰动落在前者身上把 T 推向追尾，落在后者身上什么也不会发生。

### 1.3 前人两条路各自缺什么

物理 LiDAR 攻击一直走两条路。移除类用对抗物体或物理伪装压掉真实目标的回波，注入类往点云里塞不存在的障碍物。两条路都能在下游感知和控制里造出后果。

问题出在评测方式上。这些工作通常在简化路形里验证单个原语，直路行驶、预先规定好的转弯、或者预先假定的车辆动作，参数由人手选。这种评测能回答一路原语有没有用，回答不了它在什么样的车流里有用。

第三条路是离线的。攻击硬度分析（Kim 等人）用离线搜索找出物理攻击在什么条件下可行，LLM-Attacker（arXiv 2501.15850）用大模型去改仿真驾驶场景，两边的动作都发生在攻击执行之前。一篇系统化梳理（Zhang 等人，arXiv 2509.11120）把传感器扰动在自动驾驶管线里的传播分析了一遍，并把场景相关的混合攻击链列为开放问题，它自己不做在线规划。

TACTIC 把这件事挪到线上。可行域由实测量和标定常数现算，关系理解交给 MLLM，选原语和配参数都在回路里完成。

**这节要你记住的是，可行域窄且随车流漂移，这是攻击必须在线规划的原因。**

看图 2 右上角的 JSON 片段。语义字段从多模态上下文里推出来，比如车道归属和谁是领车，度量字段则直接沿用感知栈给的数，比如车距和 TTC。这条分工把状态估计留在感知里，把关系判断留给大模型。

这条分工还对应着大模型做决策类任务的一处常见短板。GPT-Driver（arXiv 2310.01415）把运动规划写成对结构化驾驶状态的语言建模，输入是已经算好的状态量，输出是轨迹。LMDrive 把多模态观测与语言一并接进驾驶回路，让语言参与连续控制。DriveLM 用图结构把感知、预测和规划串成视觉问答。这三条都在用语言模型处理异质观测与交通参与者之间的关系，输出都是驾驶动作。TACTIC 把同一种推理挪到攻击侧，输出换成攻击原语。

==可行性由代码兜底，提示词只是建议==。执行之前，确定性代码会把大模型生成的参数投影回可行集合 $\Phi(S_t)$，让物理边界变成系统约束。

**这节要你记住的是，五个阶段的边界很清楚，感知给量，大模型给关系，代码给边界。**

## 三、方法拆解

### 3.1 把攻击执行写成一个带约束的决策问题

每一轮，策略输出

$$
\mathcal{P}_t = (m, \theta_m) \tag{1}
$$

$m$ 是三选一的模式，取 push-away、phantom-braking 或 hold。hold 表示沿用上一轮的 $\mathcal{P}_{t-1}$，用它避免攻击期间反复换招。参数向量 $\theta_m$ 随模式走，push-away 带三个连续量，$\theta_m = (\Delta d, \rho, o)$，分别是诱导距离位移、分离爬升速率和点火位置；phantom-braking 带两个，$\theta_m = (w, \tau)$，分别是幻影墙的放置距离和发射时长。

一轮的定义是一次决策、执行、重规划的循环，每次试验最多 $R=3$ 轮。这个上限是硬编码的，不由模型自己决定。

把自由度摊开数一遍。模式变量 1 个，取 3 个值。连续未知数在推远一侧有 3 个，$\Delta d$、$\rho$、$o$。约束一共 4 条，来源分三处。

$$
\Delta d \ge 11, \qquad \Delta d \le 50 - o, \qquad \rho \ge \frac{\Delta d}{t_{\mathrm{arr}}}, \qquad \rho \le 3.0\ \mathrm{m/s}
$$

第一条来自效应量，位移不够大，受害车读到的余量不足以改变跟车行为。第二条来自感知覆盖，推得太远，假目标落到路侧感知量程外。第三条来自完成时间，$t_{\mathrm{arr}}$ 是剩余到达时间，爬升必须在真的追上去之前走完。第四条来自量测一致性，爬得太快会被识破。

四条里前两条互相拉扯。$\Delta d$ 一变大，天花板下降而地板不动，可行集非空要求 $11 \le 50 - o$，也就是 $o \le 39$。原文把点火位置 $o$ 直接以米为单位写进覆盖上限，写法上带一点量纲上的松动，这一点我放在局限里说。第三与第四条把 $\rho$ 夹成一个区间，区间的宽度随剩余到达时间缩短而收窄。

幻影刹车一侧的自由度小得多。连续未知数 2 个，$w$ 和 $\tau$。$w$ 被目标车速钉死，$w(v) = 1.5v$，再截到 5 到 15 m 之间。真正剩下的只有 $\tau$，它的下界由当前的后车间距决定。所以幻影刹车的可行集是一条一维区间，推远是一个受时间挤压的二维窄带。

参数的初值由大模型给，它联合看了关系结构和可行边界之后吐出 $(\Delta d, \rho, o)$ 或 $(w, \tau)$。驱动修正的是标定上下界构成的越界残差，越界多少就截回多少。兜底的是每一轮用实测量重算的 $\Phi(S_t)$。

**这节要你记住的是，两个原语的自由度形状不同，一个被时间挤成窄带，一个被车速钉成一维。**

### 3.2 量由感知给，关系由大模型给

感知前端跑在 LiDAR 的 20 Hz 上，先聚类再关联成稳定轨迹，输出的是目标级的量。这些量准确描述单车状态，但不编码车与车的关系。

大模型要做的是把关系补回来。每一轮查询同时给两样东西，结构化的车辆状态和对应的路侧相机帧。图像提供道路语义，比如车道结构和行驶方向。结构化量保住精确的度量信息。输出是一张语义场景图

$$
G_t = (V_t, E_t) \tag{2}
$$

节点 $V_t$ 是被跟踪的交通参与者，边 $E_t$ 编码关系，比如同车道前后车、邻车道或对向车道的交互。边的属性保留感知栈给出的度量量，包括车距、相对运动和 TTC。

视觉那一路的编码写成

$$
Z = \operatorname{Merger}\big(\operatorname{ViT}(I_t)\big) = \{z_1, \dots, z_M\} \tag{3}
$$

$I_t$ 是路侧图像，$\operatorname{ViT}$ 是 SigLIP-2 视觉编码器，$\operatorname{Merger}$ 把每 $2\times2$ 个 patch 嵌入压成一个视觉 token，$M$ 是视觉 token 数。文本那一路把跟踪到的车辆状态、输出 schema 和缓存拓扑序列化成 $X=\{x_1,\dots,x_n\}$。

两路 token 用交错 MRoPE 位置编码送进多模态解码器，DeepStack 把视觉中层特征注入靠前的解码层。图是自回归解码出来的，目标是

$$
p(G_t) = \prod_{k=1}^{K} p(y_k \mid y_{<k}, Z, X) \tag{4}
$$

$y_1,\dots,y_K$ 是序列化后的输出 token。语义字段靠多模态上下文推，度量字段沿用感知栈的量。这一刀把状态估计挡在大模型外面。

**这节要你记住的是，大模型不碰状态估计，只碰关系判断和模式选择。**

### 3.3 危害分与确定性投影

论文不希望大模型从零推后果。它先在离线用网格搜索标定出一个 h-group 度量，每一轮战术决策之前，两个原语都被这个度量打一次分。

推远一路的分数由归一化的车距、加速度和 TTC 三项按 0.15、0.70、0.15 加权，攻击时长在第二层以 0.10 的权重并进去。幻影刹车一路只留加速度和 TTC，权重 0.85 和 0.15，同样带一个 0.10 的时长项。刹车这一路把车距剔掉，理由是刹车后果由目标的减速度主导，它跟车间距的关系不单调。标定的结果是攻击样本与良性样本的平均分离裕度，推远一路 **96.5×**，刹车一路 **13.6×**。

这个分从受害车视角定义，数值越大表示后果越重，它不含攻击方成本，也不含可行性。这一条论文自己写明了。

可行性接地是下一步。分数高不代表能执行。系统把实测量和 III-C 推出来的模式专属上下界一起交给大模型。推远给的是 $11 \le \Delta d \le 50-o$ 与 $\Delta d/t_{\mathrm{arr}} \le \rho \le 3.0$ m/s，刹车给的是 $w=1.5v$ 限在 5 到 15 m，以及由当前后车间距算出的最短发射时长。这些数每一轮按当前场景重算并数值给出。

于是大模型面对三样输入，关系结构、潜在后果、剩余可行裕度。几何让某一路明显更可行的时候，它可以挑一个危害分更低的。

执行之前有一道确定性投影。大模型吐出的参数当作初值，投影把它拉回可行集合 $\Phi(S_t)$。__物理边界在投影这道闸门上生效，写在提示词里不作数__。

**这节要你记住的是，危害分和可行性分开算，最后一道闸门是代码。**

### 3.4 两个回路的时间尺度对不上

大模型推理要按秒计，车流按感知速率变。TACTIC 的对策是把高频监视和低频推理拆开。

缓存策略还有效的时候，执行和下一轮场景生成并行跑。一个轻量警报器每一帧拿 20 Hz 的跟踪状态和缓存图比对。__场景突变判定为车辆出现或消失、车间距变化超过 8 m 或 40%、或者推断出的道路关系改变__。跟车距离本来就是慢慢变的，这三个阈值瞄的是结构性变化，帧级噪声不算。最小重规划间隔 0.5 s，防止连续告警把大模型调度器打满。

判定突变之后，警报器挂起执行并触发场景更新。车辆集合和关系结构还有效就走轻量 Δ 路径，只刷边属性；否则请求整幅多模态重生成。战术规划从更新后的图和可行状态接着走。警报器只负责发现和定位变化，语义解释和策略重生成仍然归大模型。

<figcaption><b>示意图 A</b>　（编者绘制）上半圈是受害车自己的感知到控制回路，一拍约 50 ms，读的是真实物理量。下半圈是攻击者的回路，20 Hz 感知进缓存图，再进秒级的大模型推理，最后经确定性投影落到执行器。攻击的注入点只在受害车的量测处，受害车内部滤波状态与整车报文攻击者碰不到。两圈时间常数差了四十倍以上，快回路等不起慢回路，于是有了 0.05 s 的挂起警报器和 0.5 s 的最小重规划间隔。</figcaption>
</figure>

==大模型的延迟本身就是控制回路里的一个量化环节==。它的输出在一个周期内保持常量，下个周期才刷新。把它从 7.4 s 压到 2.0 s 的办法有两条，一条是把执行和生成重叠，另一条是拓扑没变时只刷新边属性。

> 📌 **控制视角**　大模型的输出在一个保持周期内不变，这在时序上和零阶保持器的作用相同。推理时间就是保持周期。慢回路给出的是阶梯状的分段常量指令，被控对象的闭合时间只有几秒。把周期压短就是把这串阶梯的台阶变密，这比优化单次决策的精度更直接。

**这节要你记住的是，慢回路按秒更新，快回路按帧挂起，靠异步把两者错开。**

## 四、结果

实验全部在 CARLA 0.9.14 的 Town07 里做，同步仿真 **20 Hz**。每次试验有目标车 T、领车 A1、后车 A2，再加 A3 与 A4 两个参与者。为了让动态车际交互不被遮挡混淆，攻击只打离路侧感知栈最近的那条车道。攻击者用杆装 LiDAR 加 RGB 相机，有效观测距离约 **50 m**，与 MVS 的设置相似。纵向车辆名义巡航速度 **6.0 m/s**，闭环实测约 **5.5 m/s**，无攻击时车距基本保持稳定。大模型后端以 Qwen 为主，另用 Kimi 做后端泛化。

### 4.1 可行域确实是个窄带

蒙特卡洛协议把 T 与 A1 的初始间距在 **18 到 28 m** 上均匀采样，正好跨过推远的可行性转变区。每种配置跑 **20** 次不同随机种子，最多 3 轮攻击。__攻击成功定义为两车中心距小于 5.0 m 且残余撞击速度不低于 1.5 m/s__。另有 20 次无攻击对照，跑 30 s。统计用 Wilson 95% 置信区间和 Fisher 精确检验。

先把位移锁死扫一遍。$\Delta d = 5$ m 时 0/20 成功，10 m 时 5/20，15 m 和 20 m 都是 20/20。更细的一遍给出 $\Delta d = 8$ m 时 1/20，9 m 时 0/20，10 m 时 5/20，10.5 m 时 12/20，11 到 12 m 时 20/20。这条曲线把下限定在 **11 m**。

表 I 里有一列比成功率更能说明问题。$\Delta d = 10$ m 那一行，最小 T 与 A1 间距低于 7 m 的试次是 20/20，二十次全都逼到了七米以内，可成功率只有 5/20。剩下的十五次被受害车的 AEB 刹住了。贴到近处和撞上去是两件事，中间隔着受害车自己的制动。

另一列记录位移跟踪误差是否小于 1 m，15 m 时 18/20，20 m 时掉到 6/20。位移推得更大，跟踪反而更差，多出来的那部分代价落在暴露上。

### 4.2 四种决策源

四种决策源在混合实现下对比，两路原语都可用，每组 20 次试验，Qwen 后端。完整策略 **20/20** 全中，固定规则 **7/20**，随机策略 **12/20**，两个 Fisher 精确检验的 p 值分别是 $1.3\times10^{-5}$ 和 $3.3\times10^{-3}$。受限大模型只挑模式、参数用系统默认值，拿到 **15/20**，与完整策略的差是 $p=0.047$。

表 II 里还有三列值得看。占空比从 0.39 到 0.67，发射剂量从 3.9 到 9.7，剂量效率从 0.26 到 0.07。完整策略三列全部落在最好的一头，信号发得最少还最管用。发射基尼 G 这一列论文没给偏好方向，我只把数抄下来，完整策略 0.61 是四组里最高的。

固定规则的十三次失败全是被 AEB 刹住的近失。它永远选推远，成功与否完全押在采样到的几何上，几何不合适就只剩近失。

两边的好处在不同的轴上。完整策略每次试验平均发 **2.1** 次大模型调用，受限策略 2.6 次，两者都要按秒等的推理延迟和推理算力。固定规则与随机策略一次调用都不发，读也不读任何状态，部署成本是四组里最低的。几何本来很有利的时候，固定规则抽到的点也能落进可行域，失败集中在几何不利的那一半。

### 4.3 消融

感知通道（表 IIIa）。去掉图像只剩物理量，掉到 **13/20**，$p=0.0083$。去掉物理量只剩图像，掉到 **15/20**，$p=0.047$。两个单通道之间没有显著差异，$p=0.73$。

==只用图像这一路顶着 15/20，代价是占空比 0.96 与剂量 10.0==，而联合输入是 0.39 和 3.9。图像单独能提供道路语义，却缺精确的度量状态，策略只能靠更长时间、更大的发射量去补。它在平均试验时长上反而最短，20.6 s 对联合输入的 34.5 s。

攻击时机（表 IIIc）。立即执行 **20/20**，等一个预定义的脆弱窗口（4 s 内车距小于 12 m 且接近速度大于 0.5 m/s）再动手只有 **9/20**，$p=1.5\times10^{-4}$，平均时长从 34.5 s 涨到 43.7 s。==等一个更脆弱的窗口，成功率掉了一半以上==。等待的过程本身会消耗时空可行域，等到了理想条件，可行域已经不在。

异步重规划（表 IIIb）。同步重生成要 7.4 s，异步 3.7 s，异步加上 Δ 刷新压到 **2.0 s**。警报器在注入突变后 0.05 s 内挂起执行。推理通道每次试验平均发约 2.5 次大模型调用。十次 Δ 路径探针全部正确保住了原拓扑，只更新了度量边属性。

### 4.4 对照与后端

无攻击对照 20 次全部没有碰撞，最小间距 17.9 m，TTC 从未进入危险区。这条对照说明观察到的碰撞来自攻击执行，标称跟车动力学会自己撞的可能性被排掉。

后端泛化方面，完整策略在 Qwen 上 20/20，在 Kimi 上也是 20/20；受限策略在 Qwen 上 15/20，在 Kimi 上 16/20。差异不显著，$p=1.0$。

**280** 这个总数是这样凑出来的。表 I 的锁定位移扫描 4 档乘 20 等于 80 次，表 II 四组乘 20 等于 80 次，表 IIIa 三组乘 20 等于 60 次，表 IIIc 两组乘 20 等于 40 次，再加 20 次无攻击对照。80 加 80 加 60 加 40 加 20 正好 280，全部是 CARLA 仿真，没有真车。

**这节要你记住的是，优势来自在线选择，而等待被量成了负收益。**

## 五、局限

论文自己承认的散在实验设置和结论里，没有单列成节。下面四条每条都能对回原话。

一是验证只在仿真里。结论说未来工作会把 TACTIC 扩展到硬件平台，CARLA 里的 280 次试验没有一次跑在真车上。

二是感知栈是任务特定的。结论把学习型感知栈单列进未来工作，说明现在的目标级量测来自一套定义明确的几何管线，换成学出来的感知栈还没试过。

三是攻击战术的粒度是单步的。结论提到更丰富的序列级战术，现在的实现是每轮从两个原语里挑一个再配参数，最多三轮，没有跨轮的长时程规划。

四是遮挡被有意绕开了。实验设置里写明，为了把动态车际交互和遮挡分开，攻击只打离路侧感知栈最近的那条车道。更远的车道、被前车挡住的目标，都不在这次的验证范围里。

以下几条是编者补充，论文未将其列为局限。

物理信道在方法里被压缩成两个标量。推远用位移 $\Delta d$，幻影刹车用墙位 $w$，两者都是以米为单位的几何量。论文没有出现光功率、入射角、脉冲时序、探测器饱和、目标反射率这类量，也没有把攻击成败和信噪比联系起来。它称作物理约束的那组边界，实际由效应量下限与传感覆盖上限构成，来源是锁定位移扫描而不是信道模型。

覆盖上限的写法还有一处量纲上的松动。原文把点火位置 $o$ 直接以米写进 $\Delta d_{\max}(o) = 50-o$，名字叫时刻却带长度单位。这个写法不影响扫出来的 11 m 地板，会让上限的物理含义难解释。

危害分的标定细节没交代。96.5× 与 13.6× 两个分离裕度只说来自网格搜索，标定集的规模、场景分布、跨场景迁移都没有报。

成功判据把擦碰和致命混在同一个口径里。中心距小于 5.0 m 且残余速度不低于 1.5 m/s 就算成功，一次低速刮蹭和一次高速追尾在这里等价。

论文没有从受害车一侧评估检测难度。占空比、剂量、基尼系数被当作信号效率的代理，可真正决定攻击能不能落地的量，是检测器在这些发射模式下的虚警率与漏警率，论文没有报。

只在 Town07 的一条直路上验证。更复杂的路形、不同的限速与 AEB 标定、不同的 IDM 参数都没有覆盖。

**这节要你记住的是，论文承认的只有仿真与范围，其余都是编者补的。**

## 六、我的评价

做得对的地方有几处。

可行性被写成系统约束，没有停在提示词层面。$\Phi(S_t)$ 投影这道闸门让参数不可能越界，大模型的自由度被限制在挑哪个模式、在区间里挑哪个点。把语言模型放进回路时最容易漏的就是这一步，很多工作把约束写进 prompt 就当成约束生效了。

大模型的职责切得干净。状态估计留在感知栈，关系判断交给大模型，物理可行性交给标定常数和投影。每一块的责任边界都能指到具体模块。

随机基线只抽一次，不按轮重抽。论文明确写了这一点，避免多轮重抽给随机策略额外的机会。这种小事上的干净程度会影响整组对比的可信度。

攻击时机的消融设计得好。它把等更好的时机做成一个可测的对照，结论是负收益。这个反直觉的结果比任何成功率都更能说明时序可行域有多窄。

存疑的地方也有。

物理层比标题读起来薄。==论文没有把物理信道建模到光功率与入射角这一层==，攻击的执行被抽象成把前车回波往外推 $\Delta d$ 和在 T 前方放一堵墙。这两个抽象对规划够用，对物理攻击这个词的支撑有限。

==这套系统的物理与信息耦合是真的，决定性的一环却在时间尺度上==。11 m 地板、3.0 m/s 上限、$w=1.5v$ 这三条都是几何或运动学关系，它们不含光。把两圈耦合起来的是大模型的推理周期与车流的闭合时间处在同一个量级。这篇的耦合机制落在大模型的决策延迟上，落在采样与保持的时序后果上，而不在什么信道物理量上。

受限大模型与完整策略的 p 值是 0.047。每组只有 20 次，这个差刚好压在常用显著性水平上，换一批种子未必守得住。完整策略 20/20 的 Wilson 区间是 [84, 100]，宽度十六个点。

危害分与可行性是两个不同的量，论文没有把攻击方成本纳入打分。它自己也说明了这一点，作为一个从受害车视角定义的后果度量，这是合理的设计选择，代价是无法直接回答哪一路攻击更省。

这套机制的可检验推论是清楚的。一旦车流离开 11 m 位移地板与 3.0 m/s 速率上限围出的带，任何决策源的成功率都会掉。它会失效的情形也很清楚，几何本身不允许的时候就没办法，十三次固定规则失败全是被 AEB 刹住的近失，说明几何不合适时，再好的选择也换不来碰撞。

要往真机走，最先该确认的是路侧感知给出的车距误差有多大，以及这个误差怎么传导进 $\Phi(S_t)$。仿真里的目标级状态近乎无偏，真机上不会。

**这节要你记住的是，耦合落在时间尺度上，物理层和标定细节偏薄。**

## 七、可以接着做什么

把物理信道换成真正的信道模型再做一遍锁定位移扫描。加入发射功率、光束发散角、目标反射率、探测器阈值这些量，看 11 m 的地板会不会移动，看 3.0 m/s 的一致性上限换成给定探测器检测概率之后是放宽还是收紧。

给受害车装一个异常检测器，把占空比、剂量、基尼系数这套代理指标换成检测器的 ROC。发射模式一变检测难度就变，这条曲线决定了攻击的隐蔽性边界在哪。

把 $R=3$ 的单步战术换成有限时域搜索。现在每一轮独立选一次，用一个 h-group 分数当后果代理，可以把它直接当代价函数接进滚动时域优化，让选模式和配参数在同一个目标下联合求解。

把攻击者的感知误差显式建进去。路侧 LiDAR 估的车距、速度、TTC 都有误差，而 $\Phi(S_t)$ 的下界和上界直接由这些量算出来。误差放大到一定程度，可行集会缩到空，这条边界值得量化。

换场景做泛化。把限速、IDM 参数、AEB 标定这三样各换一组，再试弯道与多车道，看立即执行优于等待这条结论在别的动力学参数下还成不成立。

多攻击者协同。两个路侧设备同时对相邻车道动手，可能造出现在单点攻击造不出的连锁，可行域的联合形状是个开放问题。

**这节要你记住的是，把信道模型和检测器接进来，这篇的边界才算清楚。**

## 名词速查

| 术语 | 一句话解释 |
|---|---|
| 目标车 T | 攻击指定的受害车，也是要撞上别人的那一辆 |
| 领车 A1 | T 正前方同一车道的车，推远原语的攻击对象 |
| 后车 A2 | T 正后方的车，幻影刹车后期的碰撞对象 |
| 推远 push-away | 把前车回波的感知距离往外推 Δd，让 T 读到的车距偏大 |
| 幻影刹车 phantom-braking | 在 T 前方注入不存在的障碍物，逼 T 触发 AEB |
| hold | 第三路模式，沿用上一轮的战术，避免频繁换招 |
| Δd | 诱导的感知距离位移，单位米，锁定位移扫描的自变量 |
| ρ | 分离爬升速率，单位 m/s，决定位移走完要多久 |
| o | 点火位置，原文按米写进覆盖上限 50 减 o |
| w | 幻影墙的放置距离，等于 1.5v 并截到 5 到 15 m |
| τ | 幻影刹车的一次发射时长 |
| t_arr | 剩余到达时间，T 追上前车还剩多久 |
| TTC | time-to-collision，按当前相对速度算出的相撞剩余时间 |
| AEB | 自动紧急制动，感知 TTC 低于 3.0 s 与 1.6 s 时两段介入 |
| IDM | 智能驾驶员模型，把期望车速与期望车距一起纳入的跟车模型 |
| 灰盒威胁模型 | 攻击者知道传感器与控制配置，但拿不到受害车内部状态 |
| 语义场景图 | 节点是交通参与者、边是相对关系的图，边上挂度量属性 |
| h-group 度量 | 离线标定的后果严重度评分，从受害车视角定义 |
| Φ(S_t) | 当前场景下可执行的参数集合，由标定上下界围成 |
| 警报器 | 逐帧比对 20 Hz 跟踪状态与缓存图的模块，负责发现突变 |
| Δ 路径 | 拓扑不变时只刷新边属性的轻量更新路径 |
| 占空比 duty | 一次试验里执行器处于开启状态的时间占比 |
| 剂量 dose | 一次试验累计发射的信号量 |
| 剂量效率 η | 单位剂量换来的攻击后果，越高越省信号 |
| Wilson 区间 | 小样本下比正态近似更稳的二项比例置信区间 |
| Fisher 精确检验 | 小样本列联表用的显著性检验 |
