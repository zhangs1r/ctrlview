## 它想干什么

四家单位凑在一起训一个多模态基础模型，也就是在海量数据上预训练过、之后能迁移到很多任务上的大模型。国家实验室出一台同步辐射光源和一台顶级超算，大学出方法，医院出一个临床影像队列，企业出配方数据。模型训完之后还要挂一批智能体上去，让它们自己排实验、自己抢光束线机时。

这样的合作里，最该保护的东西常常不是某一条记录。医院在意的是别人能不能从训练轮次的时间上看出它这一轮参加了。实验室在意的是对手能不能从发布出去的权重里猜出它正在扫哪个参数区间。企业在意的是开放层的用户能不能反推它的配方空间。跟这条光束线同租一台加速器的邻居，还可能从控制回路的时序上看出这一轮在跑什么。

现成的工具各管一段。差分隐私给记录或者客户端一个可量化的保证，联邦学习让原始数据不出本地，安全聚合让服务器只看得到求和结果，可信执行环境把计算关进隔离区，信息流控制给数据和权重贴标签。这些保证各自都成立，==可它们说的不是同一个资产，防的也不是同一个观察者==。一堆单看都站得住的声明叠在一起，还是可能漏掉上面那几个问题。

论文的做法是先加一层声明格式。任何一条隐私主张都要写全六个要素，受保护的资产、观察者、观测通道、允许披露到什么程度、声称的保证、以及支持它的证据。写全之后，不同机制的保证就能放进同一张台账做比较，也能看出哪些组合会失效。论文给了一个四家单位的示意场景，用它生成一张台账，再把模型生命周期从头到尾过了一遍。

这篇是立场和框架型的工作。它给了机构级参与隐私的一个形式化定义，给了组合视图的并集表达式，剩下的部分基本是设计建议和待办清单。论文没有提出新算法，没有做实验，台账里的每一条都是示意的。哪些是定义、哪些是建议，下面逐处交代。

## 一、问题背景

### 1.1 保护单位换一层，定义就得重写

差分隐私的标准定义里，两个数据集只差一条记录，机制在这两个数据集上输出同一个结果的概率之比被 $\varepsilon$ 卡住。这一个不等式里有三件事要钉死，保护单位是哪条边、噪声由谁在哪里加、观察者最后拿到什么。记录级差分隐私里，保护单位是一行，噪声在机制内部加，观察者看到的是机制输出。本地差分隐私把这套动作挪到用户设备上，噪声在本地加完再上传，不需要一个可信的聚合者，代价是每条记录单独加噪，可用性掉得厉害。

把保护单位换成一家机构，这三件事全都动。机构级的秘密写成「机构 $i$ 在轮次集合 $R$ 里出过力」，这是参与者身上的一个属性，==落不到某一行上==。群体隐私在这里不好用。把一家机构的语料看成一个规模 $k$ 的组，界就随 $k$ 线性放大。语料动辄上百万条且彼此相关，放大之后这个界已经没有意义。__保护单位、噪声位置、观察者视图，这三件事决定一个隐私保证到底说了什么。__

更麻烦的是，==参与这件事可以完全不碰任何一条记录就泄露出去==。调度器记下谁什么时候占了机器，发布出去的权重带着这一轮的痕迹，公开的成员名单说明谁在这个项目里。这些痕迹都在记录之外。

论文因此把待做的工作说成一句话，定义出与伤害相匹配的相邻世界和泄露函数。相邻世界怎么取、泄露函数怎么取，都要从具体的机构资产往回倒推。

### 1.2 记录级这条线打错了对象

记录级这条线上的工具已经很成熟。差分隐私给记录或客户端一个概率比上界，靠的是在机制内部加噪。成员推断问一个样本在不在训练集里，靠的是比较模型在样本上的置信度与总体分布。训练数据抽取把生成模型的训练样本直接抠出来。这三样瞄准的单位都是记录或者用户。放在多机构合作里，它们回答不了医院参没参加这一轮，也回答不了实验室在扫哪个区间。

数据集推断和属性推断往机构的问题靠了一步。数据集推断问某一批数据有没有被用过，属性推断问模型有没有学到某个全局性质。它们观察的仍然是模型输出这一个通道，观察集合没有扩到轮次时序、编排元数据和智能体之间的消息。

### 1.3 控制级这条线各自成立，合起来不成立

联邦学习把原始数据留在本地，只传梯度或模型增量，保护单位是数据所在的位置。它管得住数据不动，管不住传出去的更新会不会把训练样本带出来。安全聚合给每个客户端的更新加一对互为相反数的掩码，服务器只能看到所有更新之和，保护单位是单条更新，前提是服务器半诚实。MPC 让多方各自持有输入的一段，用秘密分享或者混淆电路联合算出函数值而不暴露输入，它护住的是协议内那几个值。TEE 把计算关进硬件隔离区，靠远程证明让外部相信跑的是哪段代码，保护单位是计算过程，证明不了被隔离的代码执行了正确的披露策略。信息流控制给数据和权重贴层级标签，规定哪些标签能跨到哪一层，跨层时要显式去分类，保护单位是安全域。

每一样都在自己的范围内有效。安全聚合保证没有一方知道得比聚合结果更多，可一批串通的参与者把自己那一部分减掉，剩下的参与者就更清楚了。信息流控制管的是系统内部的流动，管不到训练完的模型将来会说什么。==这几种保证放在一起不会自动叠加==，论文把这件事叫保证的组合失败。

### 1.4 论文选的路

论文不去造新机制，而是给这些机制配一套共同的声明格式，再拿机构级资产把格式实例化一遍。用一句话概括这套机制，每条隐私主张写成六要素，每条机构资产在台账里占一行。判断标准变成三条，机构级资产有没有对应的声明、每条声明六个要素全不全、每一个空着或者写着「无」的格子有没有被记成显式残留风险。

这节要你记住的是，保护单位一换，噪声加在哪、谁来回合都要重算。

## 二、总体结构

### 2.1 威胁模型的三条

第一条是观察者知道什么。论文按观察者能拿到的视图划类。视图里有发布出去的权重、每一轮的完成时间、编排元数据、调度器与账务记录、检查点元数据、加速器遥测、仪器控制时序、智能体工具调用。范围里有开放层用户、串通的同行、聚合服务运营方、同租机器的邻居、授权审计员。

第二条是观察者能改什么。诚实但好奇的机构会照协议走，同时分析它有权收到的每一份更新。去中心化学习里的隐私攻击说明这种威胁确实存在。有竞争动机的参与者会调整自己的查询，去反推同行没有发表的结果。外部攻击者可以去攻陷编排服务。被攻陷的智能体可以拿着合法凭证越权，入口是提示注入或者供应链投毒。

第三条是要什么。目标是判断某家机构参没参加、在扫哪个科学问题、仪器和控制策略到什么水平、受层级限制的结果有没有流出去、资源在什么节奏上被占用、哪些伙伴在什么时候互动。==威胁模型里最需要提防的观察者在合作方内部==，这一点决定了防御不能只朝外。

边界要一起摆清楚。物理接触和凭证窃取不在范围内。整篇只管机密性和受控披露，完整性、可用性、投毒、模型安全、公平性、科研伦理都排除在外，理由是把它们统统叫隐私会让主张本身变得模糊。查询次数上界、模型结构是否已知这类量，论文没有给，它用观察者的视图集合来划边界。

阶梯上每往右一格，观察者的范围就变宽一次。记录级只担心机制输出的那一个数，机构级要担心权重、时序、账务、遥测、控制回路一起落在同一个人眼里。论文反复强调一点，企业跨孤岛学习不适合这类合作。科学设施是共享资源，同一台仪器同时服务受不同协议约束的项目。

这节要你记住的是，先写清谁在看、能看到什么，再谈保证。

## 三、方法拆解

### 3.1 机构级参与隐私怎么定义

论文借 Pufferfish 框架把要求写下来。Pufferfish 是差分隐私的一个推广，它允许秘密是任意性质，代价是必须显式写出数据生成模型。设 $\Theta$ 是联合体数据和调度行为上的一个分布类。对机构 $i$ 和轮次集合 $R$，记 $s_i^R$ 为「机构 $i$ 在 $R$ 里有贡献」这个秘密，$\neg s_i^R$ 是它的补。记 $V_O$ 为观察者 $O$ 拿到的视图，形状见式 3。

在这个记号下，一次部署若对任意 $i$、任意 $R$、任意满足两个事件概率都为正的 $\theta \in \Theta$、任意视图 $v$ 都满足

$$\operatorname*{Pr}[V_O = v \mid s_i^R, \theta] \leq e^{\varepsilon} \operatorname*{Pr}[V_O = v \mid \neg s_i^R, \theta] \tag{1}$$

就说它对观察者 $O$ 提供 $\varepsilon$-参与隐私。

左右两边是同一个视图在两个相邻世界下的概率。$\varepsilon$ 是无量纲的对数比上界，越小越强，这一点和记录级差分隐私里的 $\varepsilon$ 一致，可以直接比大小。$\theta$ 出现在条件里，是因为调度行为和语料之间可能相关，这个相关必须显式建模，不能当成独立。

记录级差分隐私是式 1 的一个特例。把秘密对换成「某一行的存在与否」，把 $V_O$ 换成机制输出，式 1 就退化成标准定义。机构级有三处不同。秘密是参与者的属性，__群体隐私那条按组大小放大 ε 的规则在这里不适用__。$\Theta$ 必须把机构语料和它的调度行为之间的相关写进去，这让定义从难写变成难实例化。$V_O$ 覆盖发布出去的权重、每一轮的时序、编排元数据，不再是单个输出。

论文把话说得很硬，==式 1 是目标，还不是结论==。表 III 里没有任何一个部署满足它，怎么为一个科学联合体挑出 $\Theta$ 也还开着。

### 3.2 六要素声明

一条隐私保证声明写成

$$\mathcal{K} = (A, O, C, D, G, E) \tag{2}$$

六个位置各自回答一个问题，也各自去掉一种含糊。

| 位置 | 回答的问题 | 可能的取值 | 缺了会怎样 |
|---|---|---|---|
| $A$ 资产 | 保护什么 | 患者记录、机构是否参与、仪器能力 | 不知道保护对象是什么 |
| $O$ 观察者 | 防谁 | 外部查询者、聚合服务、合作机构、审计员、被攻陷的智能体 | 不知道威胁来自哪一边 |
| $C$ 通道 | 从哪里被看到 | 数据、梯度、检查点、权重、输出、工具调用、消息、记忆、时序、日志 | 不知道观察发生在哪一步 |
| $D$ 允许披露 | 允许流出去什么 | 某个统计量、某种抽象、某个可行区域 | 分不清有用合作和泄露 |
| $G$ 保证 | 声称什么性质 | 差分隐私、模拟式密码学安全、非干涉、访问控制策略、有界攻击成功率 | 这句话只是愿望 |
| $E$ 证据 | 拿什么支撑 | 隐私账本、证明、远程证明、审计记录、基准测试结果 | 这句话不可检验 |

论文特意说明这套形式本身不是新的。安全保证、威胁建模和信息流这几支传统里早就有资产、威胁、证据这些概念。它的新意落在两处，一是把声明抬到机构级并且跨整个生命周期，二是让它在不同机制的保证之间充当共同的比较格式。一个例子能说明第四项的作用。「把数据保住」没法检验，写成「同行智能体可以知道一个可行的实验区域，但不能知道这个区域为什么在战略上重要」就成了可检验的契约。

### 3.3 六要素和已有框架差在哪

论文拿两个成熟的威胁建模方法做了对照。LINDDUN 沿着数据流图枚举隐私威胁，比如可链接性和可识别性。它在示意场景的暂存区和更新流上能得出 C1 和 C2，可它没有「一家机构是否参与」这个资产类别，C3 不会出现。STRIDE 把信息泄露摆在它认得的信任边界上，那些边界是进程和数据存储的边界，仪器控制回路上一条边界也没有，C6 不会出现。这两个方法在各自那张面上比六要素细得多，缺的是给机构级资产留的位置。台账标为空白的那两条，正好是它们装不下的两条。

保证情形记法 GSN 把证据组织成一棵论证树，它管的是论证结构，隐私主张本身是什么它不规定。语境完整性给出的是一套适当流动的规范，由接收方、信息类型和传输原则三者决定，六要素里的观察者、通道和允许披露正好对应这三者，差别是抬到了机构这一层。

### 3.4 组合失效写在并集视图里

观察者往往不止看一个通道。把观察者 $O$ 能看到的声明或通道记为索引集 $I_O$，他的总视图是

$$V_O = \bigcup_{i \in I_O} V_{O,i} \tag{3}$$

$V_{O,i}$ 是第 $i$ 个通道给出的视图，并集的意思是观察者把这些信息放在一起看。

式 3 直接给出组合失效的形式化说法。对每个单独的 $V_{O,i}$ 都成立的界，加到并集上不一定还成立，除非这些通道在给定 $\theta$ 下条件独立。调度时序和公开成员名单就是一对不独立的通道，谁参加决定了哪一轮的时间被拉长。==单通道都成立，合起来不一定成立==，这就是为什么台账要有外部观察者这一栏。

论文对一个具体组合给了四条充分条件，用来保证 C2、C4、C5 三条声明合起来不多开一条新路。观察者的视图互不相交，或者就按式 3 显式分析它们的并集。C2 留下的残留元数据，也就是轮次时间和参与集大小，要么被界定住，要么被纳入 C4 的发布风险检查。C4 的去分类对 C5 的任务条件化抽象单调，智能体拿到的不会比已发布模型本来允许的更多。三个机制之间不共享随机性和标识符。

论文明确说这四条是猜想出来的充分条件，证明它们、找出最弱的那一组，都还没有做，而且表 III 里的部署违反了第二条。

### 3.5 台账长什么样

论文把六要素实例化成一张七行的台账，每行一条机密性声明，从 C1 排到 C7。

| 声明 | 资产 | 观察者 | 通道 | 允许披露 | 保证 | 证据 |
|---|---|---|---|---|---|---|
| C1 静态数据 | 医院队列记录 | 设施运营方、其他租户 | 共享存储、暂存区 | 无，原始数据不出隔离区 | 访问控制、加密、可信执行隔离 | 远程证明、访问日志 |
| C2 聚合队列 | 医院更新，含聚合服务器 | 诚实但好奇的聚合服务器 | 梯度、模型增量 | 只放开聚合均值 | 安全聚合，半诚实假设 | 协议证明、配置证明 |
| C3 参与 | 医院是否参加 | 开放层用户加串通同行 | 已发布权重、每轮时序 | 公开成员名单，不公开逐轮角色 | 机构级差分隐私，目标，尚无部署 | 参与推断优势不超过 $\delta$，目标 |
| C4 发布 | 伙伴配方空间 | 开放层查询者 | 模型输出、适配器权重 | 聚合后的结构性质趋势 | 信息流控制、对抗式发布测试 | 层级发布证书、红队报告 |
| C5 智能体消息 | 大学假设与目标区间 | 被攻陷或串通的智能体 | 智能体消息、工具参数、记忆 | 可行区域，不含战略理由 | 任务条件化抽象、策略过滤，经验性 | 智能体泄漏基准，部分 |
| C6 仪器通道 | 光束线节拍，含策略 | 同租户、电磁观察者 | 时序、功耗、缓存、控制回路延迟 | 无 | 常量时间回路、抖动，通常缺失 | 侧信道痕迹审计，缺失 |
| C7 审计 | 全流程溯源 | 外部评审方与授权审计员 | 溯源库、重放包 | 给审计员过滤后的重放，给评审方证明 | 选择性披露、零知识合规证明 | 签名清单、审计记录 |

台账的复核缩成三个动作。每一个机构级资产都要有归属的声明，每一条声明都要把六个位置写全，写着「无」的格子则记成显式残留风险，不许留成疏忽。

### 3.6 证据分六类

第六个位置是整篇里最容易被抬高的一个。论文把证据分成六类，政策与治理、形式与分析、配置与证明、经验与对抗、运行与时间、溯源与审计。这六类之间没有顺序，一个强论证通常要同时用上几类。形式证据能在给定假设下确立一个协议性质，可部署的软件版本和观察面是否真的落在那些假设里，还得靠运行证据。对抗证据能暴露证明模型漏掉的违约路径，溯源证据把结论绑到真正跑过的那条工作流上。

论文要求台账对每条声明记录这份证据支撑的是什么推断，覆盖了哪些阶段、通道和有效期，强度属于形式、经验还是流程，以及假设、范围、日期、责任方和已知盲区。论文反对把这些压成一个分数，因为证明和实测给的是不同种类的信心。

论文举了两个证据被读高一格的例子。C1 靠 TEE 远程证明，它证明的是跑过某段指定代码，证明不了这段代码执行了 C4 或 C5 需要的正确披露策略，把远程证明当成披露主张的证据等于悄悄升了级。C5 的证据是智能体泄漏基准的分数，它界的是某个测试分布上观测到的泄漏，不是最坏情况对手。这种不对称是内在的。审计能证伪一条差分隐私主张，只要拿出一次成功率超过声称界的攻击；审计没法认证一条主张，因为总可能存在更强的攻击，基础模型上这个限制尤其难受，因为重训一次做审计根本不可行。

### 3.7 复核程序与完备性的上限

一套可重复的流程是这样的。先枚举表 I 里的资产、观察者和授权角色，再枚举数据、训练、适配、发布、自主运行、超算服务、仪器、溯源这几段的通道。给每条通道写明允许披露什么，挂上一条保证，填上证据件和工作流版本。然后专门检查跨通道、跨阶段的组合，把不完整的声明记成残留风险。要翻的设施侧材料包括调度与账务日志、作业与排队时序、检查点元数据、并行文件系统访问、互连流量、加速器遥测、资源分配模式、仪器控制时序、工作流溯源和智能体对设施服务的工具调用。

完备性有一条原理上的上限。通道集合是开放的，观察面没法事先枚举完，一条没人命名的通道也就没法被证明不存在。台账能给的是相对于一份已枚举清单的完备，所以流程里必须把这份清单定死，清单之外的一律记成残留风险。自动化能帮忙从调度器日志、工具清单和数据流图里推候选通道，也能标出观察者集合相交的声明，可它证明不了枚举已经封闭。C6 就是常驻的例子，仪器通道没进模型中心的评审清单，原因是没人把它列上去，跟某一项测试过没过无关。

规模也要算一笔账。台账本身大致按资产数乘观察者数增长，是线性的，示意里那个联合体只出几十条声明。贵的是组合分析，因为 $V_O$ 要遍历 $O$ 能看到的那些通道的所有子集，穷举量按 $2^{|I_O|}$ 走。论文给了两条让这件事可做的理由。观察者会塌缩成很少的几种角色，同行、运营方、开放层用户、审计员、同租户，评审按角色做而不是按人头做。只有共享通道或者共享观察者的声明才需要联合分析，这样 $I_O$ 是稀疏的。哪些组合值得在更大规模的联盟里分析，怎么用工具支撑，论文留成开放问题。

这节要你记住的是，六要素里最容易被写弱的是证据，最容易被漏的是通道。

## 四、结果

论文没有实验。这一节的「结果」有三个来源，把现有控制逐列读一遍、台账里落到空白的格子、以及一个从外部工作借来的实测数字。

### 4.1 逐列读现有控制

| 控制 | 保护单位 | 内部通信 | 跨层流动 | 智能体通道 | 生命周期组合 |
|---|---|---|---|---|---|
| 差分隐私 | 记录 | 无 | 无 | 无 | 部分 |
| 联邦学习 | 位置 | 无 | 无 | 无 | 无 |
| 安全聚合 | 更新 | 无 | 无 | 无 | 无 |
| 可信执行 | 计算 | 无 | 无 | 无 | 无 |
| 信息流控制 | 域 | 部分 | 原生 | 无 | 部分 |
| 基础模型隐私框架 | 混合 | 无 | 部分 | 无 | 部分 |
| 六要素台账 | 机构 | 原生 | 原生 | 原生 | 原生 |

先看第一列。「无」表示该性质落在原语的保证范围之外，「部分」表示覆盖取决于配置和组合方式。==没有任何一个原语在孤立状态下不合格，可也没有任何一个能同时回答那六个问题==。最下面一行是论文自己的格式，四个格子全填满，代价是它给的是格式不是机制，任何一个格子能不能兑现仍然另说。论文特意标注这张表比的是各个原语自己，不是一套组合好的架构。

### 4.2 两条落在空白处的声明

台账把 C3 和 C6 标成这个部署的机构级缺口，它们的特点是通过了逐机制的控制评审，资产却仍然裸露。

C3 是一条组合失效。C1、C2、C4 单独看都成立，原始记录没出隔离区，医院的更新对半诚实服务器是隐藏的，发布出去的模型通过了信息流控制和发布测试。把三件事放在一起，开放层用户拿到的模型输出、公开成员名单、可以观测到的逐轮聚合时序，合起来有可能让串通同行推断出某类队列的医院在某个时间段参加过。没有任何一个机制被违反，漏洞只有在 C3 被单列成一条声明、观察者集合横跨 C2 的同行和 C4 的用户时才显形。

C6 是模型中心和纯数据流的评审根本想不到的一条。就算数据通道和模型通道全都封住，光束线作业的节奏和挂在仪器上的模型的控制回路时序，仍然可以通过时序、功耗和缓存争用泄露研究策略。共享超算上的跨租户隐蔽信道和侧信道，已经在科学 AI 实际使用的多卡机器上被演示过。这条通道横跨仪器和计算两侧的边界，所以很容易整个掉出系统级评审，这也是它必须在按资产索引的台账里占一格的原因。

### 4.3 借来的一个实测数字

C3 依赖的那条通道有人量过。论文引用的一篇系统工作在一个百亿亿次级系统上做联邦微调，并发客户端最多 **96** 个，每轮通信时间从大约 **33 秒** 涨到 **275 秒**。这一过程里负载大小没变，涨出来的部分来自同步和屏障等待。轮次完成时间因此随谁参加、什么时候参加而变，__任何能给轮次计时的人都看得见这个差异__。论文自己交代这还不是一次参与推断攻击，它只说明这条通道在顶级设施规模上确实存在，C3 缺的仍然是那样一次攻击。

### 4.4 指标的量纲与可比性

这一栏的读者容易在符号上打滑，几个量要分开。$\varepsilon$ 是对数比上界，无量纲，越小越强，式 1 里的 $\varepsilon$ 和记录级差分隐私里的 $\varepsilon$ 可以直接比大小。C3 证据栏那个 $\delta$ 是参与推断优势超过随机的上界，无量纲，但它和差分隐私里表示失败概率的 $\delta$ 是两回事。读表时不能混。33 秒和 275 秒的单位是秒，量的是通信时间，跟隐私损失不是一类量。效用损失、运行开销、能耗这几个量论文只提出了要一并上报，没有给数量级。

### 4.5 防御的代价

代价这一栏论文给的是定性判断，没有数量。安全聚合和可信执行会吃掉吞吐，任务条件化抽象会削掉智能体拿到的信息量，去分类规则太紧会让合作没法做。差分隐私能压低记忆化，但挡不住模型把训练目标刻意教给它的东西说出来，这一条是明写的。框架侧的代价说得更实，组合分析按 $2^{|I_O|}$ 穷举，论文靠角色塌缩和稀疏性把这件事压到可做，但更大规模的联盟怎么选子集仍然开着。效用和运行开销被列成一次验证性部署应当公布的四项内容之一，论文自己没有给量。

这节要你记住的是，单看都合格的机制凑在一起，空白处才是风险所在。

## 五、局限

论文在第八节末尾自己列了一串，逐条对照如下。

- 六要素格式本身不提供隐私，一份写全的声明也不能证明实现真的满足它。
- 示意场景终究是示意的。一次验证性部署应当对每家机构公布四项内容，隐私损失、观察者达到的参与推断优势、控制的效用与运行时开销、每个观察者能看到的遥测。
- 机构资产和相邻世界依领域而定，换一个联合体就要重来。
- 经验泄漏证据不蕴含最坏情况安全，它界的是某个测试分布上的观测结果。
- 有些观察者和通道可能始终未知。
- 证据件本身可能变成泄露通道。
- 框架不解决异构形式保证之间怎么组合的问题。
- 完整性、可用性、投毒、安全、公平性和法律合规都在本文处理范围之外，只在它们影响披露时才被提到。

论文另有一处自我交代值得单拎出来。C3 缺的那份证据是一次真实的参与推断攻击，论文承认它没做，只测到了通道存在。四条组合充分条件同样被标成猜想。

编者补充一段。论文未将其列为局限，而这几条会直接影响读者对这份框架的预期。第一，全文没有任何实验，表 I 到表 IV 里的每一格都是作者为示意场景填的，包括那两条被标成缺口的 C3 和 C6。第二，33 秒到 275 秒这个数字来自另一篇工作在另一套配置下的测量，条件是并发客户端最多 96 个、负载规模不变，它能证明通道真实存在，不能用来推算任何攻击的优势。第三，论文对「几十条声明」这个规模的估计，来自它自己那个四家单位的场景。换到大型联盟会不会仍然线性，论文没有给依据。第四，六要素格式落到工程上需要谁来维护台账、按什么周期复审，论文只写了该在哪些事件之后复审，没写人力和流程归属。

这节要你记住的是，它给的是声明格式，不是可用的机制。

## 六、我的评价

做对的地方有两处。把「机构是否参与」单列成一条声明，动作很便宜，成本几乎为零，==收益是让组合失效从没人看变成台账上有一格空着==。用控制的语言说，这相当于把可观性分析从单通道扩到多通道并集，单通道都可观不等于联合可观，这个类比在这个场景里是准的。另一处是把证据拆成六类并且拒绝压成一个分数，证明和实测给的是不同种类的信心，这句话在安全工程里经常被含糊过去。

存疑的地方也有三处。第一，六要素是元层面的东西，读完知道该写什么，不知道具体怎么写。式 1 里 $\Theta$ 的取法是全部难度所在，论文自己承认这一点，也承认没有部署满足它。第二，$\delta$ 被拿来当参与推断优势的阈值，和差分隐私里表示失败概率的 $\delta$ 撞名。读表时容易混，建议换一个字母。第三，代价只在文字上出现过，论文说验证性部署应当公布效用和运行开销，可它自己没给任何数量级，对一个要说服设施运维方采纳的框架来说这是最要紧的缺口。

它想走的方向是让台账变成设施维护的工件，而不是一次性的清单。自动化从调度器日志、工具清单和数据流图里挖候选通道，是这条路上最实际的一步。

这节要你记住的是，框架的价值在于把漏掉的那一格摆到台面上。

## 七、可以接着做什么

### 1. 把 C3 缺的那次攻击补上

论文自己把要做的事写得很具体。做一个留一机构出的影子联合体攻击，报告攻击者优势比随机高多少。再做一个只看每轮完成时间的时序版本。最后把已发布权重、公开成员名单和时序合起来，正好覆盖 C3 的观察者集合。这条线索的好处是验收标准已经现成，优势不超过某个 $\delta$。

### 2. 给 Θ 找一个可实例化的取法

科学联合体里语料和调度行为的相关性有结构可循。机时申请、预算周期和实验计划常常由同一份文件决定，把这种结构写进分布类，$\Theta$ 就有可能从「手工给」变成「从设施记录里估」。这一步不做，式 1 始终停在目标的位置。

### 3. 让层级标签穿过蒸馏

信息流控制要能在适配这一环继续生效，标签就得在蒸馏和适配之后还留着。论文把这个缺口标成开放项。可以挑一个小规模的科学基础模型，做一次带标签蒸馏，看标签在哪一层开始失效，失效的判据可以用跨层探针的可分性来量。

### 4. 攒仪器侧信道的威胁模型和痕迹数据

控制器和设施服务的时序、功耗、缓存痕迹目前没有公开可用的代表性数据集。论文把「缺代表性威胁模型和痕迹数据」直接写成缺口。可以先在一条真实或仿真的光束线上采一批控制回路时序，标出哪些特征能区分不同的实验意图。

### 5. 让组合分析可扩展

$|I_O|$ 大的时候没法穷举子集，需要一套启发式决定哪些组合值得联合分析，还要给出这个选择的可靠性界限。==缺的是科学领域的任务集和公认的验收阈值==，把这两样定下来，第 1 条和第 4 条才有验收标准。

这节要你记住的是，验收标准比机制本身更缺。

※ 上面五条都是读完文章的即时联想，我没有做实验，也没有查证过是否已有人在做，更没有验证过可行性。只当选题线索看，不要当结论用。

| **联邦学习** | 原始数据留在本地，只传梯度或模型增量，保护单位是数据位置 |
| **安全聚合** | 客户端更新加互为相反数的掩码，服务器只看到求和，前提是服务器半诚实 |
| **MPC** | 多方用秘密分享或混淆电路联合算一个函数，不暴露各自输入 |
| **可信执行环境** | 硬件隔离区加远程证明，证明跑的是哪段代码，不证明它执行了正确的披露策略 |
| **信息流控制** | 给数据和权重贴层级标签，规定标签能跨到哪一层，跨层要显式去分类 |
| **去分类** | 显式允许某个受限信息跨到更开放的层级 |
| **层级发布证书** | 记录模型和适配器版本、层级、去分类规则、测试结果和有效期的凭证 |
| **成员推断** | 判断某个样本在不在训练集里，靠模型在该样本上的置信度 |
| **训练数据抽取** | 从生成模型里把训练样本抠出来 |
| **数据集推断** | 判断某一批数据有没有被用于训练 |
| **属性推断** | 判断模型有没有学到某个全局性质 |
| **LINDDUN** | 沿数据流图枚举隐私威胁的建模方法，没有「机构是否参与」这个资产类别 |
| **STRIDE** | 按进程与数据存储边界摆威胁的建模方法，仪器控制回路上没有边界 |
| **GSN** | 目标结构记法，把证据组织成论证树，不规定隐私主张本身 |
| **语境完整性** | 用接收方、信息类型和传输原则定义适当流动的规范，六要素里的后三项对应它 |
| **Rényi Pufferfish** | 把 Pufferfish 推广成 Rényi 形式并配可加噪声机制，让迭代学习下更好算 |
| **智能体泄漏基准** | 对多智能体系统测通道泄漏的基准，界的是测试分布上的观测泄漏，不是最坏情况 |
| **非干涉** | 一个安全域里发生的事不会改变另一个域的观察结果 |
| **零知识合规证明** | 让评审方相信合规而不交出私有上下文 |
| **影子联合体攻击** | 留一机构出，看攻击者能否判断该机构是否参与 |
| **资源姿态** | 一家机构的算力规模、紧急程度和推进节奏，可由分配、排队和账务记录推出 |
| **协作结构** | 哪些伙伴在什么时候互动，可由编排图和通信元数据推出 |
| **层级受限知识** | 在开放、受控、机密某一层允许出现，跨层就不允许的知识 |
